# TARGETS P1 — one `mount`: a static answered by the build's host

**Status:** PROPOSAL, nothing built. Answers TARGETS §9 decision 4.
**Base probed:** `program` at d7cd84d9 (compiler `avra-macos-d7cd84d9`); `targets.av` read on
`ios-sim` at 337cee99. Probes ran from the session scratchpad, never inside the tree.

## 0. The ask, stated generally

> A trait whose static is answered by the impl the build's HOST chooses. Every impl is typed on
> every build; only the chosen one is reached, lowered and linked.

That is P6 for conditional compilation vs dispatch: **checking sees every answer, reach sees one.**
The compiler already splits the two (typing is per declaration, lowering follows the entry), so
the choice lives at the one seam between them. No "UI" and no "mount" in the compiler.

**A — a bodiless trait static called by name checks clean with zero, one or two impls, and no
build can make it:**
```
$ avra check e.av          # trait Show { static fn lifted(t: int) -> int }, impls for A and B, Show.lifted(4)
exit 0
$ avra run c.av            # one impl
avra: the program layer doesn't build this program yet — the static fn `lifted` of `Show`, at the entry
```
This hole is exactly the seam the proposal fills.

**B —** `static fn shown<V>(v: V) -> int` in a trait: `error[parse.expected]: expected '}' while
parsing 'stmt'`. An inherent `fn mount<V: View>(view: fn() -> V)` builds and runs (`page:hi`).

**C —** an impl nothing calls, `static fn shown(n: int) -> string { n + "x" }`:
`error[type.mismatch]: the body answers 'int' but 'shown' declares 'string'`. Every impl is
already typed on every build. Nothing new is needed for "no target rots unseen".

**D —** `@host(Host.Page) fn plain() -> int { 1 }` checks clean, builds and prints `1`.

**Two siblings found while measuring (not P1's; unfiled):**
- A native **dev** build of `@std.ui.web.{mount}` links (`-undefined dynamic_lookup`) and dies at
  load: `dyld: symbol not found in flat namespace '_avra_ctx_heard_now'`, exit 134. The
  `--release` build refuses each by name: "`avra_ui_arm` is extern and nothing this program links
  carries it…". So dev and release disagree on the closure law.
- A wasm build of `@std.ui.terminal.{mount}` refuses by name: "a wasm module has no body for
  avra_fd_tty_size, avra_fd_tty_raw, …". That is the law working.

## 2. The mechanism

**One distinction first: host vs platform.** A *platform* is what a binary links against (triple,
SDK, objects). A *host* is what loads the binary and calls into it. iOS device and simulator are
two platforms and one host. A terminal binary and a future macOS `.app` are one platform and two
hosts. So `mount`'s choice is keyed on the **host**, and `[link.objects_for]` stays keyed on the
platform's object dir (the iOS lane got that axis right). P2's target row names both.

**`Host` grows** (`@std/meta` and `BuildHost` together, every arm spelled):
`Process` (a native binary's own process: today's `[]`), `Page`, `Ios`. A build stands beside ONE
host, which its target names (P2). `hosts_of` becomes `host_of(target) -> BuildHost`.

**The law, in the language's words:** *a call through a trait's name to a static the trait leaves
bodiless is answered by the one impl whose answer carries `@host(h)`, where `h` is the build's
host.* It reuses `@host` as it stands: on an `extern fn` it means "exported only beside h", and on
an answer it means "reached only beside h". It is one sentence: **this body belongs to builds
beside h.**

- **Typing:** the call types against the trait's signature, as A does today. Every impl is typed
  (C).
- **Lowering:** a direct call to the chosen answer, instantiated there. The others are never
  reached, so their externs, their package C and their host fns never reach this link.
- **One language ask:** *a trait's static fn takes type parameters.* A static is never in a
  `dyn` table, so it can always be instantiated. Instance members stay as they are. This goes in
  the ROADMAP's sugar backlog, wanted by std-ui's one `mount` (`<V: View>`).

## 3. Its refusals (each a named voice)

| Kind | When | Words | Judged |
|---|---|---|---|
| `type.host_answer_twice` | two impls answer one static for one host | "two impls of `Surface` answer `mount` beside `Host.Page` — a build beside one host has one body for each static"; label *answers again here*, secondary *first answer here* | every check, target-free |
| `type.host_answer_missing` | the build's host has no answer | "no impl of `Surface` answers `mount` beside `Host.Ios`, and this program is built for `ios`"; at the trait's static, secondary at the program's reaching call; help: "answer it — `@host(Host.Ios)` on an impl's `mount` — or take `ios` out of `[app] targets`" | per target |
| `type.host_answer_none` | no impl names any host (hole A) | "`Show.lifted` has no body to call: a call through the trait's name is answered by the impl its build's host chooses, and no impl of `Show` names a host"; help: "call it through a type (`A.lifted(4)`) or a bound (`T.lifted(4)`), or mark one answer `@host(Host.…)`" | every check |
| `type.host_misplaced` | `@host` on a fn that is neither a bodied extern nor an answer (D) | "`@host` says whose build a body belongs to — `plain` is neither a host fn nor an impl's answer to a trait's static" | every check |

**What `avra check` does for hosts other than the build machine's:**
1. It types every answer, which happens today.
2. It judges *twice*, *none* and *misplaced* everywhere, a library included.
3. It judges *missing* for **every target in the program's `[app] targets`** (P2), with no
   `[app]`, for the build machine's own (`Process`). So `avra check tools/ui-board` on a Mac names
   a missing `ios` answer before anyone builds for iOS. A library (std-ui) is never refused for a
   host it does not answer yet.
4. **Cost, stated:** the *reach* laws (a runtime row or package C with no body on a platform) stay
   each build's, as today. Running them per target in `check` would mean a lowering per target.
   `avra build` builds every target (decision 3), and that is where they are paid.

**Cost of the mechanism (P4):** one direct call, no vtable, no runtime branch on a platform, and
no other host's code in the binary. The ZERO_COST row it adds: *host-chosen statics | proposed |
removes a dispatch over hosts and every host's body in every binary*. Detector: the IR golden for
the call is one direct `Call`, never `CallPtr`. Cache: only the unit holding the call (std-ui's
one-line `mount`, per instance) is keyed by host. Every other unit stays shared across targets.

## 4. What std-ui folds into

```avra
// packages/std-ui/src/mount.av: neutral, no target's word
/// Where a view runs: one answer per host, chosen by the build.
export trait Surface {
    static fn mount<V: View>(view: fn() -> V)
}

/// `view`, running wherever the build stands.
export fn mount<V: View>(view: fn() -> V) { Surface.mount(view) }

// realize/dom/: today's web/web.av
type OnPage = {}
impl Surface for OnPage {
    @host(Host.Page)
    static fn mount<V: View>(view: fn() -> V) { … }
}
```

| Today | Becomes |
|---|---|
| `web/web.av` `mount` | the `Host.Page` answer. Its host fns stay `@host(Host.Page)` |
| `terminal/terminal.av` `mount(view, width, height, inplace)` | the `Host.Process` answer, `mount(view)`. No caller passes the three extra seats (grep: 0), and `terminal(view, w, h)` stays for tests |
| `headless/` | **no host.** It is a reader that answers a `Screen` and mounts nothing, so it stays a test door (`headless(view)`) |
| the iOS spike's `served` loop | the `Host.Ios` answer, after the spike |
| 16 `use @std.ui.{web,terminal}.{mount}` sites (9 programs, docs, tests) | `use @std.ui.{mount}` |
| `avra dev`'s `mounts_a_page`: an import of the module named `"@std.ui.web"` | the manifest's targets name a `Page` host (P2). Under one mount, the module-name test is a string tag that stops working |

**One contract to rule on: when `mount` returns.** On a page it returns once painted. In a
terminal it blocks until the input ends. So `mount(view); load()` means two different things.
The lean: **`mount` returns once the first paint stands, on every host**, and the app runs as
tasks. The terminal answer spawns its `served` loop, which already spawns `read` and `resizes`.
This holds because a native process already waits for its tasks (probe: `spawn later(); println
("main ended")` prints `main ended` then `task ran`). It is also the spike's option A shape.

## 5. The board: one entry

```avra
//! The task board: one view, wherever the build stands.
use @std.ui.{mount}

ship_state()
mount(view)
load()
```

`term/` is deleted and `[app] targets = ["web", "terminal"]` (P2). **The two entries have already
drifted:** `term/src/main.av` calls neither `ship_state()` nor `load()`, and it cannot call
`load`, which is private to the web entry's module. That drift is the bug class this removes.

## 6. Asks for the ruling

1. The law of §2: host-chosen answers to bodiless trait statics, with `@host` as the one mark.
2. `Host` grows to `Process | Page | Ios`, one host per build.
3. The language ask: trait statics take type parameters.
4. `mount` returns once the first paint stands, on every host.
5. The trait's name (ruled `Stage`, §7) is std-ui's to choose.

## 7. Rulings (UI lead, 2026-11-25: approved)

1. **The law as worded.** `@host` is the one mark; checking sees every answer, reach sees one;
   all four refusals. Plus one TEST case, not a voice: a program that never reaches the static
   builds for a host with no answer. A library, or an app mounting nothing, is never refused.
2. **`Host` = `Process | Page | Ios`.** One host per build, distinct from platform, every arm
   spelled in `@std/meta`'s `Host` and in `BuildHost`. Both enums join `make vocab`'s table in the
   same change, which is that table's first widening.
   *As built (P2's change):* `BuildHost` is in the table (`host_word`, `dev.av`'s `watches`,
   `run.av`'s `target_ran`), and so is `Platform`'s `platform_host`. **`@std/meta`'s `Host` is
   not**, because nothing in the tree matches on it. The compiler reads it by its WORDS (`host_named`
   over `every_host`), so it has no consumer to name, and a row naming none fails the keeper. When
   the P1 law adds the first match over `Host`, that match becomes its row.
3. **Trait statics take type parameters.** A compiler language ask, filed in the sugar backlog as
   avra-8sb5.10.214. Witness: a bounded static called through the trait's name, through a type
   and through a bound, eval == native.
4. **`mount` returns once the first paint stands, on every host**, the same contract as the iOS
   spike's option A. Terminal witness: `mount(view); load()` runs `load`, and the process ends
   when the input ends, together with its tasks. `mount`'s doc line says what keeps a program
   alive after it returns.
5. **The trait is `Stage`** ("where a view runs: one answer per host"), not `Surface`.

**Notes.** `mount(view)` is the one-window form, and nothing in this design may make a second
window impossible. `terminal(view, w, h)` stays the test door, and `headless(view)` stays a reader.
The change's message carries the `term/` drift (it calls neither `ship_state()` nor `load()`) as
its proof.

**Build order** (after P2's ruling): (a) the compiler slices, which the lead schedules;
(b) std-ui's one `mount` and the sweep of the 16 import sites; (c) the board's single entry,
which waits for the board-items train.
