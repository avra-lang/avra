# One store: the kernel is the only memo, the store is its durable tier

2026-10-27 · branch `hd-sigfix` (the hold deletion) · follows
[`2026_10_06_COMPILER_DB.md`](2026_10_06_COMPILER_DB.md)

**The goal, in one sentence.** Every answer the compiler gives is a query in one database;
the store holds that database's answers; nothing else caches anything.

## Measured state (this branch, cli comment edit, warm store)

| phase | time | what it is |
|---|---|---|
| parse (ast + sublang) | 18.4 s | every file re-lexed and re-parsed |
| resolve | 9.9 s | every file's names |
| bodies (typing) | 7.2 s | every declaration's facts |
| lower | 27.4 s | every body lowered |
| **keep** | **109.6 s** | serialising the whole program in one sweep |
| **edit total** | **116 s** | exits 1 on 29 `tag_stmt` errors |
| exact-text repeat | 0.0 s | the outer manifest cache; one 23 ms judge |
| main, same edit | 7.5 s | for reference |

## The three layers, and why only one may survive

1. **The kernel** — `Family.*` relations. Memoised, dependency-tracked, early cutoff,
   read sets. This is the database.
2. **`Keys`** — 60 `Cell<Map<…>>` fields in `workspace.av` (`text_digests`, `object_keys`,
   `view_parts`, `file_views`, `seen_views`, `text_scans`, …). Private memos with
   hand-rolled invalidation, invisible to the dependency graph. They invalidate at FILE
   granularity; the kernel cuts off per ANSWER.
3. **The durable store** — rows and read sets, written by a bespoke end-of-run sweep
   (`kept()`), not by the kernel's settle.

`keep` is 109.6 s because serialisation is a phase. The 60 `Keys` caches are why a
one-comment edit drops work in files that did not change.

## The law this refactor needs

**A family whose value is a leaf of another family's row must not stand alone.**

`Store.stands_alone` (`compiler/store/store.av`) currently answers "has a saver ⇒ stands
alone", so every reader of those answers names one row per answer — that is the shape that
made the earlier `Typed` saver take the compiler's own build to 7.9 GB. Durable families
are of two kinds only: a LEAF that another row embeds (filed with its parent, never a row
of its own), and a ROOT that is cheap and shared across programs (`Sig`).

## The four moves

1. **Savers onto families; delete `keep`.** A row is written when an answer settles, not by
   a sweep. `kept()`, `keep_interfaces`, `keep_asks`, `keep_codes`, `keep_instances`,
   `all_said`, `flush_saved` go. Expected: −110 s, and no separate "keeping" policy.
2. **Lowering is a query per (declaration, spec), with a saver.** The program's lowering
   becomes a fold over queries; `Lowered` revival needs no `serving` flag and no union walk.
   Expected: −27 s.
3. **Drain `Keys` (60 → 0) into families.** Each gets a key, an `ArgName`, and a saver only
   if it is a ROOT. What this buys is not tidiness: dependency edges and per-answer cutoff,
   instead of "the file moved, drop the map".
4. **One row shape.** The descriptor codec (`compiler/facts_codec.av`: one executor each
   way, ids through a scope) for every row type; delete the bespoke `*_wire` / `*_text`
   functions. One stamp (`store_wire`, a fold of the wire table), one id spelling.

Order matters: 1 and 2 are latency, 3 is invalidation, 4 is deletion. Each is measurable on
its own with `avra check --time` on the cli edit, and the gate for this lane is **10 s**
until the 300 ms target is reached.

## What is already true (this branch)

- The hold is deleted: one road, `is_held`/`hold_only`/held branches gone (−1006 lines).
- `sig()` reads a declaration's row AFTER its parse stands (a stale row was the 3733-defect
  cascade).
- A body's facts cross as their own row, keyed by the declaration and its file, verified by
  the answers it read (`facts_restored`/`facts_kept`), through one encoder and one decoder.
- A row stands under the wires its shape was written in, never under the compiler that wrote
  it: `store_wire()` is the fold of `WIRE_FACTS`/`WIRE_PRODUCERS`/`WIRE_ROW` + pack format.

## Finds from the slices (2026-10-27)

**`lower` (27.4 s) is `union`, and the reason is a refusal, not a missing cache.**
`Family.Lowered` *is* saved and its revival *is* armed for a check (`bodies_lowered` sets
`hold.serving` when `!want.links()`), but `unit_saved` (`unit_rows.av:44-46`) refuses to
save exactly the units a check spends most of its time on:

- `w.sub != null || !w.seats.is_empty()` — **every instantiation**;
- `w.decl == null` — **every per-file `program_main`** (the union adds one per file when
  `programs`, and `files_checked` passes `programs = true`);
- and `unit_text` refuses any unit that *spoke*, so a merely-warning body has no row either.

So revival answers `.Gone` for those and `lowered_unit` runs in full, every run.
`memory(units)` is not a suspect: it asks no query and does O(1) work on a revived stub, so
it is strictly downstream of `union` and smaller. The `refs` half is pre-settled
(`settle_schedulers` touches `references()` before the probe window), so a probe reading
~0 ms there is correct and the phase pays that fixpoint *before* it.

**The next lower slice**: name an instance by `w.name` (which already spells its seats) so a
specialized unit is content-addressed like a plain one, instead of refusing it; and give
`program_main` a key. Then `union` becomes a fold over reads. Do NOT "skip lowering for a
check": it would drop code hashes/kept facts and silently drop a unit's voices.

**`parse` (18.4 s) cannot be saved — it must be skipped.**
`Parsed`/`Resolved`/`Folded` are all arena-id shaped, so no row answers them; instead gate
the four per-file asks in `analyze_all` (`whole.av:77` `attach_parse`, `:80` `resolved`,
`:83` `sig_diagnostics`, `:86` `analysis`) on `file_rows_stand(store, path, want)` — the
judgement `keep_interfaces` already uses. That needs `Analysis` to grow a row-backed arm
carrying path + text digest + the readings it walked + its diagnostics (never empty
`NameFacts`/`TypeFacts`: absence is its own arm), with `view`/`names`/`facts` as demands
through `attach_parse`. Boundary: whole-program passes (`refs_ensured`, `cancel_ensured`)
re-parse what was skipped unless their answers ride rows too — measure it, and carry
`host.quiet` in the receipt (it is not in the text digest).

## The iteration loop (learned the hard way)

A cycle used to cost 4–10 minutes, and worse, several cycles measured a **stale binary**:

- `make try` runs `./avra build packages/cli` with the **released** compiler. That compiler
  was built from a main newer than this branch, so it resolved the wrong `@std` layout and
  refused: `avra: @std/relation:src/input.av does not exist`. Nothing was rebuilt, and
  `./avra-try` stayed at the last good build — probes never printed, `keep` never moved.
- Building with the tree's own older compiler ran out of memory (status 137 at 212 s) —
  the documented "a product compiled by the pre-fix pass runs with the bug it fixes".

The loop that works, and the rules that keep it honest:

1. **Merge `origin/main` before trusting a build.** The branch being behind main's
   `std-relation` is what broke `make try`.
2. **Build and measure in the SAME run**, never assume `avra-try` is current.
3. **Measure a small package** (`packages/std-text`: ~2 s a check) while iterating;
   `packages/cli` (~200 s) only for milestone numbers.
4. **Batch 2–3 hypotheses per build** — the build (~3 min), not the check, is the floor.

## Where this stands on main (2026-10-27, later)

Main is **not** the tree this design was written against: main deleted `compiler/saved.av`
and rewrote the store (`compiler/store/{store,pack,cas,body,mapped,meta,names}.av`);
`saved_family` and `stands_alone` no longer exist. Main also still **has** the hold
(61 `is_held`/`hold_only` references), and that hold is what makes its warm edit fast:
`held 577/579` — 577 of 579 files are not read at all.

(= `origin/main` + two commits):

| | wall | notes |

The remaining 5 s, by `--time`:

```
ast 1969ms · sigs 2190ms · interfaces 247 · bodies 276 · resolve 116 · names 140 · sublang 289
```

Both dominant costs are **per-file work on the 2 open files**, not cache misses: parsing
them and signing them. So the ladder is:

1. **Replace the hold flag with the rows that already answer it** (`stands_in(store,
   held_okey(store, path), want)` — the judgement `kept()` and `all_said` already use), so
   "not read" is a fact about the store, not a boolean. This is the deletion, done on main's
   store; it must keep `held 577/579` equivalent (rows standing), never `0/579`.
2. **`sigs` 2.2 s**: a file's signatures are re-derived for its open declarations; a sig row
   that stands should answer instead.
3. **`ast` 2.0 s**: the two open files are parsed; the edited file must be, the dependent
   file only if a row it stands on moved.
4. Then the facts/`Typed` rows (this document's move 1) — re-expressed on main's store,
   which is where `saved.av`'s codecs used to live.

## Why deleting the hold is not a substitution (probed, 2026-10-27)

`is_held` is **not an optimisation gate**: it is the predicate that says *the body is
absent*. Every arm it guards has no ordinary path behind it, so no site is a pure
redundancy. Two facts, both verified:

- The row judgement is **not the same question**. `file_rows_stand` needs `said && asks &&
  codes && file_ruled`; `stands_in` stops at `codes`. And `holding()` applies three more
  guards — the module is still loading, the file was counted as read, or the file was
  forced — so a file whose body **was** read keeps its rows and answers `stands_in` true.
  Substituting `stands_in` at a consumer therefore answers "held" for a file whose body
  exists: probed, it trapped the next run (`index 219 is out of bounds (length 40)`).
- The flag has a second, larger door: `decls.held` (23 readers) and `Decls.file_held`
  (6 more) decide what is minted from a record (`mint_files`, `interface.av:333`) — asked
  **before** any row judgement exists.

So the centralisation is not "delete the flag"; it is **"the flag is a memo of a fact
computed in one place"**: `holding()` already computes the real predicate (rows + the three
guards) and its only writer is that place. What remains is to give every consumer the
`Want` it needs (60 sites have none in scope) and to derive the mint predicate from the same
fact — one definition, one writer, no second road.

**A poisoned store follows a trapping run.** After the trap above, the same tree failed
`index … out of bounds` repeatedly until `.avra-cache` was removed; with it removed, cold
38 s / warm edit 4 s / exit 0.
