# TARGETS P3 — the bundle, and Apple through `avra` alone

**Status:** PROPOSAL, nothing built. Covers ticket avra-8sb5.110.1 (the Apple command line) and
P3 (the bundle) as one design, because every Apple verb starts from a bundle.
**Owner's rule:** everything Apple goes through `avra` verbs. No Xcode window, no script, no
second tool the writer runs.
**Base probed:** `program` at 42ed174d, on this Mac.

## 0. The model in one line

> **A build writes a bundle; `run` puts it somewhere; `ship` sends it to a store. Where it runs
> is a DEVICE, never a target, and signing is CONFIG, never the manifest.**

| Verb | Does | Today |
|---|---|---|
| `avra build --target ios` | writes `build/ios/<Name>.app`: binary, `Info.plist`, assets, icons | a bare binary; `tools/ios_sim_witness.sh` wraps it by hand |
| `avra run --target ios [--on <device>]` | builds, installs, launches, attaches the console | refused: "a build writes no bundle for it" |
| `avra devices` | every place a run can land, every host | none |
| `avra screenshot [--on <device>] [-o file]` | the running app's screen, as a PNG | none |
| `avra ship --target ios` | signs for distribution, packages, uploads | none |

**An honest limit:** these tools live inside Xcode.app. The writer never opens Xcode, but the
Mac must have it installed (simulators ship only with it). `avra` calls the tools as children,
with argv (never a shell line), and every call is printed by `--explain` (P7). Replacing a tool
with our own code (codesign first, it is a format) is a later, measured slice.

## 2. The bundle (P3)

One mechanism writes every target's bundle: a **list of files, each derived**, written into
`build/<target>/`. TARGETS §9.7: the page's document is a bundle too, ruled when first-paint lands.

| File | Derived from |
|---|---|
| `<Name>.app/<name>` | the build's binary |
| `Info.plist` | `[app] id`, `name`, `[package] version`, `[target.ios] min`, the derived permissions (TARGETS §2), `[target.ios.plist]` verbatim (P8) |
| `AppIcon*.png` + `CFBundleIcons` | `[app] icon`, cut to each size the platform's row names |
| assets | the program's bundled assets, by digest (exists) |
| `embedded.mobileprovision`, `_CodeSignature/` | signing (§4); ad-hoc on a simulator |

- `avra explain bundle --target ios` prints every file and where each came from (P7).
- **Keys that land here**, each with its first reader (P2 ruling): `[app] id`, `name`, `icon`,
  `[target.web] base`, `[target.ios.plist]`; voices `manifest.bad_app_id`, `manifest.bad_icon`.
- **Cost:** build time only. Each file is keyed by its inputs' digest and rewritten only when
  it changed; `run` skips the install when the bundle's digest matches the device's copy.
- **No asset catalog** (`Assets.car`, `actool`) in v1: plain PNG icons in `CFBundleIcons` are
  accepted by every iOS we target. `actool` is a row the day a store requires it.

## 3. Devices: where a run lands

`--on` names a device, by name or id, from `avra devices`. With no `--on`, `run` picks the
**booted simulator, else the newest iPhone simulator**, and says which on its first line.

```
$ avra devices
NAME              KIND       OS     STATE     ID
this Mac          process    15.6   ready     local
iPhone 16         simulator  26.5   booted    5A1F…
iPad Pro (12.9)   device     18.1   paired    4445…
browser           page       —      ready     page
```

- One table for every host, so `--on browser` and `--on "iPhone 16"` are one flag (P6).
- `--json` for agents (P11).
- The ask said `--device`. This proposes `--on <device>` instead, since a simulator is a device
  too and one flag covers both. Ruling 1 below.

## 4. Signing: discovered through config

Signing is a `@std/config` record the TOOLCHAIN loads, not the program:

```avra
export component apple_signing {
    team: string?                       // else: the only team the keychain holds
    identity: Secret<string>?           // else: the keychain's identity for that team and kind
    profile: Secret<Bytes>?             // else: an installed profile matching [app] id
    store_key: Secret<Bytes>?           // App Store Connect API key: ship, and profiles on demand
    store_key_id: string?
    store_issuer: string?
}
```

| Run on | Needs | Found by |
|---|---|---|
| simulator | nothing | ad-hoc signature |
| device | development identity + profile naming the device | keychain, then `~/Library/MobileDevice/Provisioning Profiles`; with `store_key`, avra registers the device and makes the profile through the App Store Connect API |
| ship | distribution identity + store key | keychain, config sources (`*_FILE`, env, a mounted dir in CI) |

- **Sources** are the config doc's: a repo file for non-secrets (`team`), env and `*_FILE` for
  CI, and a **keychain provider** (one `Source` impl, macOS only) for identities.
- A missing value is refused naming the key and where it may come from (config §7), e.g.
  `apple.no_identity: no development identity for team ABCDE12345 — sign in once with
  \`avra apple login\`, or set APPLE_SIGNING__IDENTITY_FILE`.
- Secrets reach `codesign`/`altool` through `with_secret_var` (C2), redacted in every printout.

## 5. `ship`

`avra ship --target ios` = build (release) → sign for distribution → `.ipa` → upload with the
store key. Prints the build number it sent and the store's processing state. A version already
uploaded is refused naming it (bump `[package] version`). TestFlight vs review is one config
field, not a second verb.

## 6. Slices

| Slice | Delivers | Proves |
|---|---|---|
| A | bundle writer + `[app] id/name/icon`, `explain bundle` | goldens per file; the witness builds with `avra build` |
| B | `avra devices`, `avra run --target ios` on a simulator | the witness becomes four `avra run` calls; the script is deleted |
| C | `avra screenshot` (simulator: `simctl io`; page: the browser leg) | a PNG with the app's first frame |
| D | signing record + keychain source, `run --on <device>` | hello on the iPad |

Each slice: voices with goldens, an attack pass, eval == native where code runs.

## 7. Rulings asked

1. **`--on <device>`** over `--device` (one flag for every host's places).
2. **`avra devices`** lists every host, not only Apple's.
3. **No asset catalog** in v1.
4. **Signing record in `@std/apple`** (a new package the CLI reads), keychain as a config source.
5. **`avra apple login`**: a one-time verb that stores the store key into the keychain, so no
   writer pastes a key into a file. Or leave that to config sources alone.
6. **Device screenshot** is open: `devicectl` has no capture verb today; slice C ships the
   simulator and page, and device capture waits for a measured path.
