# The HTTP tour

Small programs, each one run by the gate: every snippet below is a
program test under `packages/`, so it compiles and runs in both engines
rather than merely reading well.

## Serve HTTPS in ten lines

A `server` declaration is a port, a `tls` seat and its routes. The
`tls` seat takes `@std/https`'s `over_tls(config)`; the configs are
`@std/tls`'s, whose client verifies the peer by default.

```avra
use @std.http.route.{get}
use @std.http.server.{server}
use @std.http.wire.{Secure}
use @std.https.{over_tls}
use @std.tls.testing.{serving_localhost}

fn identity() -> Secure? {
    match serving_localhost() { .Ok(c) -> over_tls(c), .Err(_) -> null }
}

export server site {
    port: 8443
    tls: identity()
    get "/" { _req -> "hello over TLS" }
}

let _ = site.run()
```

Proved by `packages/std-https/src/tests/https_site`: it serves that
declaration on an ephemeral port and fetches it with `@std/https`'s
`secured`, verifying the server's certificate against the test
authority, and prints `200 hello over TLS`.

In a real deployment `identity()` loads the site's PEM instead of the
testing helper: `(server_config()?).presenting(chain, key)` (or a
client's `client_config()`/`anchored(pem)`), with `chain` and `key` read
as `Bytes`. Verification stays on; `.unverified()` is the one way off
and is named for what it gives up.

A plain HTTP request to the TLS port is answered `400` **in the clear**
and closed, never held open — the first bytes a connection sends decide
which protocol it speaks, and a mismatch is refused rather than waited
on.

## Streaming, SSE and WebSocket

### A body that streams out, in bounded memory

```avra
use @std.http.http.{Response, Stream, Pulled}

once fn piece() -> Bytes { [120 for _i in 0..65536].bytes()! }

fn next_piece(n: int, pulled: Cell<int>) -> Pulled {
    if pulled.get() == n { return .End }
    pulled.set(pulled.get() + 1)
    .Data(piece())
}

fn measured_stream(n: int, pulled: Cell<int>) -> Stream {
    Stream { pull: () -> next_piece(n, pulled), length: n * 65536 }
}

    served(l, () -> App {}, limits(), timing()) { _app, _q ->
        Response { stream: measured_stream(n, pulled) }
    }
```

The connection pulls one piece, writes it, and only then asks for the
next: the producer and the peer move in step, and nothing gathers. A
slow peer parks its own connection's task, so memory is one piece per
stream however long the body is. Proved by
`packages/std-http/src/tests/http_stream_download` (16 MiB in the
suite; `AVRA_STREAM_PIECES=16384` streams a gibibyte and
`AVRA_MEM_STATS=1` shows the native peak stays under a megabyte).

### A body that streams in

```avra
use @std.http.body.{Body}

fn poured(b: Body) -> string {
    mut total = 0
    mut largest = 0
    while true {
        match b.read() {
            .Ok(p) -> {
                let got? = p else { return "${total} octets, no piece past one read: ${largest <= 16384}" }
                total = total + got.length
                if got.length > largest { largest = got.length }
            },
            .Err(_) -> { return "failed after ${total}" },
        }
    }
    "?"
}
```

The handler runs once the head is here and reads the body a piece at a
time, each no larger than one read of the socket — so an upload of any
size flows through a sink and nothing gathers. Proved by
`packages/std-http/src/tests/http_stream_upload`.

### Server-sent events

```avra
use @std.http.sse.{Event, Feed, feed, events}

let f = feed(16)
let _ = f.publish(Event { data: "first" })

    served(l, () -> App {}, limits(), timing()) { _app, q ->
        events(q, secs(10), (c: string?) -> f.resumed(c))
    }
```

A `Feed` keeps the last events and `events` resumes a reconnecting
observer from its `Last-Event-ID`, so nothing is missed and the client
reads the chunked stream with the same body reader a handler reads a
request with. Proved by `packages/std-http/src/tests/http_sse`.

### WebSocket

```avra
use @std.http.ws.{Socket, Message, accepted, ws_limits}

fn answering(s: Socket) {
    while true {
        match s.receive() {
            .Ok(m) -> match m {
                .Text(t) -> { let _ = s.send_text("${t}, heard") },
                .Binary(b) -> { let _ = s.send_binary(b.concat(b)) },
                .Close(_, _) -> { return },
            },
            .Err(_) -> { return },
        }
    }
}

    served(l, () -> App {}, limits(), timing()) { _app, q -> accepted(q, ws_limits(), answering) }
```

A handler hands the upgraded connection to a session on the connection's
own task; the client dials `dialed(host, port, path, timeout,
ws_limits())` and verifies the accept. Proved by
`packages/std-http/src/tests/http_ws`, both sides.

### What backpressure means

A streamed answer is pulled only while its stream's windows are open and
nothing is owed on it, so it holds one piece at most — a slow peer
parks its own connection's task, never the whole server. A request body
is read as its handler asks, and the connection window is given back
only for octets the reader has taken, so a peer can never have more than
one window of body in flight that nobody read. Nothing here buffers a
body whole: `Limits.body` bounds only what a handler asks to gather,
and `Limits.stream` what a body may declare when it will be read piece
by piece.
