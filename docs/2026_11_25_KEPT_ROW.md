# A kept row costs nothing — proposal

**The question:** a window move pays for the whole window (tree, lower, diff, placement, and the host's facts) when
only a row or two is new. What would let a row that did not change cost nothing, soundly?

**Short answer:** reachable, with **one new fact** std-ui does not hold today: *the cells a component instance's
`describe` reads*. The compiler already fills that set for a text (`Sighted.reads`, the exact path). Widened from a
text to a component instance, it makes "this row is unchanged" decidable. Without it, the nearest sound rule is
narrower (below), and it already covers the windowed list.

## 1. What std-ui has, and what actually runs

- **tree/standing.av** keeps component **instances** (their state) between paints: a paint offers what stood at each
  step, once. It keeps **no output**: every instance a paint reaches is described again.
- **realize/dom/exact.av** (the web's exact path): the compiler records, for each text, the cells its words read
  (`Reading { cells }`). The page observes those cells, and a turn recomputes only the readings over written cells.
  It **declines to a full paint** when a *structural* cell (one whose writes change the tree's shape) was written.
  A task toggle writes `rows`, the list a `for` reads, which is structural. So a toggle is a full paint.
- **tree/rows.av** `windowed`: builds only the window's rows, `[self.at(i) for i in indices]`, all of them, every paint.

Probe (headless, `AVRA_BENCH_MODE=web ./avra run tools/ios-spike/bench`, the web's `dom.live` page, the walk's own
tally):

    first paint: 40 rows described
    one-row window move: 40 rows described
    one row toggled: 40 rows described

The native page is the same: 48–53 rows described per window move on the device (`rows_built`), and W1 (the board as
written) describes all 1,000 rows on every paint. **On every target today, a paint describes every row it reaches.**

## 2. What decides "this row is unchanged", soundly

A row's `describe` is a function of (a) its **key** (where it stands), (b) the **props** it was given, (c) the
**cells** its body reads (its own `state`, module `state`, anything behind a `Cell`), and (d) the **context** it is
described under (theme, env, the standing's own flags). If all four are as they were, the nodes it would produce are
the nodes it produced. That is the soundness argument: skipping is replaying a pure function on equal inputs.

- **Props without structural `==`.** Avra values are immutable, so **the same box means the same value**, with one
  exception: what a value reaches through a `Cell`, which is covered by (c). So a prop compares by **identity**: a
  scalar by value, a box by address. A false "changed" (an equal value rebuilt, as `r with { done: false }` rebuilds
  a row) costs a re-describe and is never wrong. A false "same" cannot happen. Unchanged list elements keep their box
  through `[if … { r with {…} } else { r } for r in rows]`, so on a toggle every other row is identical by address.
  What this needs: a comparison of two values by identity, a runtime row (`avra_box_key` already answers a cell's
  address; the same for any box), never a structural equality.
- **Cells read.** This is the missing fact. Today the compiler fills `reads` for texts only. A row that reads a
  module `state` (the board's `filter`, `dark`) through anything but a text is invisible to the exact path, which is
  why it declines whole. **The smallest sound rule needs the instance's read set**: the cells its body, and the fns
  it calls, can read. A static over-approximation, computed by the compiler as `Sighted.reads` is, is sound. A
  runtime read barrier would be exact but would cost every read.
- **The nearest sound rule without it:** skip an instance whose key and props are identical **and whose component
  is declared to read no cell outside its props and its own state** (a compile-time check, not a promise). The
  windowed list's row (`task_row(row: Row)`: an item, a checkbox, a button over `self.row`) qualifies. The board's
  rows, which read nothing global, would too. A row that reads module state does not qualify and is described as today.

## 3. A kept row: what each stage skips, and why it is safe

| Stage | Skipped for a kept row | Why it is safe |
|---|---|---|
| Describe | the row's body | its standing hands back the nodes it produced last paint (the standing holds them beside the instance); inputs equal ⇒ output equal |
| Lower | the row's native elements | lowering is a pure function of the Node; the standing's Node subtree is the same box, so its lowered element is reused by identity |
| Diff | matching inside the row | the matcher sees `Kept(was, now)` with `now` identical to `was`, and returns at once: no facts, no children walked |
| Placement | the row's own layout | its size is remembered (the measure cache already holds it); in a list its offset is arithmetic, the sum of the heights above it. The solver needs an entry that places one subtree at a width and a memo of a placed subtree by node identity and width |
| Host | everything | the diff said nothing; only a moved row's `rect` (its offset) is sent |

## 4. A window move then

Per newly exposed row, from the device's phase numbers (W2, 53 rows built, 13 new per move): describe ~33 µs, lower +
diff ~16 µs, placement ~62 µs, and host apply ~0.85 ms (three views from the row pool, ~9 facts, frames). A move
exposing **two rows**: ~0.2 ms in Avra plus ~1.7 ms in the host, plus the list's bookkeeping (the spacers' counts,
the kept rows' offsets: one `rect` each) — **~2 ms against ~17.5 ms today**, under the 6 ms budget with room for the
host's layout. The host's per-row cost is then the whole cost, and the row pool already makes it a recycle.

## 5. A toggle of one row

The same mechanism, not a second one: the toggled row's prop is a new box (`r with { done: … }`), every other row's
is the same box, so exactly one row re-describes, plus the footer if it reads the counts (it does on the board: its
text reads `tasks()`, so its words change and it re-describes). The exact path is this mechanism's special case for a
text whose cells changed. With read sets for instances it stops being a second mechanism: a text is an instance
whose read set is its reading's.

## 6. The first window

614 views against the twin's 192: a 40-row first window (`first_rows(40)`) plus an overscan of 10 each side, against
a table's visible cells (about 18 on this phone) and UIKit's small prefetch. What should size it: **the rows the
screen shows plus a small margin** (2–3 rows). That needs the host to say its visible height before the first paint,
and the native mount can ask it (the host knows the screen before the scene connects). Once kept rows cost nothing,
the overscan exists only to hide one paint's latency, and the velocity lead covers a fast scroll, so overscan can fall
from 10 to 2–3.

## 7. Where it lives, in order, each with its witness

1. **Compiler: an instance's read set**, filled where `Sighted.reads` is filled, as a static over-approximation.
   Witness: a test per shape (a row reading only props: empty; a row reading module state: that cell; a callee's read
   reaching the caller).
2. **tree/standing.av: a standing keeps the nodes it produced** beside the instance, with its props' identities and
   its read set's cells observed (the runtime's observe/log, as exact.av uses). On a paint, an instance whose key,
   props (by identity) and observed cells are unchanged hands back its nodes. Witness: the web's suites and goldens
   **byte-identical** — output is equal by construction — plus a "check" mode that describes anyway and traps on any
   difference, as `AVRA_EXACT=check` does today.
3. **realize/native: reuse a lowered element for an identical Node subtree**, and the matcher's fast return for an
   identical `Kept`. Witness: native tests, plus patch counts (a one-row move says the new row and the rects).
4. **place/: place a subtree at a width, memoized by node identity and width; a list's offsets by arithmetic.**
   Witness: placement's own tests unchanged, and a move's `solve_us` proportional to new rows.
5. **The first window sized by the host's visible rows**, and overscan 2–3.

**The web gets 1–2 for free**: describe and lowering are target-neutral, and the dom differ's `Kept` fast return is
the same change in patch.av. Its goldens stay byte-identical because nothing skipped would have produced different
output.

## 8. Asks for a ruling

1. **The read set:** may the compiler fill a component instance's read set (a static over-approximation, as for texts),
   or do you want the narrower rule first: skip only instances whose component reads no cell outside props and own
   state, checked at compile time?
2. **Identity as a prop's equality:** a runtime row answering whether two values are the same box (sound by
   immutability; a false "changed" only re-describes). Agreed?
3. **The standing holds output:** a standing keeps its last nodes beside its instance. This costs memory per kept
   instance (bounded by the window). Agreed, and should it be on for every instance or only under a list?
4. **The solver's entry** for a subtree at a width, with a memo by node identity: in place/, used by every target?
5. **First window and overscan:** the host tells the mount its visible rows before the first paint, and overscan
   becomes 2–3. Agreed?
6. **The exact path's fate:** keep it as the text-only fast path, or fold it into instance read sets once (1) lands?

"A kept row costs nothing" is reachable. Its one prerequisite std-ui does not hold is the read set (ask 1). The
narrower rule reaches it for the windowed list and the board's rows today, without that prerequisite.
