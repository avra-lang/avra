## What the design asks (§3.3, §5 review 1, CHANNELS §5.4 law 10)
- A `defer` runs WHOLE under a cancel: the frame's cold exit brackets
  its deferred calls with a row pair. Shielded, a call that may reach is
  not cut between them; a WAIT still answers the standing cancel at once,
  so it is cut at its first wait, not its first call.
- A `within` opened while shielded is a SHIELD SCOPE: waits under it
  answer only its OWN limit, so cleanup that waits is bounded by the
  time it wrote.
- A checked back-edge in a shielded task yields and raises nothing.

## The byte, resolved (DISCREPANCY FLAGGED)
The lane task says the first row "saves and clears the TICK byte". §3's
"the byte" is the UNWIND byte: "`unwinding` is a global byte the switch
swaps" (§3), §3.1's "the cold side may therefore set the byte". Clearing
`avra_tick` cannot be right: the emitted back-edge calls `avra_tick_cold`
only WHEN the tick is set (f:2050 tests it), so a cleared tick would mean
no call at all and §3.3's "a checked back-edge ... YIELDS" could not
happen. Read as `avra_unwinding`; the pair is a f:1692-style save/clear/
restore. If the lead meant the tick byte, this is the line to correct.

## The code
- `Scope` (f:184) gains `uint8_t shield`, set in `within_opened` (f:980)
  from the task's depth; a child's inherited record (f:1086) is no shield
  scope: the shield is a frame's, not a spawn's.
- `Fiber` (f:197) gains `shield_depth` and `shield_saved`. The pair
  `avra_fiber_shield_enter`/`_leave` (new) save the running bit and clear
  it at the outermost enter, restore it at the outermost leave; a nested
  bracket is a depth, so a deferred call's own cold exit nests.
  `avra_vtask_shield_enter`/`_leave` are the same on `f->unwinding`, as
  `avra_vtask_within` mirrors `avra_fiber_within`.
- `shield_scope_stands` (new): the innermost open scope is a shield one.
- `cancel_stands` (f:1706), `park_begun` (f:1717) and `fiber_cancelled`
  (f:2019) skip the task cancel while a shield scope stands, so its wait
  parks and only its deadline cuts it. `deadline_reached` (f:1043) does
  NOT drop a shield scope's limit under a task cancel.
- `avra_tick_cold` (f:2065) skips `cancel_met` while shielded; it still
  yields and still reads/clears the tick.
