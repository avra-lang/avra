# FLOW 01 — waiters, gates, task rows, the per-task slot: design note (v4)
Ticket `avra-8sb5.34.53.1`; base `89ea7f7`. v4 follows the build and review 3 of `810b072`; §11 says what each finding became. The scheduler is not rewritten yet. `f:` is `runtime/avra_fiber.c`. A number is MEASURED (the bench in §6, run by `sh tools/work run`), QUOTED, or ESTIMATE; unmarked sizes are the reviewer's PROBED ones (Waiter 48 B, Fiber 392 B, head 448 B).
**Today (READ).** A `Fiber` has one `next`, one `parked_fd`, one `timer` (f:125-138); the heap holds one entry per fiber and is never stale (f:201-206); descriptor lists hold fibers (f:287, f:358-364); an edge wakes EVERY waiter and readiness is a level bit (f:392-397, f:419-423); join files the fiber on `TASK_WAITERS` (f:733-749); a virtual task is the same struct (f:869-878); the yield path reads no waiter state (f:604-610, f:796-800).
## 1. Structs
```c
typedef struct Waiter { struct Waiter* next; struct Waiter** link;  // its source's list; link NULL = not filed, so unlink is O(1)
    Fiber* fiber; int32_t arm, member; uint32_t kind;               // W_FD_R, W_FD_W, W_AT, W_GATE, W_DEADLINE
    union { int fd; size_t timer; void* gate; } on; } Waiter;       // `on` is what G2 and `avra tasks` print as waits-on
struct Fiber { /* today's sp, task, next, joining, state, deadline, virtual */   // A RECORD ON THE HEAP, pooled: a task not yet run holds no stack
    uint8_t claimed, parked, deaf, expired; int32_t arm, member;    // THE SET: one live set per fiber. deaf = parked by an old row
    Waiter held[4], due; Waiter* more; uint32_t held_n;             // four inline, the deadline's own, an overflow list
    uint64_t id; Fiber* all_next; Fiber** all_link;                 // G4 id (0 = main); G2 and `forked` walk every live task
    uint32_t cancel_by; uint8_t unwinding;                          // who asked (G3, slice 3); unwinding is slice 3's
    void* slot[4]; char *base, *guard; uint64_t* canary; };                                               // §4, §7; slots unused by a virtual task
typedef struct { int64_t at; uint64_t seq; uint32_t kind; void* who; } Timer;   // T_WAITER or T_TASK (a fiberless `task_at`)
enum { GATE_HEAD, GATE_TAIL, GATE_OPEN, TASK_FIBER, TASK_BODY, TASK_ANSWER, TASK_AT, TASK_END, TASK_CELLS };  // a task record BEGINS as a gate
```
A gate is a record as a task is (f:140-145). Spawn site = the body's code address (f:684-685). `TASK_AT` is 1 + the task's heap index; `TASK_END` is 0 live, 1 answered, 2 cancelled.
## 2. The claim machine
`IDLE → ARMING (rows register waiters) → PARKED → CLAIMED(arm, member) → resume: unlink the LOSERS → IDLE.`
- `claim(w)`: THE CLAIMANT UNLINKS `w` FIRST and drops its count (heap entry popped, `g_parked_fds` down), then: set claimed → answer 0 and move on; else write `(arm, member)`, ready the fiber if PARKED, answer 1. So a due timer on a claimed set cannot spin `fire_due_timers` (f:552; same shape at f:396, f:813-814, f:822), a rouse of n is O(n), and the fast path at f:605 comes back at once. (Findings 7, 14.)
- `avra_wait_park` answers, in this order, before any switch: a claim made while the set was ARMING (a handed value is taken before anything else is heard — trap 2); else `cancel_by` set → `-1:0`; else the deadline passed → `-1:1`. A cancel that lost a claim is therefore answered by the NEXT park (finding 4). A source ready at registration claims at once: an OPEN gate, an unwatchable descriptor (f:836-840).
- CANCEL (`avra_task_cancel`): writes `cancel_by`; claims `(-1, 0)` only a set that is unclaimed AND not `deaf`. Sleep, join and `park_fd` park `deaf`: cancelling them is recorded and wakes nothing until slice 3 (finding 5). A fiberless task: taken out of the heap, its heap reference released, `TASK_END = 2`, its gate opened.
- ONE SET AT A TIME: sleep, join and `park_fd` trap "a task waited inside a wait it had not parked" when `held_n != 0` (finding 6).
- THE DEADLINE IS ARMED LAZILY, ONCE PER `within`: the first park inside the scope reads the clock once and files `due`; it stays filed until the scope ends (`avra_fiber_within_end` takes it out). Fired while running → `expired`; fired while parked → claims `(-1, 1)`. A `within` nothing parks under, and a spawn under one (the child copies a number, f:708), do no heap work. Sleep and join heeding it is slice 3; here they stay as today (f:802-808, f:733-749).
- `avra_task_answer` on a task already ended traps "a task answered twice". The heap holds a reference to a `task_at` until it fires or is cancelled (finding 10).
- `avra_fiber_forked` walks `all` and forgets every fiber but the caller's — waiters unlinked, gates released — so a child cannot ready a parent's task through a copied gate (finding 8; today's body, f:851-861, forgets descriptors, timers and the queue only). `avra_vtask_free` retracts gate waiters and releases kept gates too (finding 17; f:880-900).

- **A SEPARATE `avra_wait_task`, not "the evaluator's task id is its gate".** In the evaluator a task is `Val.I(index)` (`interp_tasks.av:88`) and that index is read by six arms (join, done, settle, settle-all, tasks-push, spawn); making it a gate changes all six for one caller. Natively both rows are two entries to one static body, because a task record begins as a gate.
- **The evaluator's gate** is the same C gate, so there is ONE claim machine: `GateNew` makes it through a twin, the machine lists it, and `retired()` (`interp_tasks.av:55-63`) releases every one. A gate lives to the run's end there, as every aggregate does today (PR #196 is what frees them; REASONED from its title). Natively the answer is an owned box and every gate seat is spelled `List<int>` — a `type` or an `alias` over a list is refused at a row's seat (`type.row_shape`, PROBED both engines, `tools/flow_bench/probes/gate`); privacy is the holder's private field. PROBED there too: a box read from a `Cell` and handed to a row is ONE box behind every copy of its holder, 0 clones, even through a `writes` seat; a `mut` local would fork it, so landing 2 pins "Bell never binds its gate to a `mut` local" with a test. The evaluator's list of gates is bounded: a gate leaves it when its handle is released, the rest at `retired()`. Twins (C in landing 1, declared in `interp_tasks.av` in landing 2): `avra_vtask_wait_fd/until/gate(t, …)`, `avra_vtask_park(t) -> 1 parked | 0 claimed`, `avra_vtask_claim(t)`, `avra_vtask_new(site)`, and `avra_vgate_open(g)`, which opens a gate for ever — what the evaluator calls when a `Job` ends, so its `WaitTask` arm is `avra_vtask_wait_gate` on the `Job`'s gate.
## 4. The per-task slot — a fixed table of four (ruled)
`void** avra_task_slots` in `avra_runtime.c` beside `avra_fd_drained_hook` (`avra_runtime.c:3247`), pointing at a static main table; `switch_to` repoints it — one store. `avra_task_id` reads a word beside it. No scheduler is linked by a program that never spawns; wasm carries both (`Makefile:236`). A child's slots start NULL and its id differs, which is how the DB engine refuses (O2 = A). A VIRTUAL task's slots and id live in the evaluator's `Job`; a vtask switch never repoints the host's table, so the compiler keeps its own asker while it evaluates. KEYS: one table in `core/runtime_api.av` (0 asker, 1 flow scope), generated into `avra_rt.h` as an enum (`make rt-header` already refuses a stale header, `Makefile:733-736`), `_Static_assert`ed against `slot[4]`, and `make externs` holds every `.av` constant passed at key seat to it. The evaluator's MAIN has slots before its root `Job` exists (`interp_tasks.av:36-53` makes it lazily): they live on the machine and the root `Job` adopts them when it is made (landing 2, with its test).

## 7. Stacks — MEASURED on the Sprite (`make flow-probes`), and the recommendation
| probe | result |
|---|---|
| (c) ceiling with one `mprotect` guard per stack, `vm.max_map_count` 65530 | 32,754 stacks, then `mprotect`: "Cannot allocate memory"; 2 mappings a stack; the same at 256 KiB |
| (c) what a guard costs a fresh stack | `mprotect` 3.5–6.5 µs; none 0.03 µs. First touch of the top page 2.3–11 µs. Together they ARE the 8 µs cold spawn. Mac: 0.6–0.8 µs and 1.5–5.1 µs |
| `MADV_GUARD_INSTALL` on 6.12 | refused, "Invalid argument" — guard regions could not be measured anywhere |
| (b) reservation 1 MiB → 256 KiB | page tables 2059 → 521 B a stack; resident 4.1 KiB both; cold spawn 8.4 → 7.8–8.0 µs; a million 256 KiB stacks with NO guard map and touch: 4104 + 521 B each, 24 mappings |
| (a) record at 392 B, zeroed whole vs its 80 B prefix | no difference outside noise: warm 590 vs 583 ns (run 1), 864 vs 571 (run 2); cold 8588 vs 8269, 8686 vs 8745. Review change 2 buys nothing measurable; adopt it only for tidiness |
**THE OWNER'S RULING, CONFIRMED: D-hybrid + B, 256 KiB default.** One function decides it (`guards_settle`) and carries the owner's comment, which the code is held to line by line.
- Guard regions where `madvise(MADV_GUARD_INSTALL)` is accepted (settled once, on the first slab): every stack fully guarded, no mapping split. WRITTEN BLIND — no kernel here has them; only its fallback is tested.
- Else the first K stacks each get an `mprotect` guard, K = a quarter of the mapping limit read at start ÷ 2 (8,191 on a default Linux; every stack where no limit is readable, as on macOS): a quarter of the limit for guarded stacks, half left to the program, and a million slab-guarded stacks take 31k more. A guard the kernel refuses early ends K there.
- Beyond K: one guard per slab of 64 adjacent stacks, the top word of each stack reserved as a CANARY that is never written (an untouched page reads zero, so it costs no resident page), and a check at EVERY SWITCH-OUT, inside `avra_fiber_switch` itself (five instructions, so no park or yield carries a frame for it) — the saved stack top below the stack's floor, or the word under the floor non-zero → trap by name with the task's spawn site. THE LAW, in the code: beyond K an overflow is caught at the next switch, not at the write, and a bounded one that neither stays below the floor nor writes that one word is not caught. A runaway still reaches the slab's guard.
- `AVRA_FIBER_GUARDS=all` gives every stack a guard PAGE and the ceiling that comes with it (its trap names the remedy); a whole number sets K. A value asks for pages by name, so it is given them whatever the kernel has — BY DESIGN it skips the guard-region probe: the owner's comment says `all` is a page each and capped, and a count is how the policy past K is run and tested on any kernel. Any other spelling traps by name at the first spawn. `MADV_NOHUGEPAGE` on every slab.
- TWO POOLS, a page-guarded stack preferred: "the first K tasks" are whoever holds a stack while at most K do, so a lone task after a burst past K is guarded at the write again.
- A stack is never unmapped: after a burst of N tasks, N stacks' page tables and N records stay for the process's life, and pages given back with `MADV_FREE` stay in the resident count until the kernel wants them.
- **A stack is bound at a task's FIRST RUN, not at spawn** (review 2 §4.1): the record is on the heap, so 10k spawned-then-joined tasks reuse two hot stacks. ADOPTED on the probe (Sprite, MEASURED): 10k alive cold 8054 → 424 ns a task, one at a time 174 → 180, switch 7.0 → 7.6 with the branch in line (out of line as built). Option C is not built.

## 10. Risks
1. Beyond K the guard is a check, not a page (§7's law). 2. A 256 KiB default is a behaviour change for deep recursion in a task (`AVRA_FIBER_STACK` restores it); the suites decide. 3. Guard regions are written blind. 4. The switch-out check adds instructions to the yield path; the gate names each.
## 11. Review 3, item by item
1. A task that ends with a wait it never parked on retracts it (`fiber_start`), as a freed virtual task does. Tests: `ends_without_parking` (gate, time), and "freed with a wait it never parked on" in `as_virtual`.
2. A fork KEEPS the timer's tasks and the caller's own deadline in the heap — they are the child's memory, and whoever waits on one there is owed its time; only other tasks' waiters and deadlines leave. Test: `forked_with_timer_tasks` in `cores_test.c`.
3. Two stack pools (§7). Tests: `lone_after_burst`, `recycled_past_k`.
4. The guard count is read whole or refused. Tests: the four `AVRA_FIBER_GUARDS=` traps in `stacks`.
5. THE WORLD IS ASKED EVERY 64 SWITCHES, never per switch: one countdown replaces the two loads the fast path tested, and whoever files a time or a descriptor brings it within reach. A due timer waits at most 64 switches while tasks are ready — the bound a descriptor already had. Rows: `yield_under_within`, `c_yield_under_within`.
6. `make runtime-mutations` (`runtime/tests/mutations.py`): 31 single-line breaks, each killed by a runtime test; a break whose line has left the source fails the run.
7. The law's hole is pinned as it stands: `uncaught_overrun` passes while a bounded overrun that skips the canary word goes uncaught.
8. NOT DECIDED HERE: a join of a fiberless task that ended with no answer (cancelled, or fired by the heap) answers NULL. Landing 2 decides what such a join answers before any `.av` declares `avra_task_at`.

10. `avra_wait_gate` and `avra_wait_task` declare `writes` and `keeps`, as their siblings do.
11. The frame proof is published for both architectures (the phase C report).
12. Stacks never unmapped: said in §7. No bench row for the resident count after a burst: `MADV_FREE` pages leave it only under memory pressure, so the row would measure the kernel's mood.
