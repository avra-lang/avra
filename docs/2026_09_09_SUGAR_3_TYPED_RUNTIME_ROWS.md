# Sugar 3 — typed runtime rows

## The want
A runtime call names its row with a string:

    cx.emit(Ins.CallRt(crossed, "avra_str_of_bytes", [octets]))

A typo compiles; the registry (`rt_sigs()`) is consulted only later,
and CLAUDE.md's rule is "no string tags".

## The form
    cx.call(rt.str_of_bytes, octets)

`rt` is a namespace generated FROM the registry: one name per row,
carrying the row's seats and answer. A call site is checked against the
row at typing time — seat count, seat kinds, ownership — not at
emission.

## Rules
- `rt.<name>` is the row whose C symbol is `avra_<name>`; the prefix is
  the projection's, never spelled by a feature.
- A row that does not exist is a check-time refusal naming the nearest
  row.
- The five registry consumers (`rt_sigs` readers) keep reading the same
  table; `rt` is a projection of it, so adding a row is still one row
  plus one C body.

## What it buys
Every `CallRt` in the compiler becomes a typed call. The keeper that
checks extern seats against C already exists; this makes the
compiler's OWN runtime calls go through the same door.

## Cost
A generated namespace from the registry (a build step or a compile-time
projection once `@comptime` lands). Until then a checked-in projection,
regenerated by `make`, with a keeper that refuses drift.

## Trigger
Lands with the registry's next row.
