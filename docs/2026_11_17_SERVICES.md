## 1. Working rules

1. Commit on `services` only. Never on `program` or `main`.
2. A finished slice: message the lead with its commit shas. The lead batches it; the GitHub gate checks it.
3. Run the touched package's own suite locally. The gate covers the compiler and cross-package checks.
4. Plain std-package code only until the switch (the old compiler still checks library code).
5. A language ask goes to the lead as a list, one sample program each.
6. Every slice: red team, then review round, then `fmt --check`.
