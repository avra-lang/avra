# iOS benchmark — the board on UIKit against a hand-written twin

Simulator numbers (iPhone 16 Pro simulator, iOS 18.5, Apple-silicon Mac) are **relative only**: they
compare the two apps on one machine. Device numbers come later.

The bar (docs/2026_11_16_UI.md, "The performance bar"): one changed value reaches the screen with no
tree rebuilt and no allocation; a frame's work fits 8 ms; 10,000 rows fling with no dropped frame and
memory follows the rows on screen; within 10% of a hand-written UIKit app on cold start, memory and
update time; counters per change recorded and only shrinking.

## Workloads

- **W1, the board as written**: `tools/ui-board`'s `view`, unedited, seeded with N tasks through its
  hydration door (`tasks_written`). Its list is `list { for t in visible() { task_row … } }`, which
  nothing windows, so every row is built on every target.
- **W2, the windowed list**: the same row (switch, title, Remove) through std-ui's `windowed(...)`, the
  host supplying the window from the scroll view.
- **The twin**: Objective-C UIKit, a `UITableView` with cell reuse, the same rows in memory.

## D1 — does the board build every row? (headless, native binary on the Mac)

`AVRA_BENCH_ROWS=<n> ./avra run tools/ios-spike/bench` (tools/ios-spike/bench). One first paint on a
`NativeLive`; three runs, counts identical across them.

| Tasks | Native elements | Created | Patches | Build tree | Lower + diff |
|---|---|---|---|---|---|
| 100 | 327 | 327 | 1,471 | 1 ms | 1 ms |
| 1,000 | 3,027 | 3,027 | 13,471 | 7 ms | 7 ms |
| 10,000 | 30,027 | 30,027 | 133,471 | 70–75 ms | 79–82 ms |

Each task is 3 elements (item, checkbox, button) and ~13 patches; the page is 27 elements. Linear.
Windowing exists (`tree/rows.av`) but is opt-in: nothing lowers a plain `list { for … }` through it.

## The instrument (D3)

One definition for both apps: `tools/ios-spike/host/spike_bench.m`, compiled into the Avra host and
into the twin. All times come from the display link: "drawn" is the later of the frame's
`targetTimestamp` and now.

- **Cold start**: process start (`sysctl` start time) to the first display-link tick after the first
  frame is applied to the views.
- **Memory**: `task_info` `phys_footprint`, 1 s after the first frame and 1 s after the fling.
- **Toggle**: the first row's switch flipped programmatically, to the first tick after the change is
  applied (Avra: after the turn's frame and its rects; twin: after `reloadRows`).
- **Fling**: `contentOffset` driven top to bottom over 3 s by the display link; frames drawn, longest gap,
  gaps over 16.7 ms. The simulator draws at 60 Hz, so "over 8.3 ms" is every frame and is not reported.
- **Avra counters**, per paint, logged by the spike's mount (`spike: paint …`) and host (`spike: host …`):
  time building the tree (`describe`, wrapped), lower + diff, serialize, place (the solver with UIKit
  measuring), host apply; patches, facts, creates; measure calls; live bytes (`avra_mem_live`). **Boxes
  allocated have no counter in a normal runtime** (`g_boxes_made` exists only under `AVRA_CENSUS`), so
  live-byte deltas stand in.

Re-run (simulator, one boot per run, five runs):

    sh tools/ios_board_witness.sh                                   # builds Spike.app once
    AVRA_BOARD_MODE=2 AVRA_BOARD_SHOTS=16 AVRA_BOARD_FOR=20 sh tools/ios_bench_runs.sh w2 5 avra
    AVRA_BOARD_MODE=1 AVRA_SPIKE_ROWS=1000 AVRA_BOARD_SHOTS=22 AVRA_BOARD_FOR=26 sh tools/ios_bench_runs.sh w1-1k 5 avra
    AVRA_BOARD_MODE=1 AVRA_SPIKE_ROWS=3000 AVRA_BOARD_SHOTS=50 AVRA_BOARD_FOR=55 sh tools/ios_bench_runs.sh w1-3k 5 avra
    sh tools/ios_bench_runs.sh twin 5 twin

Runs land in `build/ios-spike/bench/<label>-<n>.out`. Each run checks free disk first and stops under 3 GB.

Ranked by time: place ≫ host apply ≫ build tree ≈ lower + diff ≫ serialize. Place is 79–99% of every paint,

## The three largest costs, ranked from the numbers

1. **Placement re-measures everything, every paint** (W2: 113 ms of a 140 ms window paint; a toggle 96 ms of
   136 ms). Remedy: a measure cache keyed by prim, words and available width (and text size), so an
   unchanged row is never measured again; with it a toggle measures one row and a window move only the
   ~20 rows it brings in. Estimate from the numbers: place falls from ~113 ms to ~5 ms (20 new rows × 0.27 ms),
   a toggle from 136 ms to ~35 ms. Placing only the subtree that changed (the solver re-entering at the
   changed node) takes the rest.
2. **The idiomatic list is not windowed** (W1): start, memory and toggle all linear in rows — 37.8 s and
   3.5 GB at 10,000. Remedy: `list { for … }` lowered through `windowed` (cost number one, the lead's).
   Estimate: W1 becomes W2, from 3,503 MB to ~50 MB and from 37.8 s to ~1 s of start.
3. **Host apply builds views from text each paint** (W2: ~27 ms per window move for ~124 creates, ~0.2 ms
   each; W1-1k: 613 ms for 3,027). Remedy: reuse views by prim (a pool, as a table reuses cells) and a binary
   frame instead of text records. Estimate: a window move's apply from 27 ms to ~5 ms. Serialize itself is
   small (0.1 ms per W2 paint), so the binary frame's gain is in the host's parse, not Avra's write.

Smaller, but on the bar's own terms: a toggle rebuilds the whole tree (tree + diff ~0.5 ms in W2, 14 ms in
W1-1k, 196 ms in W1-10k) where the bar wants no tree rebuilt: the native exact path (one changed value, one
fact patch) removes it. Facts are re-made for every node each paint (182 facts said per window move) where
only changed nodes need them.

The twin's own costs, for fairness: its header wraps "Ac-tive" and "New-est first" by UIKit's defaults;
its cold start includes laying out the table header; its fling's 2 long gaps are cell creation at the start.

## Fix round 1 — F1, measuring

Same instrument, same commands; W2 five runs per step, W1 at 1,000 three runs. Median (range).

| W2 windowed | Baseline | F1a: measure without a control | F1b: + remembered measures | F1c: + no placement for still facts |
|---|---|---|---|---|
| Cold start | 971 ms (852–994) | 780 ms (758–987) | 823 ms (792–841) | 816 ms (783–867) |
| Memory after first frame | 50.1 MB | 37.9 MB | 37.8 MB | 37.6 MB |
| Toggle to frame | 136 ms (119–138) | 18.8 ms (13–27) | 19.0 ms (14–32) | 27.6 ms (13–33) * |
| Fling frames / gaps > 16.7 ms | 21 / 20 | 54 / 50 | 55 / 52 | 54 / 51 |
| Longest fling gap | 186 ms | 79 ms | 76 ms | 99 ms |
| Memory after the fling | 90.0 MB | 206 MB | 210 MB | 210 MB |
| Place, a toggle | 95.6 ms | 1.85 ms | 0.73 ms | 0.16 ms (not placed) |
| Place, a window move in the fling | 112.7 ms | 30.0 ms | 29.0 ms | 29.4 ms |
| Measure calls to the host, a window move | 415 | 425 | 126 (cache misses 128 of 429) | 126 |
| Host measure time, a window move | (in place) | 0.76 ms | 0.27 ms | 0.28 ms |
| Host apply, a window move | 26.6 ms | 28.8 ms | 28.2 ms | 28.7 ms |

\* F1c's toggle is placed by nothing; its time is the turn plus frame alignment (13–33 ms spread is vsync).

**F1a.** The host measures text with `NSString` bounding rects in the control's own text style, and a
control's chrome (a switch's size, a field's height, a bar's height, a spinner) as constants read once from
one real instance. A warm call now costs **~1.9 µs** (0.76 ms for 425 calls), against ~270 µs when a control
was built per call; the first paint's 22 ms is font loading.
**F1b.** `tools/ios-spike/src/remembered.av`: `Remembered` implements `Measure` over another `Measure`,
keyed by a node's size key (prim, words, rank, type fields, and the attributes that carry text or room:
title, placeholder, a spacer's rows, open) plus the width asked; forgotten whole on "measure again".
Hit rate: a toggle **427/427**; a one-row window move **421/429**; a window paint mid-fling **301/429** —
the fling jumps a whole window per paint. To lift it into `place/` the key is the open question: a
target-neutral cache needs the Node to say which of its fields size it (an ask).
**F1c.** `moves_box(What)` in realize/native/fact.av answers per fact code, every code spelled, whether a
change to that fact can move a box (words, rank, type, layout, contrast: yes; checked, disabled, fill, ink,
radius, mode, value, …: no). `moves_boxes(patches)` in patch.av; a paint where it is false is not placed.
A W2 toggle (a check only) is no longer placed. **W1 at 1,000 still re-places on a toggle**, correctly: the
board's footer words change ("3 open · 1 done").

| W1 board as written, 1,000 | Baseline | After F1 |
|---|---|---|
| Cold start | 4,124 ms | 2,003 ms (1,984–2,078) |
| Memory after first frame | 386 MB | 171 MB |
| Toggle to frame | 2,715 ms | 69.7 ms (58–72) |
| Place on a toggle | 2,235 ms | 19.7 ms (hits 10,077, misses 3) |
| Memory after the fling | 454 MB | 192 MB |

**New largest costs after F1**: host apply (~28 ms per window move), and on a cache miss ~220 µs per
measured node spent on Avra's side of the measure call (29 ms for 128 misses mid-fling, of which the host's
own measuring is 0.28 ms) — the key building and the crossing, not UIKit.

## Fix round 1 — F2, host apply

| W2 windowed | After F1 (F1c) | F2: views reused by prim, a removed subtree pooled whole |
|---|---|---|
| Cold start | 816 ms | 788 ms (754–866) |
| Memory after first frame | 37.6 MB | 37.5 MB |
| Toggle to frame | 27.6 ms | 22.9 ms (19–31) |
| Fling frames / gaps > 16.7 ms | 54 / 51 | 92 (80–98) / 76 |
| Longest fling gap | 99 ms | 53 ms |
| Memory after the fling | 210 MB | **72.9 MB** |
| Host apply, a window move | 28.7 ms | **14.7 ms** (127 of 127 creates reused) |
| Place, a window move | 29.4 ms | 15.4 ms |

**Did a window move re-create kept rows? No.** Headless (`AVRA_BENCH_MODE=window ./avra run tools/ios-spike/bench`),
a one-row move is 20 patches: the row that left and its spacer removed, one new row created (item, checkbox,
button: 3 creates) and placed, and the bottom spacer's row count changed. Kept rows are untouched. One quirk:
the top spacer is removed and re-made every move, because its key carries the index of the row after it
(`~skipped-<next>`, tree/rows.av). The 127 creates per paint in the fling are real: the test fling jumps more
than a window between paints.

**The memory after the fling was a host leak**: a `remove` dropped only the removed element's own node, leaving
its descendants in the host's table. The pool removes the whole subtree; memory after the fling fell 210 → 73 MB.

## F3, the blank mid-fling — not fixed, and why

The test fling crosses 10,000 rows in 3 s (~146,000 pt/s). A 40-row window with a 10-row overscan is ~2,200 pt:
about 15 ms of that scroll, less than one paint (~33 ms: tree 3, place 15, apply 15). A finger's fling is
5,000–20,000 pt/s, where the same window covers 110–440 ms. What the host needs regardless: an overscan
proportional to velocity (ask for the rows the scroll will reach by the next paint, not the ones on screen),
and placeholder rows drawn in a spacer's room at the estimated height while their real rows are on the way,
as a table draws empty cells. A real design for variable heights needs the estimate per row and a correction
when a row's measured height differs (the spacer's room adjusted, the scroll offset kept).

## What is in the 2.9 MB binary

`size -m` gives 2.18 MB of `__TEXT`, 1.85 MB of it code. By symbol (address deltas, grouped by package):

| Part | Code bytes |
|---|---|
| **sqlite (C)**, the `sqlite3_*` names plus its static internals (parser, FTS5, R-tree, JSON, window functions…) | **~1,300,000** |
| @std/ui | 155,048 |
| @std/http | 108,332 |
| runtime | ~46,000 |
| @std/task | 32,212 |
| @ui/board | 31,172 |
| @spike/ios (the app's own Avra) | 30,836 |
| @std/net, @std/json, @std/url, @std/validate, @ui/board_model, the rest | ~85,000 |

**The client carries its server's database**, through: `@ui/board` (board.av) → `@ui/board_model`
(model.av: `use @std.crud.{crud}`, for `Todo.paths("/tasks")`, the route a client asks) → `@std/crud` (crud.av:
`use @std.sqlite.{Db}`; routes.av: `use @std.sqlite.{Db, SqlValue}`) → `@std/sqlite`, whose `[link]` row links
sqlite's C. The Avra code the app uses from crud is 2.4 KB; the link row brings 1.3 MB. Without it the app is
~0.6 MB of code. The ask: a package's link objects follow the code a program reaches, not the packages it
imports — or `@std/crud`'s client half (routes as paths) stands in a package that does not import sqlite.

## Now the largest cost

After F1 and F2 a W2 window move is ~33 ms: host apply ~15 ms and place ~15 ms, then the tree ~3 ms.
Place's 15 ms is not measuring (the host's measures are 0.27 ms of it): it is the cache misses' key building
and crossing on Avra's side (~220 µs a miss before F2's run) and the solver over the window. A toggle on W2
is now ~23 ms end to end, faster than the twin's 27 ms, with nothing placed. W1 at 1,000 still re-places
3,000 nodes on a toggle (19.7 ms) because its footer words change, and builds every row.
