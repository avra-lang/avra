# The keepers, classified

Every keeper in the Makefile's `KEEPERS` (78), which `KEEPERS_STATIC` (20) and `KEEPERS_PR` (9) are subsets of, with what each checks, the code it guards, and a verdict. Each verdict quotes what the keeper reads, from its Makefile recipe and the script that recipe runs.

- **(a) DELETE**: it guards the old Workspace/`Decls` store, or a migration that is done. It is off std-program's path.
- **(b) TEST**: a behaviour check that belongs in a package's `spec`/`given`/`then` suite or its program tests.
- **(c) WISP**: a whole-tree law, which becomes a `wisp check <name>` verb. The owner's order moves internal tooling into wisp.
- **(d) KEEP**: stays as it is, with the reason given.

Counts as first classified: 2 DELETE, 1 split DELETE/WISP, 5 TEST, 23 WISP, 47 KEEP. Since then, by the owner's decision, flow-trace and exact-patches are KEEP; tools-suite is gone, packages/wisp's tests running in the derived suites, and cited and http-cites are DELETE; codecs and twenty trap rows have moved into suites. Group column: K = `KEEPERS`, S = `KEEPERS_STATIC`, P = `KEEPERS_PR`.

## How the store question was settled

The old store is gone. `type Workspace` is declared only in a test (features/structs/tests/identity_test.av). Features' `Decls` is built only by three test files. Nothing outside tests calls its `let_go`/`disarm` or arms one of its hooks. The item path's `Decls` is `@std.meta.Decls`, a different type. A keeper is (a) only when what it reads is reached from nowhere but there.

The candidates checked and found **live** (not (a)) are these:

- **The six store attacks:** each drives the build through env flags, and every flag is read by live code:
  - std-program/src/worked_ahead.av reads `AVRA_AHEAD_EDIT`, `AVRA_AHEAD_UNPROVEN`, `AVRA_MERGED_HERE`, `AVRA_MERGED_APART_FROM`, `AVRA_SHARE_UNMERGED` and `AVRA_BESIDE`;
  - std-program/src/disk_store.av reads `AVRA_WAVE_ALONE`;
  - compiler/item_signatures.av reads `AVRA_HELD_BYTES` and `AVRA_HELD_ITEMS_OFF`;
  - runtime/avra_cores.c reads `AVRA_HEIR_LINGERS_MS`, `AVRA_SHARED_KILL_AT` and `AVRA_SHARED_TRAP_AT`.
- **cutoff-witness:** its line is `QueryEngine.cutoff_said()`, std-program/src/query_engine.av:681.
- **read-lists:** `engine.read_lists()`, cli check_program.av:115.
- **warm-edit:** a warm `check packages/cli` over the live store.
- **stems:** the Makefile's `TREE_STEM_LAW`; it reads no store at all.
- **read-cost:** its bench imports `@std.relation.db.{Db}` and `@std.relation.engine.{Kernel}`. That is the memo kernel a running program's `@query` asks, so it is live.

One measurement backs families-left's verdict: a cold `check` of a fresh one-file package under `AVRA_QTRACE=1` records no `Memo.ask` event, only `parse` and `print` lines. That was traced on `check` only.
