# THE FLOW G1 GATE

Ticket `avra-8sb5.34.53.32`. Slice `flow-g1-gate`, stacking on the G1 view
(`flow-g1`, PR #517). No landing.

## Why

`77fc7b1` (#490, "the tick") added `avra_tick_armed()` to `ready_push`'s
empty-queue edge (`runtime/avra_fiber.c:273`), whose fast path reads
`getpid()`. The G1 report measured the consequence: a C gate round trip
went from flow-01's 98 ns to 1059 ns. Nothing in CI ran a latency row,
so a runtime change could cost 10x on the transition hot path and only a
hand-run bench would notice.

The G1 bench (`tools/flow_bench/`) already measures the scheduler's rows
in C (`probes/spawn_bench.c`, `c` prefix) and in Avra. This slice adds a
**gate mode** (`run.sh --gate` / `--record`, `gate.py`) that runs those
rows against a **recorded baseline** and **refuses** past a margin.

## The rows the gate holds

| row | why it is the gate |
|---|---|
| `c_gate_round_trip` | the row that regressed: two `ready_push` on an empty queue, two `getpid()`. |
| `c_spawn_one` | about two empty-queue pushes per task — the same cost, spread over spawn and join. |
| `c_spawn_parked_cold` | the parked transition, cold; the tick's share is smaller here. |

The **C runtime rows** are the gate, not the compiled Avra twins: they
seed from the runtime's `.c` alone, so they build on any tree and compare
against a recorded baseline with no compiler and no Go. The Avra twins
stay published beside Go by #517's view (`table.py --gates`); a compiler
change must not fail a runtime gate.

## Design

`tools/flow_bench/probes/spawn_bench.c` gains one mode, `g1`, that runs
those three rows in one process (the parked row first, so its first-touch
cost is the process's own), each the least of five. No second harness and
no second probe: the mode shares `spawn1`/`joined`/`rally`/`parked`.

`run.sh --gate` builds the runtime objects and the probe (`runtime_built`,
`spawn_bench` — the same functions the bench uses) and runs `g1` three
times; `gate.py` reads the least per row and compares to
`tools/flow_bench/gate.baseline`, `<platform> <row> <total ns> <count>
<toolchain>` — one row per machine, like `footprint.baseline`, so a Sprite
and a Mac are never compared. `FLOW_RUNTIME=<dir>` measures a runtime
saved elsewhere, for a before/after through the same instrument.

**Margin: 2.0x** (the G1 time gate), `FLOW_GATE_RATIO` to move it. Far
above the <2pread the rounds show, far below the ~14x a `getpid()`-per-
transition costs. A machine with no accepted row PRINTS the rows and does
not gate (`--require` refuses instead); the gate always states how many
rows it examined and gated.

## Wiring

`make flow-gate` is the one definition (`make flow-gate-accept` re-records
this machine). The runtime-PR path runs it through a `flow-gate` job in
`.github/workflows/checks.yml`, which `prepare` fires only when the diff
under `runtime/` moved (a PR, a train, or a push to main against its
parent), running `make flow-gate FLOW_GATE_ARGS=--require`; `test`
aggregates the job, so a red gate stops the run.

It is deliberately NOT a keeper in `KEEPERS_B`. The committed baseline is
the pre-tick line, so a whole-keepers train would refuse on main today —
branching from a tree that carries `.32` — and the gate PR itself could
not land. The conditional job gives the same teeth where they belong (the
runtime path) and lets a compiler-only PR pay nothing. Once `.32`'s fix
lands and main is green, adding `flow-gate` to `KEEPERS_B` is one word.

## Proof (Sprite `avra-cores`, Linux 6.12 x86_64, clang 22.1.2)

Two runtimes through one instrument: the tree's (with `.32`) and a saved
copy of `77fc7b1~1` (pre-tick), each recorded, then judged.

| row | pre-tick accepted | tree (`.32`) | ratio | gate |
|---|---|---|---|---|
| `c_gate_round_trip` | 75.8 ns | 1059.1 ns | **13.96x** | REFUSE |
| `c_spawn_one` | 186.6 ns | 1210.6 ns | **6.49x** | REFUSE |
| `c_spawn_parked_cold` | 8566.0 ns | 9373.8 ns | 1.09x | pass |

The pre rows judged against the pre baseline: 1.00x each, exit 0. The
tree's rows judged against the pre baseline: exit 1. The committed
baseline IS the pre-tick line (`gate.baseline`), so a runtime PR that
costs the transition is refused. The shipped path was then run as the
job runs it, `make flow-gate FLOW_GATE_ARGS=--require` on the Sprite,
and refused with the same two rows (14.03x / 6.45x), `make` reporting 2.
The Mac walks the same rows at ~82 ns a round trip (`getpid()` is free
there), which is why no `darwin-arm64` row is accepted and the Mac stays
informational.

## Landing order

This slice touches no `runtime/`, so its own run skips the gate and lands.
The committed baseline is the good line, so the NEXT runtime change —
including `.32`'s pid-cache fix, its own slice — is measured against it:
a fix that restores the transition passes, a regression is refused. Until
the fix lands, a runtime PR that keeps the `getpid()` on the transition is
refused, which is the gate working. If the lead wants the tree's today's
numbers accepted instead, `make flow-gate-accept` overrides.
