WHY ONE COMMIT GATES: the ladder's split is owed only by a row whose seat takes
a BOX — `crossing_law` exempts a row's name only when it is ARMED, and the
standing compiler does not carry a new row (`features/fns/check.av:120`). These
rows take no seat and answer `void`, so the standing compiler accepts their
declarations (`crossable`, `check.av:176`). No split.

## What one commit cannot prove, stated plainly
The shield has no observable effect until ladder 9 emits the bracket on a frame's
cold exit, and no `FlagRead` is emitted to read the bit (ladder 7, #465). So:
- the RED-FIRST tests are the registry's own: `core/tests/runtime_shield_test.av`
  — before this commit the row is absent from `rt_sigs()` and the namespace has
  no `fiber_shield_enter` method. 3/3 pass after.
- the program test `features/tasks/tests/shield_rows/` proves the row lowers and
  runs identically in BOTH engines (the program's own task and a spawned one),
  but it is NOT red before wiring: an undeclared row lowers as an ordinary
  extern. Said here rather than dressed as a failing-first case.
- the arm itself is held STRUCTURALLY: `RtHost` is a registry enum matched with
  no `_ ->`, so a host with no arm does not compile.

## The setter, and its missing caller (pinned to ladder 9)
`avra_vtask_set_unwinding` (f:2343, ladder 5) is DECLARED here and called by
nothing. #465 pins its first caller to ladder 9: a cancel met by a virtual task
never sets the task's own bit (`avra_vtask_*` parks run `cancel_met` on the
host's global, not the virtual fiber's field), co-designed with the evaluator's
claim handling. This commit only puts the seam where that caller will reach it.
