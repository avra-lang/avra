## Step 1 — a join is an event, in both engines (PR `flow-g4a`)
- One new line, `join id=<joiner> on=<task id | unrun>`, written where the joiner is about to wait: natively in `task_awaited` after the open-gate return (the target's id is its fiber's, `TASK_FIBER`; a task nothing runs has none and says `unrun`); evaluated through a new twin `avra_vtask_joins(t, on)` called in `waited_on`. A join or settle of a task already done waits on nothing and says nothing, in both.
- The wake: natively the existing `claim id=<joiner> by=<ended task>`. Evaluated, `ended` wakes each waiter through a new twin `avra_vtask_joined(t, by)` — `ready_push` plus the same `claim` line — in place of `avra_vtask_ready`. No wait arm, pick or clock is touched; both twins take words only, so they are plain externs and ride one landing.
- Reader: `join` reads "joins task N"; the gate park a native join files right after it is folded into that line. New `--shape`: per task, the events in order with no stamp, no address and no site — the part the engines agree on by design.
- Tests, failing first: `flow_test.c`'s traced scene (a native join and a virtual one each say `join` and `claim by`); one mutation; the reader's self-test; keeper `flow-trace`: `features/tasks/tests/traced_join` run evaluated and compiled under `AVRA_FLOW_TRACE=<file>`, the two `--shape` outputs equal and equal to a committed text.
## Step 2 — a spawn site is a source line (as built, PR `flow-g4b`)
- MEASURED today, Sprite (Linux x86_64 ELF, a two-spawn program): a task body's symbol is `av_main$24l14$24task` — module, file stem and the node's index, no line; `addr2line` answers `??:0` (no debug section); stripped, `nm` reads no symbol. So the binary cannot say a line by itself.
- THE CARRIER IS THE PROGRAM'S SITE TABLE. `Body` gains `site: string?` — `file:line` for a task's lift, written by the lowering (`written_at`), the file named by package, module and stem (`Decls.file_named`), never the building machine's path. The backend files one ROW per task body, `{ entry, text }`, in a section of its own (`avra_sites` on ELF, `__DATA,__avra_sites` on Mach-O; `AvraSiteRow`, avra_box.h), kept by `llvm.used` through `--gc-sections` and `-dead_strip`. The runtime names a task by the row whose entry is its body's (`site_of`, under the trace only), and code no row names — C's own — by its address. NOTHING READS CODE'S BYTES, so execute-only text is safe, and a task body's entry is the function's own aligned start (x86-64: 16; MEASURED `…3650`, `…3740`). The evaluator reads the same field of the same `Body` through `avra_vtask_sited`. A wasm module files no row: it runs no task.
- A site in a generic fn used from another file reads THAT file's line (MEASURED: `twice<T>` in `helpers.av`, used at two types from `main.av`, says `helpers.av:5` in both engines — keeper program `traced_generic`).
- One new line from both engines, `site id=<task> <file:line | 0x…>`, after the spawn's; the reader folds it into the spawn ("spawned by task 0 at zz-traced_join/main.av:10"), and the shape keeps a source line.
- (#369 laid the site in the bytes before the entry; review 2 asked that only a body the compiler marked be read, and noted the entry then sat at 8 mod 16 on x86-64. The table answers both.) MEASURED, the ruling's two carriers in #369, same program (2 sites), against a base built before #367: file 58232 B → site-before-code 62432, symbol-borne (`objcopy --redefine-sym`) 58256 (+24); stripped 48192 → 52288 and 48192 — the site's bytes are in the code's segment and its 80 B took that segment over a 4096 B page here; a task body's instructions identical (69 = 69, operands masked); `avra_task_spawn` 245 → 242 instructions (the trace's two lines are one cold call); `make footprint` unchanged (22848, 35200). COMPUTED: a site costs 16 B + its text's padded room (40 B each here) against the text + 1 in a symbol table (22 B each, gone when stripped); the rest of the +616 B of text is the runtime's cold trace functions since that base, which the symbol figure does not carry. Tens of bytes a site either way, so by the ruling the site is DATA: a stripped binary still answers (MEASURED: the stripped binary's trace names both lines), a symbol does not.
- NOT a site: a body a template copied from another file (its offsets are that file's) says its address.
## Step 3 — `avra tasks <pid>`: the door
| option | what an operator types | cost when unused | verdict |
|---|---|---|---|
| A. a signal asks, the scheduler answers at its next slow switch, into a file | `avra tasks 4242` | 0 instructions on any leaf; 1 `sigaction` at the first spawn; no thread, no descriptor | **recommended** |
| B. a debug socket a task serves | `avra tasks 4242` (connects to `/tmp/avra.4242.sock`) | a listener, a filed waiter and a path for every program that spawns, asked or not | refused |
| C. read the process's memory from outside | `sudo avra tasks 4242` | 0 | refused as the door: root or an entitlement on macOS, `ptrace_scope` on Linux, torn reads, needs symbols. It is the only one that sees a task that never switches |
| D. a table the runtime keeps current in shared memory | `avra tasks 4242` | a store at every park and wake | refused |
**A, in full.**
- THE SIGNAL IS `SIGURG`: its default is to be IGNORED on Linux and macOS, so `avra tasks` aimed at a process that is not ours, or one that never spawned, harms nothing (`SIGUSR1` and `SIGQUIT` would kill it). The runtime never sets `F_SETOWN`, so the kernel sends none of its own. A stray one is still harmless: THE ASK IS A FILE, `$TMPDIR/avra-tasks.<pid>.ask`, made by the CLI before it signals; no file owned by our user, no dump.
- IN THE HANDLER, and nothing else: store 1 to a `volatile sig_atomic_t` and store 0 to `g_until_poll`. The second store is why no leaf grows: the fast switch already decrements and tests that word, so the next switch falls to `next_with_world`, which reads the flag (out of line) and dumps. A store lost inside arm64's three-instruction decrement costs nothing but time — the CLI signals again every 100 ms. A process asleep in the poller is woken by the signal itself (`EINTR`, f:760).
- AT THE NEXT SWITCH (deferred): walk `g_all`; format; write `avra-tasks.<pid>.tmp` (`O_EXCL | O_NOFOLLOW`, 0600) and rename it; the CLI waits for the name, prints, removes both. One line a task: `id site state waits-on age`. Waits-on is read from the set (`held`, `more`, `due`): `fd:r:N`, `time:+<ms>`, `gate:0x…`, `task:N` (a join), `deadline:+<ms>`. Sites resolve as in step 2; the dump carries the same `image` line.
- A TASK THAT NEVER SWITCHES cannot be listed safely by a cooperative scheduler. On the SECOND signal with the first unserved, the handler itself writes one line — `running id=<n> has not switched` — with `open`/`write`/`rename` only. The CLI prints it after 2 s and says what it means.
- AGE costs a clock read a spawn (ESTIMATE 20–30 ns on a 239 ns spawn). PROPOSED instead: a spawn copies the scheduler's last clock reading (one load, one store), and the dump says "at most". MEASURES `spawn_one` before and after; if it moves, age is stamped only once a first dump has been asked.
- THE WALK-AND-WRITE IS A PLAIN FUNCTION (`tasks_listed(fd)`), the signal only one door to it: a target with no signals (`docs/2026_10_06_NO_OS_FOOTPRINT.md`) calls the same function from its own door. RULED: age is said as "at most"; no stamp on the spawn path unless measured free.
- An evaluated program (`avra run`) is listed too: its tasks are virtual fibers on `g_all`, and `avra_vtask_next` reaches the same slow path.
- Gates: frame proof and instruction diff of the yield, park, slot, id and gate-claim leaves, byte for byte, both architectures; `make footprint` unchanged; mutations for the flag, the ask file and the rename. Witness: a std-http server under load, listed, compiled and evaluated.
- NOT HERE: cores (each process is its own pid; the parent's dump names no child); a dump under a seeded schedule draws nothing, so replay is unchanged — tested.
## Step 4 — the wait graph (as built, PR `flow-g4c`)
`avra trace <trace> --graph [--at <ms>]`: at that instant (default the trace's end), every live task and what it waits on — a task (from `join`; "a task nothing runs" for a fiberless one), a descriptor and its direction, a time, a gate named with the last task whose claim came through it — then every ring of joins, once, from its smallest task. Ended tasks wait on nothing; a task alive and waiting on nothing is "ready or running". The graph is built from a table of waits (`waits_at`), so step 3's dump prints through the same `graph`. G2's report is this text.
## Risks
1. Step 3 is scheduler C: one flag read in `next_with_world`, one handler, one `sigaction`. 2. A program that installs its own `SIGURG` handler takes the door away (it is told nothing; the CLI times out by name). 3. Symbol-borne sites change every task body's symbol: anything that greps symbols (`make footprint`, `census`) is re-run in step 2. 4. `--shape` equality is only as wide as the engines' agreement: ids agree for a program run alone (FLOW 01 §12 A8), a fiberless task's do not, so the test program joins spawned tasks only.
