# Spread `..` everywhere

Status: design, no code. One spelling, one prefix `..`, in every seat
that holds a run of things. Principles: P1 (the TypeScript habit is
correct on first generation), P3, P6, P9, P12.

## 1. The surface

| Seat | Spelling | Today |
|---|---|---|
| type declaration | `type B = { ..A, x: int }` | exists (`type.spread`) |
| record literal | `P { ..a, ..b, x: 1 }` | template holes only (`..${h}`) |
| list literal | `[..xs, y, ..zs]` | missing |
| map literal | `{ ..m, "k": v }` | missing |
| call args, list | `f(..xs)` into a variadic seat `fn f(..rest: List<T>)` | template params only |
| call args, record | `f(..opts)` fills NAMED seats by field name | missing |
| list pattern | `[first, ..rest]`, `[..init, last]`, `[a, ..]` | missing |
| record pattern | `P { x, .. }` (discard only) | missing |

Destructuring: struct destructuring in `let` does not parse ("The
subset today"). Patterns land in `match` arms and `if … is` first; `let`
destructuring is its own ask (ROADMAP sugar backlog: `let P { x, y } = p`).

Not spreadable: ranges (`..(0..3)` is no list; write `[..(0..3).map(it)]`
or a comprehension), a fixed-arity call (`f(..xs)` into `fn f(a, b)` is
refused: length is a runtime fact, a seat is a compile-time one — P9).

## 2. One typing law per form

| Form | Source type | Result |
|---|---|---|
| record literal | a record whose every field is a field of the literal's type, same type | the literal's type |
| list literal | `List<T>` (T fits the element seat; nullable lists spread only after unwrap) | `List<join of elements>` as plain literals infer |
| map literal | `Map<string, V>` | `Map<string, V>`, insertion order |
| call, list | `List<T>` into `..rest: List<T>` | seat's type |
| call, record | record whose fields are named seats | each field is a named argument |

Record merge: written order, LATER WINS, as in TypeScript (P1: the
habit generates correctly). Guard rails keep it from being a trap (P9):
- the literal's type is the HEAD NAME (`P { … }`) or the want
  (`let p: P = …`); a spread never decides the type, so `P { ..a }` with
  `a: Q` is refused unless `Q`'s fields are a subset of `P`'s with equal types;
- every field of `P` must be given by some spread or explicit field;
- an explicit field fully shadowed by a LATER spread is a warning (dead write);
- an explicit field repeated is refused (as today, F2010).
Map: later key wins and keeps the first key's place (the map's own law).
List: no merge; order is written order. Spread evaluates its source ONCE,
left to right with the other elements.
`..null`/nullable sources: refused, unwrap first (`..(m ?? {})`), matching `??`.

## 3. P6: spread, `with`, `concat` are one thing

- `a with { x: 1 }` IS `T { ..a, x: 1 }` where `T` is `a`'s type. `with`
  keeps its spelling because it names no type and chains
  (`user.address with { city: "NYC" }`, `users.map(it with { … })`), but it
  is DEFINED as that rewrite: one typing law, one lowering, one set of
  voices. What dies: `with`'s own record rules and voices (they become the
  spread's), and the spec's `list with { 3: v }` / `map with { "k": v }`
  forms (spec 11.x) — replaced by `[..xs]`-based edits and `{ ..m, "k": v }`.
  Recommendation: keep `with` as sugar, never as a second mechanism.
- `xs.concat(ys)` stays a METHOD (chains, pipes) and lowers to the same
  list build as `[..xs, ..ys]`. What dies: the head-plus-tail PUSH
  spelling and `[a].concat(b)` / `.concat([x])` as idiom sites (rule
  `style.concat_literal`, new, ratcheted); `flatten([[..]])` of literal
  lists. `concat` is not retired: it is the point-free form.

## 4. Grammar

`..` is one token already. Position decides, no lookahead:

| Position | Reading |
|---|---|
| start of an element/argument/field/pattern slot (after `[`, `(`, `{`, `,`) | PREFIX spread `..x` |
| after a complete expression | INFIX range `a..b` |
| comprehension `src ..hi` | infix (follows an expression) |

A range as a bare element needs parentheses: `[(0..3), 7]`. A prefix `..`
is never a prefix range anywhere else, so nothing existing re-reads. The
spread operand is a postfix-level expression (`..a.b`, `..f(x)`), so
`..a..b` is a refusal at the second `..`, never a range of a spread.
Trailing comma: every list the spread joins already takes one; `..xs,` is
legal and a lone `[..xs]` is the copy. Grammar authoring law: the new
branch shares `[`/`{`/`(` with existing ones only after the opener, so no
first-set clash; `make bootstrap` order per CLAUDE.md for a syntax change.

## 5. Lowering and performance

| Form | Lowering | IR |
|---|---|---|
| list | sum lengths, ONE pre-sized allocation, bulk-copy each spread (retain per managed element), plain elements stored | existing `CallRt` rows (`array_sized`, a copy-into row) — registry row at most, no `Ins` |
| record | field copies from the source (retain managed), explicit fields stored; the unique-reference in-place form of `with` (spec 9.23) is the same path | existing field ops |
| map | `CallRt` insert per key, later wins | existing rows |
| call, list | the variadic seat is a `List`; `f(..xs)` with nothing else passes `xs` (borrow, no copy) | none |
| flat one-scalar record | the value is its field; a spread is identity | none |

No IR growth: if a row is missing it is a runtime-registry row (data), per
the vocabulary seam rule. Witness: eval == native, plus a census showing
one allocation for `[..xs, ..ys]`.

## 6. Refusals (named voices, help each; all in a voices tail)

| Kind | Says | Help |
|---|---|---|
| `type.spread` (exists) | type decl spreads itself / cycle / non-record | unchanged |
| `type.spread_value` | `..x` spreads `T`, which is no record/list/map | name the form that takes it |
| `type.spread_field` | `..a` carries `y`, which `P` lacks | spread a `P`, or drop the field by building `P` |
| `type.spread_missing` | `P { ..a, … }` leaves `z` unset | add `z: …` or spread a record that has it |
| `type.spread_twice` | field `x` written twice | keep one |
| `type.spread_dead` (warning) | `x: 1` is overwritten by `..b` | move `x` after the spread |
| `type.spread_seat` | `f(..xs)` into fixed seats | declare `..rest: List<T>` or index |
| `type.spread_nullable` | `..m` is `T?` | `..(m ?? {})` / unwrap |
| `pattern.rest` | rest not last-in-run / twice | one `..` per list pattern |

Each help names a form that parses where spoken (the help-is-a-claim law);
a keeper compiles each.

## 7. Slices (each small, witnessed, eval == native, program test)

1. Record literal spread over a named type, `P { ..a, x: 1 }`; voices
   `spread_value/field/missing/twice/dead`. Rewrite `with` to this
   internally (delete its separate law).
2. List literal spread, one allocation; census witness. Rule
   `style.concat_literal`; baseline accepts existing sites.
3. Map literal spread.
4. List patterns `[first, ..rest]` in `match`/`is`; record `P { x, .. }`.
5. Variadic seat `..rest: List<T>` and `f(..xs)`; then record-into-named.
6. Sweep: `.concat([` and `[..].concat(` sites become spreads, `make
   idioms-accept` prunes.

Sweep size (grep of `packages/**/*.av`): `.concat(` 1557 lines, of
which `.concat([` 614 and `[…].concat(` 180 become spreads; 86 lines
chain two `.concat`; ` with {` 851 stay (now one law); `flatten(` 417
mostly untouched (it flattens computed lists, not literals).

Template holes keep `..${h}` / `${..xs}`: the same token in the same
seat, now typed by the same law once the hole is a value.

## 8. Open questions

1. Later-wins vs refusing overlaps. Recommend later wins plus the dead
   write warning: TypeScript habit, P1 first-generation correctness.
2. Bare `{ ..a, x: 1 }` with no type head (TS style). Recommend NO:
   a record literal names its type; the want or head decides, so a spread
   never silently picks a type (P9). Revisit if a want-only form lands.
3. `P { x, ..rest }` binding the remainder. Recommend refuse: it needs an
   anonymous record type; `P { x, .. }` discards, `with` rebuilds.

## 10. Slice 1 as built

- A spread entry rides `Expr.StructLit` as a field named `..`
  (`features.spread_entry`) whose value is the source: every walker sees
  the source as an ordinary value, and no `Expr` variant is added.
  Written order is kept (`sorted_by` over entry offsets), which is the
  precedence.
- Grammar: `".." ( vn:HOLE | se:postfix )` in a literal's entry slot; the
  operand is a postfix expression, so `..a..b` is a parse refusal.
- Typing (`structs/check.av`): `merged_checks`. `with` keeps
  `type.with_struct` for a non-record subject and shares `written_checks`.
- Lowering (`structs/lower.av`): `P { ..a, x: 1 }` over a `P` lowers
  through `copied`, the same fn `with` uses; any other mix reads each
  slot from the last entry providing it.
- Spread in a generic record's literal is `type.spread_generic` (copy a
  generic record with `with`). Not in the doc's table; recorded here.

## 11. Slice 2 as built

- `[a, ..xs, b]`: grammar `( elems:expression | ".." se:postfix )` per
  entry. A spread element is `Expr.Named(spread_entry, operand)` (core's
  `spread_entry`, read through `store.spread_operand`): it types as its
  operand and lowers as its register, so every walker sees the operand,
  and the name keeps `[xs]` and `[..xs]` apart in the fingerprint.
- Typing reuses `collect`'s `spread_type`: one element type across the
  plain elements and the spread lists' own. Voices: `type.spread_list`
  (operand is no list), `type.spread_nullable` (shared with records).
- Lowering uses existing rows only: runs of plain elements are one box,
  each spread is its list, the parts join by `avra_array_concat`; a lone
  spread is `avra_array_slice` over the whole. `[..xs, ..ys]` is one
  allocation; `[..xs, y]` is two (the singleton and the join), exactly
  what `xs.concat([y])` costs. The doc's one-allocation form needs a
  copy-into runtime row (`avra_array_extend`): a registry row, so the
  two-landing seed ladder. Not built.
- A list of `T` does not spread into a seat of `List<T?>`: lists do not
  widen element-wise, so `[null, ..xs]` under `List<int?>` is
  `type.list_element` ("the first is `List<int?>`, this is `List<int>`").

## 12. Slice 3 as built (map spread)

- `{ ..m, "k": 1 }`: a spread entry is a `Named` key wearing `spread_entry`
  and a `null` placeholder value, so keys and values stay one entry each.
- Typing: one value type across the pairs and the spread maps
  (`type.spread_map`, `type.spread_nullable`). Lowering walks each map
  through the pipeline `Put` sink, so an overwritten key keeps its first
  place by the map's own law; no new row.

## 13. Slice 4 as built (patterns)

- `Pat.Seq { before, rest, after }` and `Pat.Fields { name, fields, args,
  open }`, owned by the lists and structs features through the pattern seam
  (`pat_semantics_of`): typing, test and binds are theirs, nested patterns
  of any owner go through the seam.
- List patterns test the length, then each element at its place, read only
  once the length agreed; `..name` binds the middle as a list, a bare `..`
  discards it. A match over lists is covered by an exact pattern for each
  length below `n` and a `..` pattern from `n`, so `[]` and `[h, ..t]`
  need no `_`.
- Record patterns name the record and look at the fields they write; a
  punned field binds its own name; without `..` every field is named
  (`type.record_pattern`). A record pattern whose fields refuse nothing
  covers its subject.
- `if xs is [h, ..t] { … }` and `if p is P { x, .. } { … }` ask the same
  patterns and bind on the taken side, like `is .V(p)`; outside an `if`
  they are `type.is_bind`.
- `let P { x, y } = p` and `let [a, ..rest] = xs else { … }` are a
  `LetPattern` node holding the rest of their block (`Builder.folded_lets`
  folds the statements after it in); the match it means is minted through
  the means door (`let_matched`) and walked in its place, so the names scope
  as an arm's do, and the printer reads the node. A refutable pattern
  without `else` is `type.let_pattern`; at a file's top level (no block) it
  is refused too. `destructure` is a grammar seam (`Grammar.with_seam`,
  declared in stmt_spine) the pattern owners contribute to, so `let`
  names no owner.
- Not built: `P { x, ..rest }` (refused by design), a `let` pattern of
  enum variants.

## 14. Slice 5 as built (variadic seat)

- `fn f(a: int, ..rest: List<T>)`: the last seat takes every argument past
  the seats before it. `Param.variadic` and `DeclFacts.variadic` (the
  seat's position, so a held file answers without a parse) carry it.
- A call judges each extra as its own seat: a plain one against `T`, a
  `..xs` one (a `Named` node wearing `spread_entry`, as in a list literal)
  against `List<T>`. `Checks.placed` does it for every call shape (a free
  fn, a method, a generic), so the seat contracts, the instantiation and
  the arity law run unchanged over the expanded seats.
- Lowering: `seated_regs` packs the extras with `listed`, the one list-
  building verb the list literal also speaks; a lone `..xs` passes `xs` as it
  stands (borrowed, no copy), and no extras is an empty list.
- Voices: `type.variadic` (not last / not a list / a name where the seat
  is positional / too few before the seat) and `type.spread_seat` (`..` into
  a fn with no such seat). A named argument is refused beside a variadic
  seat; a `mut`/`const`/`state` seat cannot be variadic (the grammar has no
  word before `..`).

## 15. Record spread into named seats: the seat-law witness list

`f(..opts)` fills the NAMED seats from a record's fields. A seat's source is
a written argument, or (spread argument, field slot) — `SeatFill`, the one
plan typing (`Checks.spread_placed`) and lowering (`spread_regs`) share. The
spread's one register is read per field, so its operand runs once. A seat a
field fills is judged in `spread_placed` itself and leaves `Placed`, as a
defaulted seat does, so the seat laws downstream see only the written
arguments. A seat typed by a type parameter is filled too: the field's type
is a `FieldPin` unified in `generic_call` as a written argument's is, so it
pins the parameter and a disagreeing argument or field is refused. Built with
these witnesses (`fns/tests/spread_named`, `spread_named_test.av`).

1. a field fills the seat of its name, and a seat no field names keeps its
   default (or is refused as an unwritten seat);
2. an explicit named argument and a field naming one seat: the later wins in
   written order, the earlier is `type.spread_dead` (the record rule);
3. two spreads naming one seat: the later wins;
4. a field the callee has no seat for: `type.spread_field`;
5. a field whose type is not the seat's: the ordinary seat mismatch, worded
   about the field;
6. the spread source evaluates once however many fields it fills;
7. a `mut` seat is never filled by a field (a field is a value, not a place):
   refused; a `state` seat likewise; a `const` seat needs a settled value, so a
   field cannot fill it; an `isolated` seat cannot be filled by a field fn;
8. a generic seat pins through the field's type, like any argument;
9. a positional argument still fills the seat at its place, and a spread after
   positional arguments fills the seats those leave;
10. a variadic seat is not a named seat: `f(..opts)` over a record never fills it;
11. a managed field is retained once by the callee as any argument is, and the
    record is not mutated (eval == native, AVRA_RC_GUARD run);
12. the consumption and receiver passes see the spread's root, not a field
    they cannot name;
13. a method's spread fills its seats beside the receiver;
14. a nullable record source is `type.spread_nullable`; a non-record source
    is `type.spread_value`.
