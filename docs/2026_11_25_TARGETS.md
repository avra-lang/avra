# TARGETS — one program, every target

**Status:** DECIDED WITH OWNER 2026-11-25 (all seven of §9: yes). Nothing here is built.
**Asked by the owner:** how an app's targets are configured, how they relate, whether threads and
components keep one surface across targets, and how the code is laid out.

## 0. The model in one table

> **A program never names its target.** The source says what the app is. The manifest says what
> it is called and where it ships. The build picks the target, and everything a target needs
> beyond that is derived or is a secret.

| Question | Answer | Exists today? |
|---|---|---|
| Where is the target chosen? | `avra build --target ios`, never an import | No: `use @std.ui.web.{mount}` vs `use @std.ui.terminal.{mount}`, one package per target (`tools/ui-board/src`, `term/`) |
| Where is the app's identity? | `avra.toml`, `[app]` | No. `[package]`, `[bin]`, `[lib]`, `[dev]`, `[link]`, `[profile.*]` exist |
| Where is what one target needs? | `avra.toml`, `[target.<name>]`, deltas only | No |
| Where are secrets and stages? | `@std/config` (docs/2026_11_24_CONFIG.md) | Decided, unbuilt |
| What is derived? | scenes, permissions, assets, fonts, the bundle's files | Partly: assets are bundled by digest |
| One scheduler surface? | Yes: tasks, channels, `state`, handlers | Yes on native and wasm |
| One component surface? | Yes: a component is a contract; a target is a table | Yes: `Prim`, `Attribute`, `Prims<V>` |

## 1. The manifest

```toml
[package]
name    = "@ui/board"
version = "0.1.0"

[app]
id      = "dev.avra.board"        # one identity for every store and loader
name    = "Board"
icon    = "assets/icon.png"       # each target cuts its own sizes
entry   = "src/main.av"           # one entry: `mount(view)`
targets = ["web", "ios", "terminal"]
server  = "server"                # the service this app speaks to; today's `[dev] server`

[target.ios]                      # only what cannot be derived
min = "17.0"

[target.web]
base = "/"
```

- **Why the manifest and not code:** the toolchain reads it before the program compiles (which
  SDK, which objects, which bundle). It stays static data, checked against known keys as today.
- **Why not split per target:** there is no `ios/` or `android/` project folder. A target's
  project (the `.app`, `Info.plist`, the page's document, an APK's manifest) is written into
  `build/`, and `avra explain bundle --target ios` prints it (P7).
- **Escape hatch (P8):** `[target.ios.plist]` takes extra keys verbatim, and a package's `[link]`
  objects are already per platform for wasm; that row becomes per platform for every target.
- **`avra build`** builds every target in `targets`. `avra run --target ios` builds, installs and
  launches that one, with `server` running beside it. `run` means one thing everywhere.

## 2. What is never written

| Fact | Derived from |
|---|---|
| Scenes and windows | the program's `app` declaration |
| The entry and its delegate shim | the platform's row |
| Permissions a store asks about | the packages the program reaches (camera, location, network) |
| A permission's reason text | written once, beside the use, as a typed setting; a use with none is refused |
| Assets, fonts, icon sizes | the bundled assets, by digest |
| URL schemes and deep links | the program's routes |
| Minimum OS, where unsaid | the platform's default |

## 3. Secrets, stages and signing

Not in the manifest, ever. A signing identity, a team id, an API address per stage are
`@std/config` values: typed, with a source and a provenance, `Secret<T>` for the first two. The
build asks the config for them; a missing one is refused naming the key and where it may come from.

## 4. How targets relate

An app is a set of deliverables that share one model and one set of typed routes.

```
            model (types, rules)            one package
                   │
        ┌──────────┼───────────┐
      view      routes       server         view: one `mount(view)`
        │          │            │
  web  ios  terminal            service     each a target of the same program
```

- A client target and the server agree by construction: both read the same route types.
- A target that cannot draw a primitive fails the BUILD of that target, naming it (the law today).
- The storyboard draws every component on every target in `targets`: that is the parity check.

## 5. Threads: one surface, one port

The surface a program writes is the same everywhere: `spawn`, `.await`, channels, `within`,
`state`, handlers. There is one scheduler. What differs per platform is two answers: what idle
does, and what wakes it. That is a port, one implementation per platform, picked at link time.

| Platform | Idle | Wake | Frame |
|---|---|---|---|
| CLI, server | block in the poller | fd, timer | none |
| Web | return to the event loop (exists: hosted idle) | event, timer, fetch | `requestAnimationFrame` |
| iOS, macOS | return to the run loop (the spike's option A) | run-loop source, fd, timer | display link |
| Android | return to the looper | message, fd | choreographer |

A program on a UI target runs on that platform's UI thread, as fibers. Work that must leave the
UI thread is an open language question (no fork on iOS, plain refcounts); recorded, not solved here.

## 6. `mount`: one name, one implementation per platform

`use @std.ui.{mount}` and nothing else. Proposed mechanism, stated generally: **a trait whose
implementation is chosen by the build's platform.** Every platform's implementation is
type-checked on every build, so no target rots unseen. Rejected: conditional compilation, which
hides the other targets' code from the checker.

## 7. Components: a contract and a table

```avra
@prim(.Switch)
export component switch(@attr(.Label) label: string) { … }   // no target's word in it
```

- A component declares a primitive, its attributes, its events and its places.
- Views become a neutral tree: 24 primitives, typed attributes.
- A target is a total table from primitive to its own control. `Prims<V>` has a slot per
  primitive, so a missing one is a compile error.
- A composition (card, model_form) is made of primitives and costs a new target nothing.
- A new target costs 24 rows and an event table, not a rewrite of components.

| Primitive | Web | iOS (the spike decides) | Terminal |
|---|---|---|---|
| button | `<button>` | `UIButton` | a focusable cell run |
| field | `<input>` | `UITextField` | an edit line |
| list | `<ul>` | `UICollectionView`, recycled by key | windowed rows |
| dialog | `<dialog>` | a sheet | an overlay |

Open: the update stream is HTML-shaped today (tags, CSS). The neutral patch as the one source,
with the web wire as a projection, is its own study after the spike, and must cost the web nothing.

## 8. Layout of the code

```
runtime/
  sched, fiber, poller           the one scheduler
  host/                          the port: one file per platform
    blocking.c  page.*  apple.c  android.c
packages/std-ui/src/
  tree/ place/ a11y/ style/      neutral: no target's word
  app/ components/ forms/        neutral
  realize/
    html/ dom/                   web
    tui/                         terminal
    uikit/                       iOS (after the spike)
  mount.av                       the one `mount`; today's web/ terminal/ headless/ fold into it
compiler/targets.av              Platform: Native | Wasm | Apple(sdk); each row names its bundle kind
```

## 9. Decided (owner, 2026-11-25: yes to each)

1. **`[app]` in `avra.toml`** for identity, `[target.<name>]` for deltas.
2. **No per-target project folders**; generated into `build/`, printable.
3. **`targets = [...]`** listed in the manifest, so `avra build` builds all.
4. **One `mount`**, by a platform-chosen trait implementation, no conditional compilation. The mechanism
   needs a compiler proposal stated generally.
5. **Permissions derived**, reasons written beside the use.
6. **Signing and stages in `@std/config`**, never the manifest.
7. **A web page's document is a bundle too**: one mechanism writes the `.app` and the page's
   document. Its design is ruled when the first-paint lane's
   server-drawn document lands.
