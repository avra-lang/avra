## 1. Today (READ and RUN)
- A cancel is recorded and answered by the next park BEFORE it switches (f:1237-1240), so a request already stands until someone clears it. A task parked by sleep, join or a descriptor park is not woken by one (f:1497-1500, f:1375, f:1519, f:1381, f:1554). `avra_task_cancel` is a row with no evaluator arm and no Avra caller (`core/runtime_api.av:1702-1707`).

RUN, both engines (p10): under `within ms(30)` a caught timeout is heard again by the next socket wait at once, a `sleep(ms(60))` after it takes its 60 ms, and an inner `within secs(5)` reports the OUTER deadline as its own — "the outer block went on to its end, true (70 ms under a 30 ms deadline)". p11: a child spawned under a `within` (it inherits the deadline, f:1352) and joined after it answers `timed out` as an ordinary value.

WHAT C ASKS OF THE COMPILER — the grammar learns nothing (`expression = l:disjunction ( "catch" … )?`, `features/expr_spine/mod.av:53`; `.await` is a property row, `features/tasks/mod.av:33`, and a paren group mints no node, so `(t.await) catch` is the same subject):
- THE TYPER: `catch` reads its subject's sides from the subject's TYPE alone (`features/results/check.av:29`). It asks ONE verb instead — a `Result`'s sides, or the FAILURE VIEW the subject's own row declares: `PropertyRow` gains that column, `await` answers `(T, Cancelled)`. The pair is never interned as a `Result`, so a task answering nothing needs no `Result<void, …>`. The results feature still matches no tasks node.
- LOWERING: the same row lowers the caught form as a join that answers how the task ended; a bare `.await` joins and, on a cancelled task, cancels the awaiter with the same asker (it unwinds; its own watcher sees it).
- `match t.await { … }` is the `T`: only `catch` sees the cancel. `t.await?` is REFUSED with its own voice — a cancel already passes through; `catch` it or drop the `?`. `let v = t.await` then `v catch …` stays refused (p12, "this is `int`"): the cancel left at the await.
- COHERENT WITH D1: one law — `catch` recovers the failure its subject can have. A `within` OWNS its deadline, so its failure is a value (`Result<T, TimedOut>`: `match`, `?` and a binding all hold it). An await's cancel is someone else's, so it is a channel that passes through by default and `catch` is the one place it lands. WHAT C CANNOT SAY: the cancel as DATA beside the answer (`List<Result<T, Cancelled>>`); the arm answers a `T`. Nothing in the tree wants it today; B′'s property is how it would be said.
- THE ARM RUNS ONLY WHEN `t` ENDED CANCELLED (review 6). The awaiter's OWN cancel or deadline arriving during the join claims the join itself and unwinds past the `catch`, exactly as it passes a `within … catch` that is not its asker: `within ms(10) { t.await catch c -> { slow() } }` over a slow `t` answers `Err(TimedOut)` and never runs the arm.
- `t.cancel()` is the verb that cancels (p08: free).

**SETTLED — "like Go", gated at 1% of server CPU a request.** One byte, `avra_tick`; the switch reads it instead of the clock, a `while` back-edge reads it, and its cold side fires due timers, checks the running task's own deadline, raises a standing cancel, and yields when others are ready.
- WHICH LOOPS: a `while` (its trip count is nobody's to know) is checked every turn — measured free at a nanosecond a turn. A `for` over a list or a range carries no check: that keeps the two loops that paid (+18–22%, ×3.5) untouched and needs no constant. STATED PLAINLY: `for i in 0..n` is NOT preempted — a billion turns at a nanosecond is a second, and longer with a body that calls — and recursion that never waits is bounded only by its stack. Ticket `.24`'s acceptance is then met for a `while` alone (a spinning `while` is cancelled by its deadline and its neighbour still runs); the ticket is amended to say so.
- TWO NAMED SETTINGS, NO LITERAL IN THE CODE (DECIDED). `AVRA_TICK_US`, default 10,000 — Go's own quantum: a spinning `while` holds its core for at most that long, and the tick is not measurable on a saturated one-core server (+0.5% / −0.7%; at 1000 it was +2.0–3.2%, D6's row, outside the gate). `AVRA_TIMER_TURNS`, default 64: while a timer is filed the switch reads the clock every that many switches, so a due timer among busy tasks is late by 64 switches or one tick, whichever is sooner, never by 10 ms of short turns. It rides the countdown the switch already makes for the poller (`FAIR_TURNS`, f:439; f:441, f:1118), so the fast path gains no instruction; ESTIMATE 0.46 ns a switch (29.4 ns ÷ 64), and `.28`'s bound is restated as that. BOTH ARE READ ONCE, in the scheduler's own constructor beside the trace flag (f:298-300), so a running program pays no `getenv`; a value that is not a whole number above zero traps by name at the first spawn, as `AVRA_FIBER_GUARDS` does.
- BEHIND THE PLATFORM SEAM (footprint door D7: no thread and no thread-local in `runtime/*.c`; `runtime/avra_platform.h` is where the runtime reads its machine). The scheduler calls two verbs, `avra_tick_armed()` and `avra_tick_stood_down()`, and reads one byte. A hosted target implements them with a thread in its own object, outside `runtime/*.c`; a no-OS target implements them over a timer interrupt that stores the same byte; wasm implements neither and has no preemption (as it has no scheduler today). The object rides the scheduler's: a program that never spawns links neither.
- ARMED BY A STORE (review 10). The scheduler stores `wanted = 1` as a task starts running with others ready or a deadline standing and `wanted = 0` as it enters its poller: one store each, no call, no syscall. The tick thread reads `wanted` each period and, after 8 periods unwanted, parks itself; only the first arming after that pays a wake. An idle process pays nothing (left armed it measured 15.8–16.4 ms a second). Re-armed in `avra_fiber_forked`: a forked child saw no tick.
- THE BYTE IS ATOMIC, RELAXED ORDER (the same instruction; a lost tick costs one period). The tick's object may call its sleep and nothing else — no allocation, no lock — or a fork in a two-thread process can inherit a held libc lock: a keeper reads the object's undefined symbols against that list, beside the keeper that holds `runtime/*.c` free of threads.

## 3. Mechanism
- RUNTIME. `unwinding` is a global byte the switch swaps beside `avra_task_local` (`runtime/avra_runtime.h:28-30`, f:1074, f:1088), set where a cancel point answers a cancel to the running task. Sleep, join and the descriptor park lose their deafness and go through `park_begun`'s order (claim, then cancel, then deadline). A joined task says how it ended (`TASK_END`, f:218).
- IR. One new value read — a byte of the runtime's — because a row call costs a call (1.6 ns against none); the tick's read is the same instruction over another byte. Everything after it is today's shapes: `IfStart`, `failing()` (`compiler/lower/walk.av:417`), `FnExit`; inside `within`'s landing, a `LoopJump` out of a one-turn loop, `defer`s run as `jumped` runs them (`walk.av:410`, `core/ir.av:173`). The test is emitted by the call verbs (`features/emit.av:126-152`) and at a checked back-edge's cold return.
- THE EVALUATOR runs the same instructions; a `Job` carries the bits.
- `at` is one frame a fn the unwind passes, pushed by that fn's single cold exit, capped at 16 (spec §9).
**3.1 The fact has two bits, and a `while` is in it (review 1).** `parks`: the fn calls a cancel-point row or calls through a value. `spins`: its body holds a checked `while`. MAY REACH = either, here or in a callee; the test follows a call to any such fn. The back-edge's cold side may therefore set the byte and return: every caller on the way tests. Counts and cost: §2 D6. IF THE GATE BREAKS: `spins` leaves the fact, and the cold side only YIELDS — a standing cancel or a passed deadline is recorded and raised at the task's next row. A spinning `while` is then fair to its neighbours and is NOT ended by its deadline; `.24` would be half met, and that is said to the owner with the numbers, not chosen here.
**3.2 `@unbroken` — "nothing runs between", held by the compiler at no cost (review 2).** The library's gates stand on one law: between a task's test and its park, or its claim and its append, no other task runs (spec §5.1; `rouse` is `while avra_gate_claim(…) >= 0 {}`). A back-edge that yields breaks it. A fn marked `@unbroken` promises the law and is held to it:
- its own `while`s carry NO check; it may call C (a runtime row or an extern — C is never preempted), a vocabulary row that does not wait, a constructor, and another `@unbroken` fn; any other call, a call through a value, a spawn and a read that waits are REFUSED (`flow.broken`, `compiler/typing/unbroken.av`). THE LAW IS LOCAL (lead's ruling): a pure helper an `@unbroken` fn calls is marked too, and the refusal names the helper to mark — sound with no other body typed first, and only library authors write the mark. THE FACT-BASED ALTERNATIVE (accept any callee the cancel fact says reaches nothing) needs every other body typed before this one is judged; its TRIGGER is marking spreading past a handful of helpers per package
- so the region is STATIC. No depth in the task, nothing for the cold side to honour, no entry or exit: ZERO instructions inside and outside one. THE PROOF IS THE DIFF: an `@unbroken` fn's code is byte for byte what main emits today (in `aftercall_ir`'s `go` build a fn not holding a checked `while` is untouched), and the step that lands it gates on that disassembly.
- a claimed taker's fn is `@unbroken` from its park's return to its `take`, so no cancel is raised between the two (trap 2).
- THE ALTERNATIVE, not chosen: a depth in the task raised by a row pair and read on the cold side — two instructions at every region's entry and exit, and a cold side that must remember what it owed.
```avra
@unbroken
fn rouse() { while avra_gate_claim(self.gate) >= 0 {} }
```
**THE WORD IS `@unbroken` (DECIDED; over `@atomic`, which suggests shared memory, and `@no_yield`, which names the mechanism).** p16: an annotation over a fn parses today and is refused only as a name — "`unbroken` is not defined".
**3.3 A `defer` runs whole under a shield, and waits only for as long as it says (review 3).** The cold exit brackets a frame's deferred calls with a row pair: the first saves and clears the byte and marks the task SHIELDED, the second sets the byte again. Shielded, a call that may reach is no longer followed by a taken test, so a two-call `defer` runs both; a WAIT answers the standing cancel at once (f:1240), which unwinds that `defer`'s own frames back to the bracket — it is cut at its first wait, not its first call. A `within` opened while shielded is a SHIELD SCOPE: waits under it answer only its own limit, so cleanup that waits is bounded by the time it wrote (law 10). A checked back-edge in a shielded task yields and raises nothing. `flow.unbounded_cleanup` REFUSES a `defer` or `errdefer` whose body `parks` outside a `within` written in that body; of the 14 `defer`s in package source today none waits (READ), so it fires on nothing that stands. Cost: two row calls on the cold exit of a frame that has entries; none elsewhere.
**3.4 Every scope keeps its OWN limit (review 4).** A `within` pushes a record on its task — `{ id, at, outer, shield }`, `id` process-unique because a child carries its spawner's — where today one minimum is kept (f:743-748). The task's deadline is the earliest `at`; its OWNER is the scope that holds it, the OUTER one on a tie. A firing sets `cancel_by` to the owner's id; only the landing with that id ends it and answers `TimedOut { after: its own limit }`; every other landing is passed. A spawned task starts with one record copied from its spawner's owner, so an inherited deadline unwinds the child to its top (no landing of the child's has that id) while the child's own later `within` is passed. One heap entry, as today.
**3.5 An interrupt is not a deadline (review 5).** `avra_fiber_fd_interrupt` claims a parked reader AS the deadline today (f:1541-1549, `-1:1`), which is how a server's stop wakes its connections (`std-http/src/server.av:277`). It gets its own claim (`-1:2`) and the parking verb answers its own ordinary error, `e.interrupted()` — a VALUE of the verb, not a cancel: nothing unwinds, no `within` lands, the socket stays open and the next read is whole (`std-net/src/tests/parked_interrupt`). Drain's readers (`server.av:441`, `:583`, `:932`) tell a stop from an idle timeout by it.
**3.6 Two requests (review 7).** One request stands. A task-level cancel (`t.cancel()`, an owner leaving) outranks any scope; among scopes the OUTER outranks the inner. A new request replaces the standing one only when it outranks it; otherwise it is dropped, because the standing unwind already passes that scope's landing. Each request, kept or dropped, is a line of the flow trace. HOW A TASK ENDED IS DATA ON ITS RECORD — `TASK_END`, who asked, the frames — read by a row, `avra_task_ended`: that is what a failing block lists its cancelled children from and what `main`'s report prints. WHEN `main` IS CANCELLED (DECIDED) (a bare `t.await` of a cancelled task, passed up to the top): its `defer`s run, stderr says ONE line, `avra: main was cancelled — awaiting a task cancelled by <who> at <site>`, and the process exits 1 — a verdict; 2 stays a trap's.
**3.7 The fact rides the signature fingerprint (review 8).** `parks` and `spins` are part of a declaration's signature fingerprint, beside its seat marks, so a held interface covers them and a callee that starts to wait is a changed signature to every caller. The cache attack: edit a callee to wait, rebuild its caller warm, the test stands after the call.
**3.8 Under slice 02's seed the tick is a DRAW, never wall time (review 9).** Seeded (`avra_sched_seed`, flow-02 §1, §4), the seam's verbs do nothing and no thread exists. The byte is held SET, so every checked back-edge takes its cold side; there a per-task count of turns falls, and at zero the task yields and a new count is DRAWN from the schedule's stream — one counted choice, like a pick. Schedule 0 draws "never": no choice, FIFO, as flow-02 §2 promises. The production fast path is the same two instructions. The deadline is read from the one clock (flow-02 §5), so, frozen, a task that only computes never passes its deadline — flow-02's stated limit; `.24`'s test runs under `AVRA_CLOCK=real`. The evaluator's machine counts the same turns at its loop's end, so both engines draw alike.
**3.9 A block that answers nothing (review 14).** NONE of the 80 sites has one (READ: 75 are bound, matched or passed; 5 stand as a fn's answering tail — `std-tls/src/tls.av:363`, `std-http/src/body.av:322`, `:328`, `quota.av:133`, `flow_bench/avra/switch/src/main.av:31`). So `Result<void, E>` is not on this slice's path: `within` over a void block is refused by name ("answer what the block did"), and the general type lands when something needs it. ## 6. Risks
1. "A call through a register may reach anything" multiplies the fact by 3.4 on the server and by 95 on the compiler; a fn TYPE that says it waits is the remedy, and is not designed here. 2. A block answering nothing cannot be a `Result` side (`features/results/check.av:286`): `within d { sleep(x) }` is refused by name; no site has one today (§3.9). 3. A `catch` arm does not hear the ok side's type, so the migration's fold needs a named fn (p03). 4. The tick makes a hosted process that spawns two threads; a fork must re-arm it; a long `for` that never waits is not preempted (D5). 5. The server numbers sit inside a ±4% spread; the published row needs more rounds or a quieter machine. 6. Where `Cancelled` and `TimedOut` live is not settled (`Frame` is `@std/errors`', `Duration` is `@std/time`'s). 7. Under C the same `.await` joins two ways by where it stands; a helper fn that awaits hides the cancel from its caller's `catch` — the cancel passes through the helper and the caller alike, by design, and the refusal for `v catch` says where to catch. 8. `@unbroken` spreads to whatever a marked fn calls in Avra; if that set grows past the gates' own verbs the depth alternative (§3.2) is the way back. 9. The `go` build tests every back-edge of a fn holding a `while`, a `for`'s too, and charges a `while` in a lambda to the fn around it: its counts are an upper bound by a source scan, not the compiler's fact.
