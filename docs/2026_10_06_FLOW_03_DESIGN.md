# FLOW 03 — cancel, `within` → `TimedOut`, preemption: design note (v1, DESIGN AND PROBES ONLY)
Tickets `avra-8sb5.34.53.3`, `.24`, `.28`; base `0d261da`. Nothing here is built. `f:` is `runtime/avra_fiber.c`. Every number is MEASURED on the lane's Sprite (Linux 6.12.105-fly x86_64, 8 cpus, clang 22.1.2) by a script in `tools/flow_bench/probes/{cancel,preempt,aftercall_ir}/`, or marked ESTIMATE. A probe is a package checked OUTSIDE the tree (`cancel/run.sh`); pNN names its file.
## 1. Today (READ and RUN)
- A cancel is recorded and answered by the next park BEFORE it switches (f:1237-1240), so a request already stands until someone clears it. A task parked by sleep, join or a descriptor park is not woken by one (f:1497-1500, f:1375, f:1519, f:1381, f:1554). `avra_task_cancel` is a row with no evaluator arm and no Avra caller (`core/runtime_api.av:1702-1707`).
- `within` is a library component that answers its block as written (`std-time/src/time.av:58-74`); a deadline reaches code only as each waiting verb's own error (`std-net/src/net.av:226`, `:274`). RUN, both engines (p10): under `within ms(30)` a caught timeout is heard again by the next socket wait at once, a `sleep(ms(60))` after it takes its 60 ms, and an inner `within secs(5)` reports the OUTER deadline as its own — "the outer block went on to its end, true (70 ms under a 30 ms deadline)". p11: a child spawned under a `within` (it inherits the deadline, f:1352) and joined after it answers `timed out` as an ordinary value.
- A `return` and a `?` inside the block leave through it today (`std-time/src/tests/within/within.av:6-27`); `std-tls/src/tls.av:363-366` depends on the `?`.

About 70 wrap a verb that already answers a `Result` (READ, not typed).

**D2 — what a join of a cancelled task answers.** 96 `.await` lines tree-wide (15 source, 81 tests).

|---|---|---|---|

Under B, `.await` on a cancelled task has no `T` to give. B1: it traps (the whole process, decision 1). **B2 (recommended): the awaiter is cancelled by the same asker** — it unwinds, its `defer`s run, and its own watcher sees `Err(Cancelled)` with one more frame. A server loses one connection's task, not the process.
**D3 — what re-raises after a catch.** The program: an outer `within ms(10)` whose block is `let x = within secs(5) { sleep(secs(1))`⏎`1 } catch _ -> { println("inner")`⏎`2 }`, then `println("x ${x}")`, `sleep(ms(1))`, `println("slept")`. The outer deadline fires in the first sleep.
| rule | prints | the block answers | |
|---|---|---|---|
| R1. Only the scope that asked ends a cancel; any other `within … catch` on the way is passed untouched | nothing | `Err(TimedOut)` at 10 ms | RECOMMENDED (spec §5.4) |
| R2. Every catch on the way sees it; it is raised again at the next cancel point | `inner`, `x 2` | `Err(TimedOut)` at 10 ms; the inner arm was told five seconds ran out | no |

WHERE A CANCEL IS SEEN AND NOT OWNED (D4's block, or a joiner that is itself under the asker), THE REQUEST STANDS: nothing clears `cancel_by` but its asker's scope ending, so the next cancel point raises it again — the park already answers so (f:1240). D5 is what bounds "next" in time.
**D4 — is `cancellable { }` needed.** No user program was found that needs it: cleanup is `defer`; "who cancelled me, and where" is the watcher's `t.joined`; a different goodbye on cancel is the spawner matching `.joined`, at the price of one task (177 ns, slice 01's MEASURED spawn + join). ONE PROGRAM DOES NEED A LANDING INSIDE A FN: `within` itself. Its block must stay inline (§1's `return` and `?`); as a lambda it is refused twice (p06: "a `return` answers a fn, and there is none enclosing"; "`?` passes the failure to a caller, and a lambda promises none"). So the compiler learns one block form either way:
| option | what is added | |
|---|---|---|
| (i) the word `cancellable { body }`, answering `Result<T, Cancelled>`, in the tasks feature; `within` stays a library component written over it | one expression. p09: `cancellable { … }` parses today as a call with a trailing block ("no `fn cancellable` is defined"), so the word merges ahead of `fns` | RECOMMENDED: visible, and `select`'s arms get the same landing |
| (ii) no word: `within` moves into the tasks feature's grammar | `within` leaves `@std/time`; nothing else can land a cancel | the owner's stated preference; it costs the library its one deadline |
**D5 — G3 preemption** (`preempt/run.sh`; ns a turn, least of five, two rounds, plain → checked).
| piece | measured | |
|---|---|---|
| (a) one load-and-branch on every loop back-edge | byte hash 1.24–1.26 → 1.24–1.27; collatz `while` 1.25–1.27 → 1.26–1.28; list walk 1.27 → 1.26–1.27. A 64-turn inner product 0.73 → 0.86–0.89 (+18–22%); a vectorized sum 0.142 → 0.49–0.55 (×3.5: the vector loop is gone). A counter in a register, or the loop reading the clock itself every 1024th turn, is no cheaper (sum 0.54–0.59). A COUNTED loop checked once per 1024 turns: sum 0.19, inner product 0.71–0.73. On Avra's own code (`aftercall_ir`, the bench server's IR, 665 back-edges): text +1.4%, server CPU a request −0.4% / +1.1% against a ±4% spread | build it: every `while` back-edge; a counted `for` once per 1024 turns |
| (b) a 1 ms tick that sets one byte | by a THREAD: its own CPU 15.0–15.6 ms a second (1.5% of one core) while armed, the worker's turns unchanged (799–807 → 802–806 M/s), longest gap 1.7–4.4 ms. By a SIGNAL: the worker −0.3 to −2.1%, and an idle process's poller is broken in on 1000 times a second (EINTR), 19 ms CPU a second. Left armed while idle the thread costs 15.8–16.4 ms a second. A forked child sees no tick from either. The switch's "is anything due": 29.3–29.6 ns by clock (today, f:1100) → 1.6 ns by byte, `cmpb $0x0, g_tick(%rip)`; `jne` | build it: a thread, armed only while a task runs with others ready or a deadline standing, re-armed in `avra_fiber_forked` |
| (c) a lint for a loop with no wait point in a task | by-name census (ESTIMATE): 37 of std-http's 87 loops and 13 of its 51 `while`s reach no cancel point, and all are bounded parsers | not as the remedy: it would fire on correct code (the F2040 lesson) |
**RECOMMENDED: (a) + (b), one byte.** The tick is `.28`'s flag: the switch reads it instead of the clock, the back-edge reads it, and its cold side fires due timers, checks the running task's own deadline, raises a standing cancel, and yields when others are ready.

**WHERE THE FACT LIVES (proposed):** a per-fn summary read from the RESOLVED body — calls a cancel-point row, calls these declarations, calls through a value — and a whole-program fixpoint over the summaries, asked through the declaration table's hook and remembered by the kernel: the seats pass's exact shape (`compiler/receivers.av:1-10`). A cancel point is a COLUMN of `rt_sigs` (data, a registry row). A program that links no scheduler has no such row and emits no test.
## 3. Mechanism
- RUNTIME. `unwinding` becomes a global byte the switch swaps beside `avra_task_local` (`runtime/avra_runtime.h:28-30`, f:1074, f:1088), set where a park answers −1 to the running task. Sleep, join and the descriptor park lose their deafness and go through `park_begun`'s order (claim, then cancel, then deadline). A `within` gets an id; `cancel_by` names a scope or a task. A joined task says how it ended (`TASK_END`, f:218).
- IR. One new value read — the byte — because a row call costs a call (1.6 ns against none); it is the tick's read too. Everything after it is today's shapes: `IfStart`, `failing()` (`compiler/lower/walk.av:417`), `FnExit`; inside a landing, a `LoopJump` out of a one-turn loop, `defer`s run as `jumped` runs them (`walk.av:410`, `core/ir.av:173`). The test is emitted by the call verbs alone (`features/emit.av:126-152`).
- THE EVALUATOR runs the same instructions; a `Job` carries the two bits.
- `at` is one frame a fn the unwind passes, pushed by that fn's single cold exit, capped at 16 (spec §9).
## 4. The PR ladder (after slice 02; each leaves main green; runtime rows take the three rungs)
1. runtime: sleep, join and the descriptor park hear a cancel and a deadline; `unwinding` set at a cancel point; scope ids; how a task ended. C tests and mutations only.
2. runtime: the tick thread and the byte; the switch reads it (`.28`: frame proof, `yield_under_within` within 1 ns of the bare yield, `timers_among_bursts`).
3. rows' evaluator arms and declarations (rungs 2 and 3).
4. IR: the byte read, every consumer paid (`avra new ins`), goldens; nothing emits it.
5. the may-reach fact and the `rt_sigs` column, with its tests and an `explain` line; nothing reads it.
6. lowering: the test after a call that may reach; `flow.callback_pointer` and `make externs` listing fn seats. Compile time and requests a second published against §2's BEFORE.
7. the landing: `cancellable { }` (or D4 (ii)); a grammar change — save `build/avra.pre`, build twice, seed refresh.
8. `t.cancel()`, `t.joined`, the `Cancelled` record; the cancel-tree bench twin beside Go's row (936 / 433 ns a task, G1).
9. `within` answers `Result<T, TimedOut>`: the component rewritten and all 80 sites migrated in ONE change (the type flips at once; about 2 lines a site).
10. G3 after the owner's word: the back-edge check, with its own bench row (a spinning task under a deadline, and its neighbour's latency).
## 5. Tests — one per observer row of spec §5.4, each failing first, eval == native
1. the cancelled task: its `defer`s and `errdefer`s run, nothing after its cancel point does. 2. opting in: the arm runs, the next cancel point unwinds. 3. `within`: `Err(TimedOut { after, at })` over a sleep, a join and a socket read, each; an inner `within … catch` does not see an outer deadline (D3's program, R1's output). 4. a joiner: `t.joined` is `Err(Cancelled { by, at })`; `t.await` cancels the awaiter (B2). 5–7, named here and owed where their subject lands: a stream's `.ended` (slice 5), a failing block listing the children it cancelled (slice 5), a queue's redelivery (slice 7). 8. the operator's listing is `.25`. Beside them: a claim made before a cancel is taken first (trap 2); a spinning task is cancelled by its deadline and a second task still runs (`.24`).
## 6. Risks
1. "A call through a register may reach anything" multiplies the fact by 3.4 on the server and by 95 on the compiler; a fn TYPE that says it waits is the remedy, and is not designed here. 2. A block answering nothing cannot be a `Result` side yet (`features/results/check.av:286`): `within d { sleep(x) }` is refused until that lands, and says so. 3. A `catch` arm does not hear the ok side's type, so the migration's fold needs a named fn (p03). 4. The tick makes every process two threads; a fork must re-arm it. 5. The server numbers sit inside a ±4% spread; the published row needs more rounds or a quieter machine. 6. Where `Cancelled` and `TimedOut` live is not settled (`Frame` is `@std/errors`', `Duration` is `@std/time`'s).
