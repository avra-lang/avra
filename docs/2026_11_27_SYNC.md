# Sync — the proposal

Status: PROPOSAL, for the UI lead's ruling (§9). Nothing here is built. It answers the owner
decision "sync is first class" (docs/2026_11_16_UI.md, Direction): state is designed with local,
remote and peer-to-peer data on the table from the start, an app is written barely thinking about
syncing, presence falls out, and where a rule cannot survive a merge the design says what
arbitrates. Probes are quoted with their base (`program` at 13c2fd4, Linux x86-64, Xeon 2.1 GHz).

## 1. The author's view

A synced place is an ordinary `state` whose declaration says WHO ELSE holds it. Reads and writes
are unchanged: `todos[i].title = x` is the whole write. The type is a plain record with the
`@relation` vocabulary it already has (`id` minted by the store, `@unique`, `@local`).

```avra
@sync
type Todo = { id: int = 0, title: string, done: bool = false, @local open: bool = false }

state todos: List<Todo> = [] at .account          // my devices; the server keeps a copy

component todo_row(state t: Todo) {
    row {
        checkbox { checked: self.t.done }          // a register write
        field "Title" { value: self.t.title }      // a text edit: merges by character
        button "Remove" { on press { todos.remove(self.t) } }
    }
}

fn page() -> column {
    column {
        button "Add" { on press { todos.push(Todo { title: "" }) } }   // the id is minted here, offline too
        list todos by it.id { t -> todo_row { t: t } }
    }
}
```

The shared board is the same program with a wider replica set and one arbitrated field:

```avra
@sync
type Card = { id: int = 0, title: string, done: bool = false, votes: int = 0, @unique slug: string }

state cards: List<Card> = [] at .shared(board)    // everyone who can read `board`
state cursor: Point? = null at .room(board)       // presence: lossy, expiring, never stored

// in card_row(state c: Card):
button "+1" { on press { self.c.votes = self.c.votes + 1 } }  // a counter: two +1s make +2
```

A chat is an append-mostly list:

```avra
@sync
type Message = { id: int = 0, author: Principal = me(), text: string, at: Time = now() }

state messages: List<Message> = [] at .shared(room)
state typing: bool = false at .room(room)
fn who_is_here() -> List<Principal> { present(room).map(it.principal) }
```

The element `t` of a synced list is a PLACE, addressed by its id: that is the answer to the UI
doc's open question of "a place through a `state` list of plain records (`todos[i].title`)".

What the author no longer writes, measured against today's board (tools/ui-board/src/board.av):
the three `Fetch` states, `send(…, foresee: Overlay.Patch(…))` per write, `named(t)` and "id 0
until the server answers", `tasks_written`/`todos_of`, and the `@crud` doors on the page. The
server keeps `Todo.routes` for non-sync clients; sync is a second door over the same table (§6).

## 2. The model

**A document is a map of records; a record is a map of fields; each field is a CRDT chosen by its
type and by how the program writes it.** The compiler sees every write (P10), so the op is derived,
never spelled. `avra explain Card` prints the choice per field (P7); a mark overrides it (P8).

| Field | Merge | Chosen when | Op on the wire |
|---|---|---|---|
| `bool`, enum, `int`, record, `T?` | LWW register, stamp `(lamport, replica)` | default | `set(rec, field, stamp, value)` |
| `int` written only as `x = x ± e` | PN counter | every write in the program has that shape | `add(rec, field, stamp, delta)` |
| `string` | register; a **text sequence** when a text control or `@text` writes it | the writer is `field`/`@text` | `ins(after_id, chars)` / `del(id, n)` |
| `List<T>` of `@sync` records | **sequence** of record ids (one algorithm with text) + map id → record | always | `ins(after_id, rec)` / `del(rec)` |
| `List<T>` of scalars | sequence | always | as text |
| `Map<string, V>` | map of V's CRDT, add-wins keys | always | per key |
| `@unique`, `@check` field | **arbitrated** (§3) | the mark | `ask(rec, field, value)` |
| `@local` field | not synced | the mark | none |

- **Why assignment is enough** (SHARING_MODEL §4.5 break 2: `x = x + 1` vs `x = x + 2` under LWW).
  The compiler proves a counter from the program's writes; a program that also writes `x = 5`
  keeps a register, and `explain` says why. A `string` assigned whole by code is a register (a
  status word must never merge as `"doneactive"`); typed text is a sequence, and a whole
  assignment to it is diffed into `ins`/`del` against the value it read.
- **Identity.** Every synced record's `id` is minted where it is created: 32 bits of replica, 32
  of counter, so an offline insert has its final id at once. The server's row id becomes this id.
  Items of a list are ordered by the sequence, never by index: `todos[i]` resolves `i` to an id at
  the write, so a concurrent insert above cannot redirect it.
- **Ordering.** One sequence algorithm (Fugue-style, item = `(id, origin_left, origin_right)`,
  which does not interleave two concurrent runs) for text and lists. Fractional position keys
  were probed and refused: key length grows linearly under adversarial insertion (§8).
- **Deletes.** A removed record leaves a tombstone of `(id, stamp)`, 24 B held and about 10 on the wire, and drops its
  field registers at once. A deleted sequence item keeps its id (it anchors neighbours) and drops
  its content.
- **Garbage collection.** A tombstone is dropped once the authority's frontier is past it: every
  replica that has synced in the last 30 days (a setting) has acknowledged its stamp. A replica
  away longer resyncs from a snapshot; the feed already has the word for it (`cursor-expired`,
  std-ui feeds.av). Peer-only documents with no authority GC only by a full-replica agreement and
  say so in `explain`.
- **Offline, then rejoin.** Every local write is applied at once and appended to the outbox. On
  reconnect a replica sends its ops since the server's last acknowledgement and receives the
  server's since its own cursor (one integer, the server's sequence). Merge is commutative and
  idempotent, so order and duplicates do not matter; an op carries its stamp, which is its
  idempotency key (AUTONOMOUS_SYSTEMS §0).

## 3. Optimistic and confirmed

Two kinds of write, and the type says which (the mark is on the field, so the line is visible):

- **Converging writes** (everything but §2's arbitrated row). The local value IS a valid final
  state: it never rolls back. "Confirmed" means the op reached the authority's log. A view shows
  the local value; `pending(t.title)` is a `bool` read a view may show (a dot, a dimmed field). A
  concurrent register write that loses is replaced by the winner on the next paint; the lost
  value is kept for one turn as `lost(t.title)` for an app that wants to say so. Default: no
  indicator, as Linear and Figma do.
- **Arbitrated writes** (`@unique`, `@check`, an `@owner`-guarded delete, a balance that stays
  positive). Shown at once, held as a layer (today's `Overlay` mechanism, std-ui cache.av), sent
  to the authority as an ask. Accepted: the layer becomes the value. Refused: the layer is dropped,
  the view reverts, and the refusal is the write's own `Failed` (as std-ui's write lanes do
  today). `shown: T?` (UI doc, ruling of 2026-11-18) becomes the optimistic value and the place the
  confirmed one; that is the ruling's own revisit.
- A place `at .room` or a peer document with no authority has no arbiter: an arbitrated field
  there is a compile error naming the profile (§9, ruling 4).

## 4. Transports: one model over three

A transport carries one frame shape: `{ doc, from_cursor, ops[], frontier }`. The model never
knows which carried it.

| Transport | Carrier | Cursor | Authority |
|---|---|---|---|
| Local | none; tab ⇄ tab by BroadcastChannel, process ⇄ widget by the same file | — | none needed: one device |
| Client–server | std-http: `POST /sync/<doc>` carries ops; the existing SSE feed (`/events`, std-http `sse.av`, `Last-Event-ID`) carries the server's ops, its notice `id` now the server sequence it already is (`avra-stand`) | server sequence (int) | the server: total order, arbitration, GC |
| Peer-to-peer | WebRTC data channel (web), TCP/QUIC (native), same frames | version vector | a named host peer, or none |

The server is a peer that is durable, always reachable and allowed to arbitrate; nothing else
distinguishes it. Today's observed layer survives as the transport for non-sync reads (an
`@crud` list a page only observes): its `avra-reads`/`avra-wrote` staleness, 304s and `Overlay`
layers are the confirmed/optimistic machinery of §3, and a synced place replaces the re-ask with
the ops themselves. The native target has no stream yet (`unheard`, native/sources.av); it is owed
before `.shared` runs there.

## 5. Presence

Presence is a document at `.room(x)`: a map from replica to that replica's `.room` places, each
an LWW register, never written to a log, never sent to a replica that was not connected, each
entry expiring 30 s after its replica's last frame. `cursor`, `typing`, `selection` are ordinary
`state … at .room(x)`; `present(x)` is the map's keys with their principals. Same frames, same
transport, one bit set (`ephemeral`). Using a `.room` value as a durable fact is refused (UI
ledger, "presence is not truth").

## 6. Persistence and schema change: no new store

- **Server.** A `@sync` type is a `@model` (std-db): its table is the materialized state, read
  by everything that reads it today (`Todo.all(db)`, the `@crud` doors). Each field gains two
  columns, its stamp and the server sequence of its last write (`seq`). Catch-up is "rows with
  `seq` > cursor", so registers need NO op log; std-db's per-table counters (`avra_commits.seq`,
  `avra_tables.last`) become per-row. Sequence items are one more `@model` table per sequence
  field. Tombstones are rows with a `gone` stamp.
- **Client, native.** The same `@model` tables in a local SQLite file; the outbox is a
  std-queue_store queue (`send` commits before it answers; `ack` on the server's acknowledgement;
  dedupe by the op's stamp, the queue's own `FlowSeen`).
- **Client, web.** SQLite over OPFS, the same tables; IndexedDB is the fallback. Owed: a web
  build of std-sqlite.
- **In memory.** The document is std-relation rows; a view's read of `todos` is a `@query` over
  them, so the kernel's invalidation is the repaint trigger (§8's cost is that path).
- **Schema change.** A field is addressed on the wire by its declaration position, so std-relation's
  shape verdict decides: `Same` and `Grew` (fields appended) sync between versions, an older
  replica keeping and forwarding ops for fields it does not know; `Moved` (rename, reorder, type
  change) is refused for a `@sync` type exactly as std-db's `diff` refuses a moving migration. A
  frame carries the writer's shape hash; the server holds every shape it has seen (`FlowShape`
  is the precedent).

## 7. Prior art

| System | Model | Right | What we take | What we leave |
|---|---|---|---|---|
| Automerge 2 | JSON CRDT, columnar log, hash DAG | full history, compact saves (14 KB for §8's doc) | per-field registers, text by `splice`/diff, the columnar idea for snapshots | a change per write (143 B each on the wire, §8), a hash DAG where a server gives order |
| Yjs | YATA sequence, struct store | fast (11.6 ms per 10k merged ops), small updates (17 B/field write), awareness protocol for presence | the sequence, the `awareness` shape for §5 | untyped shared types beside the app's types; tombstoned structs never shrink (113.7 → 112.8 KB after deleting half) |
| Replicache / Zero | server-authoritative, client mutators replayed on rebase | arbitration by the server, pull by cursor, optimistic rebase | the cursor, arbitration for the marked fields | mutators written twice (client and server) |
| ElectricSQL | Postgres logical replication to a client store, shapes | the server DB is the truth, no second store | the materialized table as truth (§6) | read-path only; writes are the app's problem |
| Linear's sync engine | object graph, per-object versions, server total order, transactions queued offline | per-row `lastSyncId` catch-up, the model declared once | `seq` per row (§6), client-minted ids | LWW per object, so long text needed a separate CRDT |
| SwiftData / CloudKit | per-record LWW, server change tokens | zero ceremony on the model, `CKShare` for sharing | the declaration-only author's view | whole-record LWW, opaque conflicts, no text merge |
| Firebase (Firestore) | document store, LWW per field, offline cache | per-field merge, offline write queue, listeners | the outbox, per-field granularity | no ordered sequences (`arrayUnion` is a set), a counter only by spelling `increment()` |

## 8. Cost (P4)

Probes are in `scratch-probes/sync/` (an Avra package; two Node scripts over yjs 13.6.20 and @automerge/automerge 2.2.8); output quoted. The Avra probe is the model's hot path: a document as
per-field registers in `Cell<List<int>>` columns, `(lamport, replica)` stamps, ops merged one
compare each, the wire size of each op as LEB128 varints with the clock delta-coded.

```
1000 records x 3 fields, 10000 ops: local 24 ns/op  concurrent 14 ns/op  replay 15 ns/op  wire 6.74 B/op  (changed 10000 6000 0)
100000 records x 8 fields, 1000000 ops: local 123 ns/op  concurrent 67 ns/op  replay 28 ns/op  wire 7.70 B/op  (changed 1000000 600000 0)
AVRA_MEM_STATS=1: list boxes peak 192 MB for 2,000,000 Op records; each stamp column 9 MB peak for 800,000 cells
```

Read as: a merge is one stamp compare and three column writes, 14 ns warm on a 3,000-cell
document and 67 ns on 800,000 cells (cache misses); a replayed op, the duplicate an offline
rejoin sends, costs 15–28 ns and changes nothing (`changed … 0`). An op on the wire is 6.7–7.7
octets in a batch. Not yet in the number: decoding the varints, and the sequence (text, list
order), which this probe does not model. Two costs it found: a stamp is 16 B per field (two int
columns, 9 MB per 800,000 cells with growth slack), and an op held as an Avra record is 96 B
(192 MB / 2,000,000), 12× its wire form, so a batch stays packed `Bytes` until it is merged.
Built by the committed seed (`bootstrap/seed.ll.gz`): `make bootstrap`'s gen-1 refused
std-ui at 13c2fd4 (`type.struct_fields` in tree/story.av), so the probe has no std imports.

Prior art over the same workloads (1,000 todos of three fields; 10,000 field writes; 10,000
characters typed; another peer's 10,000 title writes merged):

```
yjs       {"insert_bytes_per_todo":56.67,"field_write_bytes":16.99,"char_bytes":13.52,"doc_bytes":113657,"heap_bytes":4055000,"merge_10k_ms":11.63,"merge_batch_bytes":121712,"doc_after_delete_half":112809,"load_ms":28}
automerge {"insert_bytes_per_todo":164.55,"field_write_bytes":4.91,"char_bytes":95.60,"doc_bytes":14343,"merge_10k_ms":272.24,"merge_batch_bytes":1427725,"doc_after_delete_half":108527,"load_ms":295.18}
```

(Automerge's `field_write_bytes` is a compressed `saveSince` chunk; its per-change wire cost is
the batch: 1,427,725 / 10,000 = 143 B. Its heap is wasm memory, not measured here.)

Fractional position keys, 10,000 inserts, base 95, midpoint rule:

```
append   max 1429 mean 714.79
random   max 6 mean 3.22
head     max 1667 mean 833.83
same-gap max 1667 mean 833.83
```

Random inserts cost 3 octets. Under this rule, appending, prepending or typing into one gap costs one
octet per ~6.6 inserts, without bound. Libraries that grow an integer head fix append and prepend;
none fixes repeated insertion into one gap without renumbering. That is why §2 orders by a
sequence, not by keys.

The budget this proposal holds itself to, against those numbers:

| Measure | Budget | Basis |
|---|---|---|
| Wire, one field write | ≤ 8 B in a batch, ≤ 40 B alone with the frame | measured 6.7–7.7 B; Yjs 17 B |
| Wire, one typed character | ≤ 4 B in a batch (runs coalesce) | Yjs 13.5 B |
| Merge | ≤ 50 ns per register op; 10k ops < 1 ms | measured 14–67 ns, 10k in 0.14–0.46 ms; Yjs 1.2 µs/op |
| Memory | ≤ 16 B per synced field beyond its value; ≤ 24 B per tombstone | two ints of stamp |
| Repaint | an op repaints only the views that read its `(rec, field)` | the read set, UI doc |

## 9. Rulings asked

1. **Where sync is declared: an `at` profile on `state`** (`.device`, `.account`, `.shared(x)`,
   `.room(x)`), not a wrapper type (`Replicated<T>`), so reads and writes stay in `T`.
   Recommend: yes. It retires the UI ledger's T7 ("`.replicated` not in v1"), whose condition,
   a proved catalogue, is §2's table; each row lands with an exhaustive finite check of
   convergence (all interleavings of three replicas, two ops each) as its receipt.
2. **The write means what the compiler can prove**: register by default, counter when every
   write is `x = x ± e`, sequence for typed text and for lists; `@register`, `@text`, `@counter`
   override; `explain` names each choice. Recommend: yes. The alternative, op verbs
   (`x.add(1)`), is SHARING_MODEL's fallback and costs the author's view.
3. **Identity is minted by the creating replica** (32-bit replica, 32-bit counter in the `id`
   int); the server stores it as the row id. Recommend: yes. It deletes the board's "id 0 until
   named" and makes offline inserts final.
4. **The arbitration line is a mark on the field**: `@unique`, `@check`, `@owner` writes go to the
   authority and roll back on refusal; every other write converges and never rolls back. A field
   so marked in a place with no authority (`.room`, an unhosted peer document) is a compile
   error. Recommend: yes.
5. **The store is std-db's tables plus std-queue_store's outbox**: stamps and a per-row `seq` as
   columns of the model's own table, no op log for registers, sequence items as a `@model`
   table. Recommend: yes, with the first slice server-and-native only, and the web client owed
   on a web std-sqlite.

First slice if ruled so: `@sync` registers and tombstones over client–server, the board ported,
§8's budget as a gate row in docs/ZERO_COST.md.
