# FLOW 04 — `select`, timers, task arms: design

Ticket `avra-8sb5.34.53.4`. `f:` is `runtime/avra_fiber.c`. A number is MEASURED (where and how is
said beside it), READ, or ESTIMATE. The surface in §1 is the owner's decision; §2 is the mechanism
that carries it; §5 is the order it is built in.

## 1. The surface

1. Arms are tried TOP TO BOTTOM, at entry and at every wake. No word says so: order is priority.
2. One opt-out, `@fair select { … }`: the arm ready LONGEST goes first, wherever it is written.
3. A list arm binds the VALUE of the first member to answer; a member that ended cancelled is skipped.
4. `r in t` binds `T`; a task that ended cancelled passes its cancel on, as a bare `t.await` does.
5. A timer is a plain value: one `Deadline` is one budget across a loop, and `d.wait()` waits for it alone.
6. The loopable group (`Tasks`) is slice 05's (D5).

```
primary = ( f:mark )? "select" "{" ( BREAK | "," | a:sel_arm )* "}" @expect("}", "expected `}` to close the `select`") -> select_expr(f, a)
sel_arm = "else" "->" v:expression -> else_arm(v)
        | ( ( ix:NAME "," )? ( b:NAME | w:"_" ) "in" )? h:expression ( "if" g:expression )? "->" v:expression -> wait_arm(ix, b, w, h, g, v)
```

```avra
select {                                  // ORDER IS PRIORITY: `stop` wins whenever both are ready
    stop           -> halt()
    r in job       -> use(r)
}
let limit = after(secs(5))                // one budget across a loop
for url in urls {
    select {
        limit                 -> { return pages }
        p in spawn fetch(url) -> pages.push(p)      // made here: cancelled the moment `limit` wins, joined as the `select` ends
    }
}
let mirrors = [spawn get(a), spawn get(b)]
let page = select {                       // the first mirror to ANSWER; one that ended cancelled is passed over
    page in mirrors -> page
    limit           -> cached(url)
}
mirrors.cancel()                          // the rest are the author's: without this the block waits them out
@fair select {
    a in left  -> merge(a)
    b in right -> merge(b)
}
```

- THE STARVATION IS SAID WHERE IT IS WRITTEN: an upper arm that is always ready is taken every time,
  and the arms below it never run. That is the meaning of the order, it is visible in the source, and
  `@fair` is the one way out. The `select` doc opens with it.
- BINDERS: a task arm binds its answer; a list arm binds the value, or `i, page in mirrors` the index
  too; a timer arm binds nothing; `_` binds nothing. A GUARD is read immediately before its own head,
  in order; a false one skips the head.
- `else ->` runs when nothing is ready. `select { }`, a lone `else`, and a `Quiet` beside `else`
  (`flow.quiet_never`) are refused. `_ -> …` speaks "a `select` has no catch-all — `else ->` runs when
  nothing is ready"; `x.await` as a head speaks "drop `.await` — the arm does the waiting".
- `@fair` IS A MARK THE `select` CLAIMS — data, nothing runs where it is written. In expression
  position the `select`'s own rule takes it. At statement position the annotation rule would take
  `@fair` first and resolve it as a name, so the feature contributes a statement branch of its own
  ahead of it (`stmt = f:mark s:select_core END`), non-committing. If that order cannot be had, the
  spelling is `select @fair { … }`, one rule for both positions. Any other mark on a `select` is
  `annotation.unread_mark`.

## 2. The decisions

**D1 — THE SCAN CHOOSES; THE PARK ONLY WAKES.** One loop, and one column on a row: `since(cx, head)`,
its readiness as a STAMP — 0 when not ready, else when it became so.

```
guards and heads once, in source order → g_i, h_i ; a Quiet's instant is fixed here
loop:
    wait_enter(site)                      // a standing cancel, a passed deadline: heard before any arm is looked at
    ordered: the first live arm, top to bottom, whose since ≠ 0      |  @fair: the live arm whose since is least
    found a: each other live arm's row.lose ; v = row_a.take ; body_a ; leave
    else-arm: yield ; else's body ; leave  // `avra_fiber_yield`: the world runs when it holds anything
    each live arm: row_i.arm(h_i, i)       // files only on what is still LIVE
    wait_rest()                           // parks; nothing filed and no `else` → trap, "a `select` had no open arm"
    again                                  // the claim is a HINT: the scan decides
on leaving the expression: each head-made task is settled
```

- PRIORITY HOLDS AT THE WAKE BY CONSTRUCTION: parked on an upper and a lower arm, the lower ends first
  and claims the park, the upper ends before the task runs again — the claim names the lower and the
  scan from the top takes the upper. Every wake scans; there is no second mode.
- A CANCEL AND A DEADLINE ARE HEARD AT EVERY ENTRY, ready arm or not. An entry that finds an arm ready
  switches to nobody, so it counts as a turn for the world: every `FAIR_TURNS` of a task's such turns,
  while a timer or a descriptor waiter is filed, due timers fire and the poller is asked. A `select`
  never claims for itself, so every claim its park sees is another party's.
- THE RAW ROWS HOLD THE SAME LAW: on `avra_wait_park` another party's claim comes first, then a
  standing cancel, then a passed deadline, then the task's own claim (an arm found ready as it armed).
- `else` NEEDS NO ROW OF ITS OWN: the scan found nothing, nothing is armed, and the yield row is the
  whole poll.
- THE RETRY LOOP HAS NO CHECKED BACK-EDGE and needs none: `wait_enter` is its cancel point, and each
  turn but the first follows a wake. `arm` files only on live members — an ended task is an open gate,
  and one armed in a retry loop would claim at once every turn.

**D2 — `@fair`: OLDEST-READY FIRST.**

| | oldest-ready: a logical stamp (chosen) | a random start |
|---|---|---|
| bound | HARD: a ready arm is passed over only by arms ready before it — at most `arms − 1` times | none: ((n−1)/n)^k |
| replay | exact; nothing drawn, nothing counted | one counted draw an entry with two ready |
| at the wake | the same rule: the first claimant IS the oldest | a second rule |
| cost | it must look at every arm | stops at the first ready from its start |

- THE STAMP IS A COUNTER, NEVER THE CLOCK: one count for the process, drawn where a task ends
  answered. A cancelled end stamps 0. A seed and the virtual clock change nothing about it.
- TIMERS ARE ONLY NOTICED, NEVER OBSERVED ENDING, so they carry no honest event stamp — and a stamp
  taken "when noticed" would be the newest at every entry, so a `Deadline` in a busy fair loop would
  never fire. THE RULE: A DUE `Deadline` OR `Quiet` GOES FIRST (among several, the earliest instant);
  an `Every` is stamped in its own `Cell` the first time it is FOUND due and keeps that stamp until
  taken, so it queues with the events. THE ONE EXCEPTION TO THE BOUND: a loop that keeps a `Deadline`
  due at every entry (an absolute period that overruns) wins every entry even under `@fair`; `every`
  is the fair period.
- A REPEATABLE ROW'S `since` IS RENEWED AT ITS TAKE (least-recently-served), or a source that stays
  non-empty holds the oldest stamp for ever. Slice 05's rows owe this.

**D3 — WHAT AN ARM MAY WAIT ON.** `WaitRow { name, takes, binds, since, arm(cx, head, a),
take(cx, head, member), lose(cx, head, a), once, fresh, promise }`. `promise` (false for every row
here) is 05's: a wake that HANDED this task a value another arm must not strand.

| row | head | binds | since | arm | take | lose | once | fresh |
|---|---|---|---|---|---|---|---|---|
| a task | `Task<T>` | `T` | its end's stamp; a CANCELLED end reads as oldest — done either way | `wait_task(t, a, 0)` | the join's own read: a cancelled task passes its cancel on | head-made: `t.cancel()` | yes | no |
| tasks | `List<Task<T>>`, a place | `T`; `int, T` | the least stamp among members that ANSWERED, and its index | `wait_task` on each member still LIVE | that member's cell | none | yes | no |
| a deadline | `Deadline` | — | due: first | `wait_until(d.at, a, 0)` | — | — | yes | yes |
| a quiet | `Quiet` | — | due at its entry instant: first | `wait_until(entry + span, a, 0)` | — | — | no | no |
| a period | `Every` | — | its found-due stamp | `wait_until(e.next, a, 0)` | the library's `passed()` | — | no | yes |

A SINGLE TASK'S `since` IS "DONE", A LIST'S IS "ANSWERED": a cancelled task must fire its own arm so
the take can pass the cancel on, and must never win a race among mirrors. The two rows differ in
exactly that word. Slice 05 adds `Source`, `TrySource`, `AnyOf`, `x.ended`, `offer`, a typed
`Tasks<T>`; slice 06 sockets, watch, signals.

**D4 — THE LIST ARM.** It fires for the member that ANSWERED FIRST — the least stamp, in either mode,
not the lowest index. `Err` from a `Task<Result<…>>` is an answer and wins. A member that ended
cancelled is never taken, never armed again, and cancels nobody; its end may wake the selector once,
and the scan passes over it. `Task<void>` members bind nothing: `_ in ts`, `ts ->`, or `i, _ in ts`.
- EVERY MEMBER CANCELLED, OR AN EMPTY LIST: the arm stays SILENT beside its siblings — a dead arm is
  not an error while another can fire. When NO arm of the `select` can ever fire (nothing filed, no
  `else`) it traps by name, at entry or at the wake that closed the last one. One rule with "every
  guard false", and it is the runtime's: `avra_wait_rest`.
- ONE-SHOT, AND REFUSED IN A LOOP whatever its guard (`flow.spent_arm`): an answered member is ready
  for ever. A list literal as a head is refused only where the index is asked for.
  `List<Task<T>>.cancel()` is one method row beside `Task.cancel`.

**D5 — THE `Tasks` GROUP IS SLICE 05's.** `page in group` needs a type for `page`, and `Tasks` has
none: typing it is `Tasks<T>`, an arity change to a core type, its fingerprint word, and the owners
that hold tasks of unlike answers. The take must also HAND OUT the answer the shed releases, and the
loop needs an `is_empty` the owner lacks. Nothing here makes it harder: the row is `since` = the
oldest answered member, `take` = shed it, `once: no`, and the scan-chooses loop already tolerates a
head its own take changes.

**D6 — TIMERS ARE PLAIN, SEALED VALUES IN `@std/time`.**
- `@sealed type Deadline = { at: int }`, minted only by `after(d)` and `d.plus(span)`. `at` is
  NANOSECONDS OF THE MONOTONIC CLOCK, an instant of THIS process only: `left() -> Duration` is what
  crosses a wire or a store and `after(left)` rebuilds it. `late() -> Duration` is zero until due.
- `quiet(d)`, EXACTLY: armed each time its `select` is ENTERED, for `d` from that entry; it fires if
  no arm is taken first. Any arm taken, and the time its body ran, restarts it; it has no maximum
  wait. IT IS A LOOP-IDLE DEBOUNCE AND NOT A WATCHDOG, and its doc carries both programs: the wrong
  one (`quiet(ms(200)) -> stop_motors()` beside a telemetry arm never fires) and the idiom —
  `mut dog = after(ms(200))`, the heartbeat's arm writes `dog = after(ms(200))`,
  `dog -> { stop_motors()  return }`.
- `every(d)`: `@sealed Every`, bound outside the loop, holds its next instant in a `Cell`. ABSOLUTE:
  the first tick is one `d` after `every` was called and each next is `d` after the last DUE instant,
  not after the body. MISSED PERIODS COALESCE: a take that finds itself k periods late moves `next` to
  the first boundary after now and adds k to `tick.missed()` — no burst.
- `d.wait()` and `tick.wait()` are library: a due value returns at once, else `avra_wait_until` and
  one park — a cancel point.
- THE TIE: a `within` limit and an arm's time on one instant — THE SCOPE WINS. `wait_enter` hears the
  deadline before the scan, and the heap sorts a scope's limit before an arm's time.

**D7 — LOSERS, OBSERVERS.**
- A task MADE in a head (`spawn e`) is CANCELLED RIGHT AFTER THE CHOICE, before the winner's body's
  first statement — its row's `lose` — and JOINED when the `select` EXPRESSION is left, on the
  `select`'s own frame, not the fn's. The join waits for the loser's unwind: bounded by its next
  cancel point, and by its `defer`'s own `within`.
- A task bound outside is the author's: `flow.loser_runs` warns where it is never read after.
- THE WAIT RECORDS ITS SITE: `wait_enter` hands the task's record the text of where the `select` was
  written, the record keeps it, and `avra tasks` says it for a task resting there — `select id=N
  site=file:line for=<ms>`, the time an upper bound — beside each timer arm's `due_in=<ms>`. A task
  parked on nothing says `src=none`.
- WHERE A CANCEL LANDS: at an entry or a park (no arm runs); never between the choice and the take; in
  the BODY at its first cancel point — a taken value is then gone, though a task's answer is still in
  the task.

**D8 — LOWERING: no new instruction; four word-seat rows with `avra_vtask_*` twins.**
`avra_wait_enter(site)`, `avra_wait_rest`, `avra_task_since(task)`, `avra_time_since(at_ns)`. Arming is the
rows that exist (`avra_wait_task`, `avra_wait_until`); `else` is `avra_fiber_yield`. None of the IR
protocol's four justifications is met, and every pass reads what it reads without them.

**D9 — THE SEED COUNTS NOTHING IN A `select`.** Ordered, there is no choice at entry or at a wake.
`@fair` reads stamps, which are facts of the schedule already chosen. What is counted is which ready
task runs — and that decides which task ends first, hence every stamp. EVAL == NATIVE needs the
evaluator's jobs stamped from the same counter where they end.

**The rules.**
- `flow.spent_arm`: a `once` arm inside a loop whose head is a place bound outside it, UNLESS the
  body's last statement leaves the loop (`return`, `break`, `fail`), or the head is a `mut` binding
  the body's own statement list assigns. A GUARD LICENSES NOTHING. A task arm must leave; a list arm
  has no licence. Help: "leave the loop in this arm".
- `flow.fresh_deadline`: a `Deadline` MADE in a loop beside a sibling arm that can fire again; an
  `Every` made in a loop, always. A per-attempt timeout checks. Help: "for one limit over the whole
  loop bind it before; for 'nothing happened for `d`' write `quiet(d)`; for each `d`, `every(d)`".
- `flow.loser_runs` (WARNING): a task or list arm whose head is a binding of the enclosing block, in
  a `select` with another arm, where the binding is never read after the `select`.
- `flow.quiet_never`: a `Quiet` beside `else`.

## 3. Where the spec is silent or differs

- The spec's `select` has no place for a mark, and an annotation cannot sit on an expression: `@fair`
  is the `select`'s own.
- The spec's `any(tasks)` "skips a task once it answered"; the list arm skips one that was CANCELLED
  and takes the first that answered.
- `Tasks` cannot be a typed arm without becoming `Tasks<T>` (D5).
- A task that ended cancelled opens its gate: every "wait for an answer" filters it, at the scan and
  at the arm.

## 4. Tests — one per law, failing first, eval == native unless marked C

1. ORDER AT ENTRY: two ready, the upper is taken, under every seed, and the run counts no choice.
2. ORDER AT THE WAKE: the lower claims the park, the scan takes the upper.
3. STARVATION IS THE LAW: an always-ready upper arm over 1000 turns never lets the lower run — a pin.
4. `@fair`: the same program takes them alternately; three arms ready at stamps 3, 1, 2 are taken
   1, 2, 3; no arm is passed over more than `arms − 1` times in 10,000 turns (C).
5. `@fair` and a due `Deadline`: it goes first; an `Every` queues by its found-due stamp.
6. THE LIST: the first to answer wins though it is the last index; an `Err` wins; a cancelled member
   is skipped and the selector is not cancelled; one cancelled WHILE PARKED wakes and is passed over;
   every member cancelled beside a deadline waits for the deadline; alone, it traps by name.
7. A list arm in a loop: refused, guard or not.
8. `@fair` at statement and at expression position; another mark on a `select` refused.
9. `d.wait()` under a cancel unwinds; due, it returns at once.
10. A cancel standing over an always-ready arm is heard at the next entry; a `within` over it is cut.
11. An else-loop beside a parked reader lets it run.

## 5. The ladder — [C] is scheduler C

1. [C] THE ENTRY AND THE STAMP: `avra_wait_enter`, `avra_wait_rest`, `avra_task_since`,
   `avra_time_since`, twins; the stamp set at a task's three ends.
2. [C] The tie by kind; the site word and the listing's additions.
3. [C] Overflow waiters on one process-wide free list, trimmed where the world idles.
4. The rows' evaluator arms, the job's stamp, the lowering's verbs; a program test over hand-declared
   externs.
5. `@std/time`: `Deadline`, `Quiet`, `Every`, `after`, `quiet`, `every`, arithmetic, `wait`.
6. GRAMMAR: `features/select` — node, builder, resolver, formatter, `WaitRow`, the task row, the
   ordered loop, `else`, the trap, `lose` and the join.
7. The deadline, quiet and period rows; `flow.fresh_deadline`, `flow.quiet_never`.
8. The list arm: value and index binders, the answered-only scan, `List<Task<T>>.cancel()`, its loop
   refusal.
9. `@fair`: the least-stamp scan, the timers-first rule, `Every`'s stamp.
10. `flow.spent_arm`, `flow.guard_binder`, `flow.arm`'s help, `flow.loser_runs`, the `_ ->` voice;
    each rule's rate.
11. Seeded program tests, the bench rows, the ROADMAP asks (`-> {}` as void in arm position; a typed
    `Tasks<T>`).

## 6. Bounds, and what a test cannot show

| quantity | bound |
|---|---|
| entry, n arms | O(n); ordered stops at the first ready, `@fair` looks at all |
| a park | entry, plus filing O(n), plus one scan at the wake |
| a list arm of N | O(N) to scan, to arm and to retract; unbroken |
| a lower arm, ordered | UNBOUNDED while an upper arm stays ready: by design |
| a ready arm, `@fair` | at most `arms − 1` passes; UNBOUNDED under a `Deadline` kept due every entry |
| a `Deadline` due → its body | one tick or `FAIR_TURNS` turns to notice, plus every task ahead × its longest run: UNBOUNDED beside a `for`, a recursion or a blocking row |
| a cancel → a busy `select` | its next entry |
| allocation | 0 a turn for ≤ 4 waiters |

NOT FOR HARD REAL TIME. Under the virtual clock every body takes zero time: no drift, no missed
period, `late()` always zero, a `Deadline` never beats a task that computes. `select` is not
`@std/ui`'s event construct.

MEASURED, ladder 1, ONE MACHINE (x86-64 Linux, `cc -O2`), three processes, least–most over their
rounds. "By arming" is the path a wait took before the scan: every arm armed in order, the ready one
claiming as it arms, the park answering — measured on the object built from the tree before this
ladder. "Scan" is `avra_wait_enter` and the caller's loop over `avra_task_since`.

| a turn with one arm ready | by arming | scan, ordered | scan, oldest-ready |
|---|---|---|---|
| 2 arms, the first ready | 11.9–14.7 ns | 6.0–7.3 ns | 8.5–11.1 ns |
| 2 arms, the last ready | 23.8–34.5 ns | 7.7–11.0 ns | 8.5–12.8 ns |
| 4 arms, the last ready | 49.7–67.8 ns | 10.8–14.1 ns | 11.7–13.9 ns |
| 8 arms, the last ready | 129–148 ns | 19.0–22.0 ns | 20.7–22.8 ns |
| 64 arms, the last ready | — | 119–134 ns | 121–141 ns |

| a parked pick | the claim trusted, before | the claim trusted | scanned before and after |
|---|---|---|---|
| over 2 gates | 126–152 ns | 123–155 ns | 139–184 ns |
| over 4 gates | 157–212 ns | 154–183 ns | 177–204 ns |
| over 8 gates | 240–286 ns | 236–306 ns | 277–341 ns |

One stamp read: 2.2 ns. One entry with nothing standing: 3.4–3.7 ns. So a ready turn by scan costs
about a third of the same turn by arming at 2 arms and a seventh at 8, and a park pays one more scan
on each side of it: about 15, 20 and 40 ns on the least values.

## 7. The objections it concedes

1. ORDERED BY DEFAULT STARVES A SERVER whose upper arm is always ready. Conceded as the design's
   cost: the hazard is on the page, not in a scheduler; `@fair` is one word; test 3 pins it so a "fair
   by accident" fix cannot hide it. Nothing WARNS: a lint for "a repeatable arm above a stop" would
   fire on correct priority code.
2. `@fair`'s STAMP IS A COUNTER: "oldest" is by the order ends were OBSERVED, a timer due earlier in
   real time than an event that ended first still goes ahead of it, and the overrun-period exception
   is real. The counter is why a seed replays it, and timers-first is the only rule that cannot starve
   a deadline.
3. EVERY WAKE SCANS EVERY ARM: it buys order at the wake, the cancelled-member skip and the
   dead-`select` trap with no mechanism of their own. A row whose scan is dear pays it twice a park;
   that row is refused in a loop.
4. `since` MEANS DONE FOR ONE TASK AND ANSWERED FOR A LIST: one word in two rows, tested from both
   sides. The alternative would make `r in t` wait for ever on a cancelled task.
5. ORDER AND A HANDED VALUE: a sender that HANDED a value to a parked selector must have it taken, yet
   the scan may prefer an upper arm that became ready meanwhile. That is 05's first design question,
   and its seat is `promise`: no row here promises.
