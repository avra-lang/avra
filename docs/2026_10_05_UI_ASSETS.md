# UI assets and packaging — the design

> 2026-10-05, revised after the owner's review. Base `0718345`. Ticket `avra-8sb5.59.44.11`.
> Design only. Claims about today's compiler are PROBED (result quoted) or ASSUMED.
> Sizes of fonts and libraries are approximate, from memory of the public files — re-measure before quoting.

## 0. What an author writes

```
art/
  logo.svg   hero.jpg   hero-dark.jpg   Inter.var.ttf
  icons/  close.svg  arrow-left.svg  …
```

```avra
// src/app.av — ONE line names the folder. Everything in it is typed.
asset art = "art" {
    hero { dark: "hero-dark.jpg" }               // said only because it must be
    icons { mirrored: [arrow_left, arrow_right] }
}

export const brand = default_theme with { face: { "body": .Bundled(art.inter_var), "mono": .System(.Mono) } }

fn view() -> View {
    column {
        image art.logo { alt: "Acme" }
        image art.hero { decorative: true }
        button "Close" {
            icon art.icons.close {}
            on press { shut() }
        }
        image remote(https("cdn.acme.dev/u/42.jpg"), 96, 96) { alt: user.name }
    }
}
```

**The file and the node, in three lines:**

```avra
asset logo = "art/logo.svg"      // the FILE: bytes this build has. Its type, `Picture`, is read from the bytes.
image logo { alt: "Acme" }       // the NODE: a place in a view that draws it, with its words.
icon logo {}                     // another node drawing the same file: text-sized, tinted, silent.
```

There is no `picture` word. `Picture` is a type the compiler infers, as `5` is an `int`.

### The alternatives, side by side

| | one image | a folder of icons | a font + licence | a dark variant |
|---|---|---|---|---|
| **A. a word per kind** | `picture logo { source: "art/logo.svg" }` | `icons glyph { source: "art/icons" }` | `typeface inter { source: "…ttf"`, `license: "…" }` | a `variant { … }` child |
| **B. one word, one file** | `asset logo = "art/logo.svg"` | `asset glyph = "art/icons"` | `asset inter = "art/Inter.var.ttf"` | `… { dark: "art/hero-dark.jpg" }` |
| **C. a literal at the use** | `image asset"art/logo.svg" { … }` | — (no members to name) | `.Bundled(asset"…ttf")` | nowhere to say it |
| **D. a convention, nothing declared** | `image assets.logo { … }` | `icon assets.icons.close {}` | `.Bundled(assets.inter_var)` | a sidecar file |
| **PICKED: B over a folder** | 0 after `asset art = "art"` | 0 | 0 — the licence is read from the font | 1 line in the block |

- **Picked:** `asset name = "path"`, where the path is a file OR a folder. A folder is a record typed from its tree; a block says only what a file cannot say for itself.
- **Why not D.** It saves four tokens once per package and costs a name that appears from nowhere in every file, a special rule in the resolver, and no ordinary `export`. `avra new app` writes the line.
- **Why not C.** A variant, a licence and a mirror list have no home, and a folder has no members.
- **Why not A.** Three words to learn for a fact the bytes already state.

**Still compile errors:** a missing path (at the literal) · a misspelt member (`art.lgoo` — the unknown-field error lists the members) · a wrong kind (`image art.inter_var` — "`image` draws a `Picture`, this is a `Typeface`") · `image` with neither `alt` nor `decorative`, or with `alt: ""`.

## 1. The laws

1. **An asset is a declaration: `asset name = "path"`.** It has a module and an `export`; a library ships art by exporting one.
2. **The kind is read from the bytes and carried in the type** — `Picture`, `Typeface`, `Sound`, `Video`, `Blob`; a folder is a record of them. Never from the extension. `asset x: Blob = "…"` pins a kind.
3. **No asset is found by text.** A handle exists only by naming a declaration or its member; there is no lookup by string. So what a program reaches is EXACTLY what it can show.
4. **A member is its file's stem**, `-`, space and `.` read as `_`. A stem that is no name, or two files with one stem, is refused naming the files. One spelling is read: `@2x`/`@3x` before the extension is a hand-made density of the same member, because every design tool exports it.
5. **A path is a literal, read from the declaring package's root, and stays inside it**: no `..` out, no absolute path, no symlink out.
6. **The handle is neutral; the reference is the target's.** The tree carries an id plus what holds everywhere (intrinsic size, dominant tone). What a target writes is read from that target's asset table by its lowering.
7. **Bytes the build has are an asset; a name for bytes someone else has is a `Url`.** `remote(url, width, height)` is the exception, spelled: sized by the author, never transformed, shipped or precached.
8. **Layout never jumps.** Every picture in a tree has an intrinsic size.
9. **Checking never transforms.** `check` reads headers; only `build` encodes. A file's public name is its KEY (source bytes ⊕ recipe ⊕ codec version) — one derivation for the cache entry and the shipped name.
10. **Only what is reached ships, at the sizes it is drawn.** An unreached file costs zero bytes on every target.
11. **An image says its words where it is used**: `alt: "…"` or `decorative: true`, exactly one. A file carries no words.
12. **A variant is the asset's; the choice is the environment's** (`Mode`, size class, locale, direction).
13. **Tint is a token.** `icon` draws a picture's shape in the tone the use names; `image` draws its colours.
14. **A vector is parsed into a model with no unsafe shape** — no script, external reference, event attribute or `<style>`. Targets write from the model; none sanitises.
15. **A font is licensed or refused.** The licence is read from the font's own `name` table; a face that carries none must be told one. Its embedding bits (`fsType`) are read, and a restricted face is refused where it would be embedded.
16. **An asset has a home, said with `at`** (§5). A rule may pick a home by itself only when that does not change what must be deployed.
17. **No silent downgrade.** A format a target asked for that this build cannot make is an error naming what to change.

## 2. What the compiler learns, and what each buys

| the compiler learns | buys |
|---|---|
| the `asset` declaration: a path literal read as a build input (octets and directory names), settled at check | one word for every kind; a missing file is a located error. PROBED: `asset logo = "…"` is `parse.expected` today; `embed` is text-only (a PNG traps "is not UTF-8 — byte 0") |
| a folder's type is a record generated from its tree | zero tokens per file; typos answered with the member list |
| `trait Asset` — a kind claims files by their leading bytes, reads a handle at check, and projects artifacts at build; kinds are collected program-wide | the kinds are LIBRARY code (`@std/assets`), so a package can add one (Lottie, glTF, a shader) |
| reach per member of a settled record | an unused icon in a 2,000-icon folder costs nothing; today reach is per declaration (ASSUMED) |
| a collection of only what is reached (`collect … reached`) | each target's table holds exactly what ships |
| `project() -> List<Artifact>`; an artifact is `{ name, key, make }` and `make` runs on a cache miss | the build writes files, the library does no I/O. PROBED: no `Artifact` in the tree — assets are its first consumer |
| `target()` — a settled value may depend on the build target | one source, a table per target |
| use-site facts: the settled box of every node that draws a handle | only the sizes that are drawn are made |
| `at <home>` on a declaration | §5. PROBED: `state n: int at .device` is a parse error today |
| fetched, content-pinned dependencies | §4. PROBED: `"@std/icons" = "1.0.0"` is `manifest.unsupported_dependency` — only path dependencies resolve |

Runtime value: a handle is a settled const (static data, no allocation, no I/O). `Attribute.Src(url: Url)` becomes `Attribute.Picture(Picture)`, where `Picture` is `.Bundled(name, width, height, tone, media, octets)` or `.Remote(url, width, height)`. A bundled picture is named by its CONTENT (the first 128 bits of the BLAKE3 of its octets, hex, plus the extension its media type implies), never by its path, so two builds of one program agree by public NAME and one name is one set of octets. A recipe's settings join the name when transforms land (the key above).

## 3. Every target

| target | pictures | icons | fonts |
|---|---|---|---|
| web page (wasm) | files; `<img width height srcset sizes>`, `<picture>` for formats and variants; a tone/gradient background until loaded; the first picture of the initial tree `fetchpriority=high`, the rest lazy. The wasm carries no pixels. | one inline sprite of reached shapes, `currentColor` | `@font-face`, WOFF2, `unicode-range` slices; the first slice preloaded; fallback metric-matched so the swap moves nothing |
| server HTML | the same markup from the same table; absolute names for feeds and `og:image` | the sprite in the document | `<link rel=preload>` |
| email | one PNG/JPEG at 2x, absolute URL, sizes as attributes; vectors rasterised | rasterised | system faces only; a bundled face is refused here |
| terminal | `[image: alt]`; pixels only under a graphics capability, opt-in | a cell character, else the name | none |
| iOS / macOS | an asset catalog: 1x/2x/3x, vectors kept as vectors, dark and locale as catalog variants | template images; `@std/icons` names use SF Symbols; RTL flag | bundle files + plist rows; sizes through Dynamic Type |
| Android | `res/drawable-*dpi/*.webp`; `-night`, `-ldrtl`, locale qualifiers | VectorDrawable XML from the model, `autoMirrored` | `res/font/` |
| drawn (canvas, GPU) | drawn sizes in a trivially decoded format | path data, filled by the target | the font file + that target's shaper (§6) |
| headless (tests) | the handle: `image logo alt="Acme" 120×40` | name | metrics |

- **Serving.** `assets_route()` answers from the table: a name not in it is a 404 without touching the disk. `Cache-Control: immutable`. CSP stays `img-src 'self'`.
- **`avra dev`.** One candidate per asset — the source file, `no-cache` + ETag. No hashing, no encoder. A changed file re-settles its handle and reloads that node.
- **Offline.** Web: the service worker precaches the table's eager rows. Native: bundled.
- **In tree:** PNG/JPEG/WebP decode, resample, PNG/WebP encode (`@std/image`, vendored C run by the build); WOFF2 (brotli is already vendored — PROBED). **Delegated, pinned by version and digest:** AVIF, Apple's catalog compiler. Absent → an error naming the row.
- **Receipt.** `build/<target>/assets.json`: every artifact, its key, its bytes' digest, its licence, its home.

## 4. Art that is not in the toolchain

What `@std/ui` needs for its own components (a dialog's close, a checkbox's tick — about ten shapes, a few KB) sits in its own `art/` folder and is tree-shaken like anything else. The question is the app-facing icon vocabulary and a default face.

| option | what it needs | offline / CI |
|---|---|---|
| in the toolchain download | nothing | works; every install pays megabytes it may never use |
| **platform-native first** | a name map per platform | zero bytes where the platform has a set (SF Symbols; every OS has a system face) |
| **a fetched package, pinned by the toolchain** | one transport (HTTPS GET of an archive), `sha256` pin, `avra.lock`, a machine cache `~/.avra/cache/<sha256>` | first use needs the network once; after that the cache answers |
| a URL or git dependency written by the app | the same transport; git also needs `git` | same |
| copy into the app (`avra add icon rocket`) | the fetch, then a file in `art/` with its origin and digest recorded | no network ever again; the app owns the file |

**Recommended: native first, a fetched fallback.**

- `use @std.icons.{icons}` → `icon icons.share {}`. On Apple the name maps to an SF Symbol: zero bytes. Elsewhere the SVG comes from the fetched `@std/icons` package (an Apache-licensed set), and only reached shapes ship.
- The default face is `.System` on every target with an OS: zero bytes, measured by the platform. `@std/face` is fetched only when a target has no system text (the drawn target) or the app wants build-time layout proofs.
- The toolchain carries the PIN (name → URL + `sha256`), not the bytes — `@std/*` stays the toolchain's, and a toolchain version names exactly one set of bytes.
- **First build:** resolution fetches, verifies, caches, writes `avra.lock`, and says so on stderr. **Offline:** a cache hit needs no network; a miss is an error naming the URL, the digest and the cache path to fill. **CI:** `--frozen` never fetches and refuses a lock that would change; restore `~/.avra/cache`, or `avra vendor` copies the pinned packages into the repo.
- `avra add icon <name>` is the hatch for owning the file.

This is the first network transport and the first lockfile in the tree. It is the minimum the old registry spec's content-addressed lock needs, and no registry service: a static host and a hash.

## 5. Where an asset lives

An asset's home is the same notion as a `state`'s: WHERE the thing lives and how a reader reaches it. It is simpler, because an asset never changes — no authority, no sync, cache forever. Same word `at`; its own homes.

| home | the bytes are | reached by |
|---|---|---|
| `.inline` | inside the document or code that draws it | nothing — zero requests |
| `.program` | static data in the executable | `assets_route()`, or a direct read |
| `.bundle` | files beside the executable: the app bundle, `res/`, `build/web/assets/` | the platform, or any static host |
| `.cdn(origin)` | uploaded by `avra deploy`; the program holds names only | that origin |

Where could the choice be written?

```avra
// 1. on the asset
asset intro = "art/intro.mp4" at .cdn(media)
asset art = "art" { hero { at: .program } }

// 2. an annotation
@embedded asset logo = "art/logo.svg"

// 3. the app, once — deployment is source (P13)
app acme {
    targets: [.web, .ios]
    assets: .cdn(https("cdn.acme.dev"))
}

// 4. the manifest
[assets]  serve = "embedded"
```

**Recommended: the target decides, the app says the deployment once, an asset overrides.**

- Default by what the target can do: a server or a CLI → `.program` (one file deploys); an exported static site → `.bundle`; iOS and Android → `.bundle` (catalog, `res/`); a web icon sprite or a picture under 2 KB → `.inline`.
- The app names its CDN once (form 3). Form 1 is the override for the exception: a 40 MB video, a font that must never wait on the network.
- Not an annotation: an annotation's effect is its answer type, and `at` is already the language's word for a home. Not the manifest: a second place for a fact the app declaration owns.
- **The size rule.** The compiler moves an asset between `.inline` and a file by itself — nothing about deployment changes. It never moves one between `.program` and `.bundle` by itself: that changes what must be deployed. Over the `.program` budget is an error whose help writes the `at`.
- Moving a home is a semantic diff the build prints, as for `state`.

## 6. Fonts: two engines, often conflated

**The problem in numbers.** A variable Inter is about 850 KB as TTF (about 340 KB as WOFF2) and holds about 2,900 glyphs. A CJK face is 10–20 MB and 65,000 glyphs. A page of English shows 100–200 of them — tens of KB.

**Subsetting** is cutting the font file down to the glyphs that are needed. It rewrites tables; it draws nothing.

- The compiler can PROVE the glyph set of static text: every literal and settled value that reaches a text node, plus the digits and separators of number formats.
- It cannot know dynamic text (a user's name, a fetched post). So the face is cut into `unicode-range` SLICES: slice 0 is exactly the proven set and is preloaded; the others are fetched by the browser only when a character from them appears. Nothing breaks, and first paint needs one small file.
- A face whose every text node is settled ships as its exact subset on every target. A bundled target with dynamic text ships the ranges the app declares (`covers:`), default the whole face.

**Shaping** is turning text into positioned glyphs: which glyph for each character, ligatures (`fi`), kerning, marks stacked on letters, Arabic letters joining, Indic syllables reordering, emoji sequences, right-to-left runs. It is what MEASURING text means, so it is what avra-8sb5.59.36 and the one layout engine (.44.9) need wherever the target draws its own text. The browser, CoreText and Android each have one; only a bare drawn target does not.

| | written in Avra | HarfBuzz as package C |
|---|---|---|
| **subsetting** | `cmap`, `glyf`/`loca` (+ composite closure), `hmtx`, `maxp`, `head`, `OS/2`, `name`, `post`; closure through `GSUB`; `gvar`/`HVAR` for variable faces. About 1.5k lines if glyph ids are KEPT (unused glyphs emptied, layout tables untouched — right for every script by construction); 4–6k more to renumber and prune `GSUB`/`GPOS`. Breaks first: pruning for complex scripts, CFF outlines. Prior art: fontTools' subsetter is about 4k lines of Python on a large table library; hb-subset about 30k of C++. | exact and complete today; a C++ dependency of the BUILD only |
| **shaping** | Latin, Greek, Cyrillic, CJK: `cmap`, `GSUB` ligatures, `GPOS` pairs and marks — 3–5k lines. Then bidi (UAX #9), line breaking (#14), graphemes (#29), Arabic joining, Indic, the Universal Shaping Engine. A full port is the size of rustybuzz: about 35k lines. Breaks first: Arabic, Indic, emoji sequences. | complete; about 1 MB linked into every drawn-target app |

**Is build-time use different from run-time use under P14?** Yes. P14 is about what a PROGRAM must carry to run. A subsetter runs in the build and leaves nothing in the product — it is a compiler dependency, as LLVM is. A shaper on a drawn target is in the product: that IS a runtime, and it must be ours or the platform's.

**Recommended.**

- Subsetting: ours, in Avra. It is table surgery, bounded, deterministic, and keeping glyph ids makes the first version correct for every script.
- Shaping: the platform's wherever one exists (zero bytes); ours on the drawn target, growing script by script. Text in a script the shaper does not cover is refused at compile time when settled, and named in the receipt as uncovered when dynamic — never drawn wrong silently. HarfBuzz is an opt-in fetched package for a drawn-target app that needs a complex script before ours covers it.

| stage | ships | needs |
|---|---|---|
| 1 | `.System` by default; a bundled face whole, as WOFF2 | table readers (metrics, coverage, licence), brotli |
| 2 | `unicode-range` slices; slice 0 = the proven set | the id-keeping subsetter; the glyph-set proof |
| 3 | exact subsets, pruned layout tables | renumbering and `GSUB`/`GPOS` pruning |
| 4 | measured and drawn text on the drawn target | the simple-script shaper, then bidi and complex scripts |

Metrics (stage 1) are static data from the day a face is declared, so layout over a bundled face is the same in a test, on a server and on a drawn target.

## 7. What the compiler proves

| fact | provable | not provable → what happens |
|---|---|---|
| a file is used | exactly, per member, when every read is `folder.member` | a folder value that escapes whole ships whole; `explain` names the site |
| drawn sizes | a use whose box is settled → that size at 1x/2x/3x | a fluid use → a width ladder capped at the source; `sizes:` narrows it |
| first paint | the view evaluated at build with default state gives the initial tree | "above the fold" — there is no viewport at build; `priority:` overrides |
| glyphs | §6 | §6 |
| a dead variant | a mode the program never constructs, a locale it does not list | mode from app state → both ship |
| a budget | bytes per artifact, first paint, total per target, `.program` | — |

## 8. Hatches

- `hero@3x.jpg` beside `hero.jpg`, or `hero { avif: "hero.avif" }` — a hand-made file wins over a generated one.
- `raster: true`, `recipe:`, `covers:`, `license:`, `at:` in the block; `priority:`, `sizes:` at the use.
- `remote(url, w, h)` and `asset x: Blob = "…"` — the raw doors, visibly the exception.
- `avra explain <asset>`; `avra expand` shows a folder as the record it is.

## 9. Rejected

- **A word per kind, a literal at the use, a silent `assets/` convention** — §0.
- **A folder as an `enum`** — a value built from data makes every member reachable; a record member cannot be minted from text.
- **Kinds built into the compiler** — a package could not add one.
- **A bundler outside the compiler** — it cannot know reach, drawn sizes or glyphs.
- **Public names from output bytes** — unknown until an encoder ran, so `check` and the server/client agreement would wait on it.
- **`Accept`-negotiated formats** — a varying response per URL; `<picture>` keeps every file immutable.
- **`data:` URI placeholders** — widens CSP and the `Url` type; a CSS gradient does it in 40 bytes.
- **An icon font** — no proof an unused glyph is absent, private-use characters reach screen readers, one colour, a flash while loading.
- **Words on the file (`alt` default)** — two sources for one fact, and not localisable.
- **Variants read from filenames (`-dark`, `-ja`)** — behaviour from spelling; `@2x` is the one exception, by law 4.

## 10. Defects found while probing

- PROBED: `embed("../../../../../../../../../etc/hosts")` and `embed("/etc/hosts")` compile and answer 256 — any package's const can bake a build-machine file into a binary. Law 5 holds for `embed` too.
- PROBED: a missing or non-UTF-8 `embed` is an unlocated trap, not a diagnostic at the literal.
- PROBED: `const N: int = embed("img/a.txt").length` alone traps the compiler ("a `File` write moved the whole relation after a compiler query … read it").

## 11. For the owner

1. **`asset name = "path"` over a file or a folder, kind from the bytes.** Recommended. It replaces `picture`/`icons`/`typeface`.
2. **`@2x`/`@3x` as the one filename the compiler reads.** Recommended — design tools write it; everything else is said in the block.
3. **Fetching starts here**: a toolchain-held pin, HTTPS + `sha256`, `avra.lock`, `~/.avra/cache`, `--frozen`. Recommended as the minimum; it is also the first step of the package transport, so say if that should be designed as its own campaign first.
4. **Homes**: target default, the CDN named once in `app`, `at` on an asset as the override; `.program` ↔ `.bundle` never switches by itself. Recommended.
5. **HarfBuzz as an opt-in fetched package** for complex scripts on the drawn target until our shaper covers them. Recommended over refusing those scripts outright.

## 12. Build order

1. `embed`'s path law and located refusals (§10).
2. The `asset` declaration over a file: octets as a build input, `trait Asset`, `Picture` at check, `image`/`icon` take it, `remote`, alt-or-decorative, html/tui/headless, dev serving.
3. `collect … reached`, `project()` + `Artifact`, `target()`, the receipt, `avra explain <asset>`.
4. Web projection: keyed names, `assets_route()`, placeholders, CSP; homes `.program`/`.bundle`/`.inline`.
5. A folder as a record, per-member reach, the block; the `Vector` model, the sprite, tint, mirroring.
6. `Typeface`: metrics as static data (unblocks avra-8sb5.59.36), licence and `fsType`, `Face` in the theme, metric-matched fallback — font stage 1.
7. Raster pipeline: `@std/image`, density and width variants, `srcset`/`picture`, mode/locale variants, budgets into the size gate.
8. Fetched pinned packages; `@std/icons` with native mappings; `avra add`.
9. Proofs: drawn sizes, initial-tree priority; font stages 2 and 3.
10. Apple and Android projections; `at .cdn` and `avra deploy`.
11. Email, terminal graphics, the drawn target and font stage 4, service-worker precache.
