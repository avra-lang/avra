# UI assets and packaging — the design

> 2026-10-05. Base `0718345`. Ticket `avra-8sb5.59.44.11`. Design only.
> Claims about today's compiler are marked PROBED (result quoted) or ASSUMED.

## 0. What an author writes

```avra
// src/art.av — the app's assets. Each is a DECLARATION.
use @std.assets.{picture, icons, typeface, variant}

export picture logo { source: "art/logo.svg" }

export picture hero {
    source: "art/hero.jpg"
    variant { mode: .Dark, source: "art/hero-dark.jpg" }
    variant { width: .Compact, source: "art/hero-tall.jpg" }
}

export icons glyph {
    source: "art/icons"                  // every .svg there is a member
    mirrored: ["arrow-left", "arrow-right"]
}

export typeface inter {
    source: "art/Inter.var.ttf"
    license: "art/OFL.txt"
}
```

```avra
// src/app.av
use art.{logo, hero, glyph, inter}
use @std.ui.components.{image, icon, button, column, text}
use @std.ui.style.theme.{default_theme, dark_theme}

export const brand = default_theme with { face: {
    "body": .Bundled(inter),
    "heading": .Bundled(inter),
    "footnote": .Bundled(inter),
    "mono": .System(.Mono),
} }

fn view() -> View {
    column {
        image logo { alt: "Acme" }
        image hero { decorative: true }
        button "Close" {
            icon glyph.close {}
            on press { shut() }
        }
        icon glyph.arrow_left { name: "Back", tone: .Muted }
        image remote(https("cdn.acme.dev/u/42.jpg"), 96, 96) { alt: user.name }
    }
}
```

## 1. The laws

1. **An asset is a declaration.** `picture`, `icons`, `typeface` (and `sound`, `video`, `blob`) are component words; an instance has a name, a module, an `export`. Imports, namespacing, the package graph and `explain` are the language's own, not an asset system's.
2. **No asset is found by text.** The only way to hold a `Picture`/`Icon`/`Typeface` is to name its declaration. There is no `by_name("close")`. So the declarations a program reaches are EXACTLY the assets it can show.
3. **A path appears once, as a literal, in the declaration.** It is read relative to the declaring file and must stay inside the declaring package: no `..` out, no absolute path, no symlink out. A missing file, a wrong kind and an unreadable file are compile errors at that literal.
4. **The kind is the word, never the extension.** `picture` decodes what the bytes ARE (magic number) and refuses a file that is not a picture; a `.png` name on a JPEG is fine and a `.png` name on a script is not.
5. **The handle is neutral; the reference is the target's.** The tree carries a `Picture` — an id plus what holds on every target (intrinsic width, height, dominant tone, vector or raster). What a target writes (`srcset`, a catalog name, a resource name, nothing) is read from that target's ASSET TABLE by its lowering.
6. **Bytes the build has are an asset; a name for bytes someone else has is a `Url`.** `remote(url, width, height)` is the exception, spelled: it states its size, is never transformed, shipped or precached.
7. **Layout never jumps.** Every picture a tree carries has an intrinsic size — computed for an asset, stated for a remote.
8. **Checking never transforms.** `avra check` reads headers and settles handles; only `build` runs an encoder. An artifact's public name is its KEY (source bytes ⊕ recipe ⊕ codec version), so the table is known before any pipeline runs.
9. **Key, cache name and public name are one derivation.** `.avra-cache/assets/<key>` holds the bytes; `<stem>.<key8>[-<w>].<ext>` is the file a target ships.
10. **Only what is reached ships, and only at sizes that are drawn.** An unreached declaration costs zero bytes on every target.
11. **An image says its words where it is used.** `image` takes `alt: "…"` or `decorative: true` — exactly one. The asset carries no words (words are the use's and the locale's).
12. **A variant is the asset's; the choice is the environment's.** The axes are the library's closed enums (`Mode`, size class, locale, direction). Density is generated, never declared — except as a hand-made override.
13. **Tint is a token.** An icon is drawn in the tone the use names (default: the text tone). A multicolour mark is a `picture`.
14. **A vector is parsed into a model with no unsafe shape** — paths, fills, gradients, groups, transforms. No script, no `foreignObject`, no external reference, no event attribute, no `<style>`. Each target WRITES from the model; none sanitises.
15. **A font is licensed or refused.** `typeface` requires `license`; the font's own embedding bits (OS/2 `fsType`) are read and a restricted face is refused for a target that embeds it.
16. **No silent downgrade.** A format a target asked for that this build cannot make is an error naming the tool and the row to change.

## 2. The value at run time

| type | value | where the target's half lives |
|---|---|---|
| `Picture` | `.Bundled(id, width, height, tone, vector)` or `.Remote(url, width, height)` | target table row: candidates (name, width, format) per variant |
| `Icon` | `id`, `mirrored` | web: symbol id · Apple: catalog or SF name · Android: drawable name · terminal: a cell |
| `Typeface` | `id` + `Metrics` (em, ascent, descent, cap/x height, advances, kerning) | web: `@font-face` rules · native: bundle/res name |
| `Sound`, `Video`, `Blob` | `id`, byte length | one copied file per target |

- Handles are settled consts: static data, no allocation, no I/O.
- The table is one settled list per target, holding only reached rows. `Attribute.Src(url: Url)` becomes `Attribute.Picture(Picture)`.
- Two builds of one program (server, wasm client) agree by the public NAME, never by a row number.

## 3. Kinds

**Raster** (`picture` over PNG, JPEG, WebP, GIF)
- At check: kind by magic number, width × height from the header.
- At build: dominant tone and a 3-stop gradient placeholder (CSS, not a `data:` URI); resized variants; re-encoded formats.
- Accepted sources are formats every dev target shows as-is, so dev needs no transform.

**Vector** (`picture` over SVG)
- Parsed to the `Vector` model at check; an element the model lacks is refused by name, at the declaration.
- `raster: true` on the declaration is the hatch: the build rasterises it and it becomes a raster asset.

**Icons** (`icons` over a directory of SVG)
- The instance is a settled record, one `Icon` field per file: `glyph.arrow_left`. Stem → field: `-` becomes `_`; a stem that is no name, or two that collide, is refused naming the files.
- A typo is the ordinary unknown-field error, which lists the members.
- `mirrored: [...]` names stems (checked against the directory) that flip under RTL; every platform has a native flag for it.
- `@std/ui_icons` is the library's own vocabulary (~60 semantic names) with per-platform mappings (SF Symbols, Material) and an SVG for everything else; an app set may add `apple: {...}` mappings.
- Not an icon font: no proof an unused glyph is absent, private-use characters reach screen readers, one colour only, a flash while it loads, nothing when fonts are blocked.

**Fonts** (`typeface` over TTF/OTF/WOFF2, variable or static; `face { weight: 700, source: … }` children for static families)
- At check: metrics, coverage (`cmap`), axes, `fsType`, name and licence strings.
- `Theme.face` holds `Face`: `.System(generic)` or `.Bundled(typeface)`. The family-list string goes.
- Metrics are static data the one layout engine reads (avra-8sb5.59.36, .44.9): the same line breaks in a test, on a server, on a drawn target. `.System` has no metrics at build — a non-web target then asks the platform, and build-time layout proofs are off for that face.
- Web fallback is metric-matched: `size-adjust`, `ascent-override`, `descent-override` computed from the metrics, so the swap moves nothing.
- Subsetting: §6.

**Sound, video, blob** — the same handle, table and laws with no transforms: read, keyed, copied. A new kind is a new component over the same doors (§5), in any package.

## 4. Every target

| target | pictures | icons | fonts | table row holds |
|---|---|---|---|---|
| web page (wasm) | `assets/<name>` files; `<img width height srcset sizes>`, `<picture>` for formats and art-directed variants; tone/gradient background until loaded; first initial-tree picture `fetchpriority=high`, the rest `loading=lazy` | inline `<svg><use>` against one sprite of reached symbols (inlined under 8 KB, else `assets/icons.<key>.svg`); `currentColor` | `@font-face` + `unicode-range` slices, WOFF2; the core slice preloaded | names, widths, formats; the wasm carries NO pixel bytes |
| server HTML | the same markup from the same table; `[web] origin` makes names absolute for feeds and `og:image` | the sprite inlined in the document | `<link rel=preload>` for faces of the initial tree | same |
| email | one PNG/JPEG at 2x, absolute URL (no origin → refused), `width`/`height` attributes; no `srcset`, no WebP, no SVG (vectors rasterised) | rasterised | system faces only; a bundled face is refused for this target | absolute names |
| terminal | `[image: alt]`; under a graphics capability (kitty, sixel) a cell-sized variant, opt-in per app — otherwise zero bytes | the icon's `cell` character, else its name | none | cells; opt-in pixel payload |
| iOS / macOS | `Assets.xcassets` image sets: 1x/2x/3x PNG/JPEG, SVG with preserved vector data, appearance (dark) and locale variants as catalog variants | catalog template images; mapped names use SF Symbols; RTL flag set | files in the bundle + `UIAppFonts`; sizes go through Dynamic Type metrics | catalog and font names |
| Android | `res/drawable-{m,h,xh,xxh,xxxh}dpi/*.webp`; `-night`, `-ldrtl`, locale qualifiers for variants | `res/drawable/*.xml` VectorDrawable written from the model, `autoMirrored` | `res/font/*` + family XML | resource names, resolved once at start |
| drawn (canvas, GPU) | variants at drawn sizes in a trivially decoded format (QOI-class) | path data in the binary, filled by the target | the font file + that target's rasteriser; a build-time atlas for the static glyph set later | offsets into the bundle |
| headless (tests) | the handle itself: `image logo alt="Acme" 120×40` | name | metrics only | nothing |

**Web serving.** `assets_route()` (`@std/http`) answers from the table — a name not in it is a 404 without touching the disk, so there is no path to traverse. `Cache-Control: public, max-age=31536000, immutable`. CSP stays `img-src 'self'; font-src 'self'`; a settled remote host must be listed in `[web] img_hosts` or it is a compile error.

**`avra dev`.** One candidate per asset: the source file, at `/@asset/<package>/<path>`, `no-cache` + ETag. No hashing, no variants, no encoder. A changed file re-settles its handle (the size may have moved) and reloads that node.

**Offline.** Web: the service worker's precache list is the table's eager rows; names are immutable so the cache only appends. Native: bundled. A `remote` is never precached.

## 5. The pipeline is a projection

Assets are a LIBRARY (`@std/assets`, `@std/image`) over general compiler doors. Three exist, four are new.

| door | state |
|---|---|
| a component instance is an exported declaration | PROBED: `export picture logo { source: "img/a.txt" }` imports by name and reads `logo.source`; a misspelt import is `resolve.not_exported` with "its exports: logo" |
| `const` settles records from file bytes at compile time | PROBED: `const logo: Pic = Pic { w: B.at(0), h: B.length }` over an embedded file's bytes prints `6 104` |
| `collect … in closure` gathers declarations program-wide | ASSUMED for a component word across packages (`collect … in self` is used by `@std/sql`) |
| `embed_bytes("literal") -> Bytes`, `listing("literal dir") -> List<string>` | NEW. PROBED: `embed` is text-only — a PNG traps "is not UTF-8 — byte 0", unlocated; a const may read nothing else (`const.reach`) |
| `collect … reached` — only members the program reaches, and the collection itself roots none | NEW (today "collected means reachable") |
| `fn project() -> List<Artifact>` — the build writes; an artifact is `{ name, key, make: fn() -> Bytes }` and `make` runs only on a cache miss | NEW. PROBED: no `Artifact` or `project` in the tree (designed in COMPONENT_EXPANSION §11; assets are its first consumer) |
| `target()` — a settled value may depend on the build target, folded into its key | NEW. PROBED: absent from `@std/meta` |

- **In tree** (`@std/image`, vendored C under the package-C standard, run in the build's own process): PNG/JPEG/WebP/GIF decode, resample, PNG and WebP encode, WOFF2 (brotli and zlib are already vendored — PROBED, `@std/compress`). In Avra: header readers, the SVG → `Vector` parser and its writers (inline SVG, VectorDrawable), font table readers.
- **Delegated**, each a `[process.tools]` row pinned by version AND digest: AVIF (`avifenc`), the Apple catalog compiler (`actool`, already owed by that target). Absent or wrong digest → an error naming the row; never a fallback format.
- **Determinism.** No timestamps, sorted members, fixed settings, single-threaded encoders. The codec package's fingerprint is in every key. `build/<target>/assets.json` is the receipt: every artifact, its key, its output digest, its licence.
- **Cache.** Keys are target-neutral (a 480-wide WebP is one file for web and Android), so targets share `.avra-cache/assets/`.
- **`[assets]`** in the manifest holds only policy: formats per target, budgets, `serve = "embedded" | "beside"`. PROBED: today `manifest.unknown_section`, ignored.

## 6. What the compiler proves

| fact | provable | not provable → what happens |
|---|---|---|
| an asset is used | Always, exactly (law 2). For an icon set: per member when every read is `set.member`. | The set value itself escapes (stored, passed whole) → the whole set ships; `explain` names the escaping site. |
| the sizes a picture is drawn at | A use whose box is settled (literal or token width/height) → exactly that size at 1x/2x/3x. | A fluid use → a width ladder capped at the source and at the widest breakpoint's column; `sizes: …` on the use narrows it. |
| a picture is in the first paint | The view evaluated at build with default state gives the initial tree, in reading order. | "Above the fold" — no viewport at build. The first initial-tree picture is prioritised; `priority:` on the use overrides. |
| the glyphs a face needs | Code points of every settled text that reaches a text node — literals, consts, digits and separators of number formats. | Any text node in that face with unsettled content → web: the static set is slice 0 (preloaded), the rest ships as `unicode-range` slices fetched on demand; bundle targets ship the declared `covers:` ranges (default: the whole face). |
| a face needs no slices at all | Every text node in it is settled → the exact subset on every target. | — |
| a variant is dead | A theme mode the program never constructs, a locale it does not list. | Mode from app state → both ship. |
| a budget holds | Bytes per artifact, first-paint bytes, total per target — at build. | — |

Budgets: `[assets] first_paint`, `total` per target, and `budget:` on a declaration. The size gate (avra-8sb5.59.44.3) reads the receipt; a breach names the artifact and the uses that forced it.

## 7. Hatches

- `variant { density: 3, source: … }`, `variant { format: .Avif, source: … }` — a hand-made file wins over the generated one.
- `raster: true`, `recipe: { quality: 82, formats: [.Webp] }`, `covers: [.Latin, .Greek]`, `priority:`, `sizes:` — per declaration or use.
- `remote(url, w, h)` and `blob` — the raw door, visibly the exception.
- `avra explain <asset> [--target t]` — every artifact, the use that asked for it, what was not made and why.
- `avra expand` shows an `icons` instance as the record it is.

## 8. Rejected

- **Generated handles with no declaration (R.swift, Flutter gen)** — names from nowhere, no place for variants or licence, behaviour read from filename spelling (`@2x`, `-dark`).
- **A checked path literal at the use (`asset("logo.png")`)** — the path repeats at every use; kind sniffed from the extension; nothing to `explain`.
- **A file as a module (`use art.logo`)** — the kind and every option would have to come from the filename.
- **An icon set as an `enum`** — a value of the enum built from data makes every member reachable; a record of consts cannot be minted from text.
- **Assets as a compiler feature** — a second mechanism beside components, `collect` and consts; a third party could not add a kind.
- **A bundler step outside the compiler** — it cannot know reach, drawn sizes or glyphs, which is the whole edge.
- **Public names from output bytes** — the name would be unknown until an encoder ran, so `check` and the server/client agreement would wait on it.
- **`Accept`-negotiated formats** — a varying response per URL; `<picture>` keeps every file immutable.
- **`data:` URI placeholders** — widens CSP and the `Url` type; a CSS gradient does it in 40 bytes.
- **Icon fonts** — §3.
- **Fetching at build** — no network in a build. `avra assets add <url>` copies the file in and records origin and digest in the declaration.
- **Words on the asset (`alt` default)** — two sources for one fact, and not localisable.

## 9. Defects found while probing

- PROBED: `embed("../../../../../../../../../etc/hosts")` and `embed("/etc/hosts")` both compile and answer 256 — any package's const can bake any file on the build machine into a binary. Law 3 fixes it for `embed` too.
- PROBED: a missing or non-UTF-8 `embed` is an unlocated trap (`avra: … does not exist`), not a diagnostic at the literal.
- PROBED: `const N: int = embed("img/a.txt").length` alone traps the compiler: "a `File` write moved the whole relation after a compiler query (reader 494) read it".
- PROBED: `picture hero { source: "a", alt: "x" }` on one line is `parse.expected` at the comma — instance settings are one per line.

## 10. For the owner

1. **Assets as a library over general doors (§5), not a compiler feature.** Recommended. Cost: four doors land before the first picture ships; gain: every later kind, and every other projection, is free.
2. **The words: `picture` / `icons` / `typeface` / `sound` / `video` / `blob`,** distinct from the view words `image` / `icon`. Recommended as written.
3. **Does std ship art?** Recommended: `@std/ui_icons` (the semantic vocabulary with platform mappings) and `@std/ui_face` (one OFL variable face, so drawn targets and build-time layout have metrics by default). Each linked only when named.
4. **Server bytes: in the binary or beside it?** Recommended: embedded by default (one file deploys), `serve = "beside"` when asked or when `total` is over budget.
5. **Font subsetting engine.** Recommended: v1 ships whole WOFF2 files; slices come with a subsetter written in Avra for TrueType outlines, and CFF faces ship whole until someone needs them. The alternative is vendoring HarfBuzz, which avra-8sb5.59.36 may want for shaping anyway — decide the two together.

## 11. Build order

1. `embed` path law and located refusals (§9).
2. Doors: `embed_bytes`, `listing`.
3. Doors: `collect … reached`, `project()` + `Artifact`, `target()`, the receipt, `avra explain <asset>`.
4. `picture` v0: kind and size at check, `Picture` in the tree, `remote`, the alt-or-decorative law, html/tui/headless, dev serving.
5. Web projection: keyed names, `assets_route()`, embedded/beside, placeholders, CSP.
6. `Vector` model and `icons`: the parser, sprite, tint, mirroring, per-member reach, `@std/ui_icons`.
7. `typeface`: metrics as static data (unblocks avra-8sb5.59.36), licence and `fsType`, `Face` in the theme, metric-matched fallback.
8. Raster pipeline: `@std/image`, density and width variants, `srcset`/`picture`, mode/locale/size-class variants, budgets into the size gate.
9. Proofs: drawn sizes, initial-tree priority, glyph sets and slices.
10. Apple and Android projections.
11. Email, terminal graphics, the drawn target, service-worker precache.
