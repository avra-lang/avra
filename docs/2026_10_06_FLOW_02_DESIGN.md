## 1. The seam in C — the seeded path lives in the cold half, so a production switch is unchanged
- SEEDED, the scheduler holds `g_until_poll` at 0. `queue_alone()` then fails by the test it already makes (f:1118-1119) and every switch goes to `next_with_world`, where `ready_pop()` becomes `g_seeded ? ready_picked() : ready_pop()`. Nothing but the row sets the flag. MEASURED and PROBED twice: yield 68 instructions before and after, park 59, gate claim 6, switch 33, sleep 4, join 96, spawn 199 — 0 lines differ. PR 1 publishes x86_64.
- THE POLLER KEEPS ITS OWN COUNT THERE: seeded, a second counter falls once a switch and the poller is asked every 64 switches while a descriptor waiter is filed, as unseeded (f:434-441). Never a poll per switch (PROBED on v1: 40004 polls in 40000 switches).
- THE PICK IS BOUNDED: among the first 16 of the queue, so at most 16 links are walked whatever is ready (PROBED on v1's whole-queue pick: 609,706 ns a switch at 20,000 ready). A task deeper than 16 enters the window as the queue moves; nothing is starved, and with over 16 ready not every order is reachable.
- The rows live in `avra_fiber.c`: a seeded run has tasks. (v1's hook in `avra_runtime.c` is gone.)
## 2. How a schedule maps to an order, and why two engines agree
- `ready_picked()`: `n` = how many of the first 16 are ready; `n < 2` pops and COUNTS NOTHING; else one CHOICE in `[0, n)` is taken and that one leaves the queue. SCHEDULE 0 always chooses 0 — FIFO, with its choices counted. SCHEDULE k > 0 chooses `(splitmix64(state) × n) >> 64`, state seeded with k.
- A PICK AMONG ONE IS NO CHOICE: a compiled yield with an empty queue returns without asking (f:1512-1513) where the evaluator readies itself and asks (it:222-225). Both then make the same choices.
- A TIMER'S TASK TAKES PART IN NO PICK, IN EITHER ENGINE (blocker 4). Natively it never does. On `flow-01b` the evaluator holds it as a virtual task the policy names (it:334-336), so it stands in the queue: PROBED, 20 of 400 seeds agree. THE FIX IS THE EVALUATOR'S: its timer task becomes the runtime's own fiberless task (`avra_task_at`), waited on through its gate, and the machine reads its end from the gate. PR 5 does that AFTER 2a merges. PR 1's C test drives virtual tasks that way and must read 400 of 400 with a timer task and a fiberless task in the scenario.
- NOT SEEDED: a gate claims its FIRST waiter (f:1277-1284), equal timers fire in the order asked (f:380-381), `select`'s arm turn (slice 04). A spawn is not a switch (f:1355).
- THE REAL EVALUATOR'S AGREEMENT IS UNPROVEN until PR 6's program tests; PR 1 claims the C level only.
## 3. What `avra test` runs (ruled)
- SCHEDULE k USES SEED k FOR EVERY CASE. No label hash, no position: renaming a case changes nothing.
- A case runs schedule 0 first. NO CHOICE MADE → it has one order and runs ONCE. Else it runs N schedules: every order when the choice tree is small enough to walk in N runs (the runner feeds a path of choices, depth first), else schedules 1 … N−1. Default N = 8; `AVRA_SCHED_RUNS=<n>` raises it; `AVRA_SCHED_SEED=<k>` runs schedule k alone. The same on every machine, so no train flakes.
- A failure names the case and k: `✗ <case> — schedule 5: AVRA_SCHED_SEED=5 avra test <path>`. PR 4a publishes what N = 8 costs the std-http and std-net suites in wall time.
- EACH CASE'S BODY RUNS IN ITS OWN TASK and the runner waits on its end. DEADLOCK FAILS ONE CASE: "nobody ready, nothing can wake one" claims the runner, which prints each task (id, spawn site, what it waits on) and the schedule, abandons the case's tasks as a leak does, and goes on. No process-ending trap in `avra test`; `avra run` keeps today's trap (f:1107). The case's task gets a stack the size of the main thread's, one reservation reused: spec bodies recurse far past 256 KiB.
## 4. Rows — `Unhosted`, word seats only, `reach: World`, `wasm: false`
| row | seats | answer | PR |
|---|---|---|---|
| `avra_sched_seed` | schedule: I64 | Void: order follows the schedule from now | 1 |
| `avra_sched_settle` | — | I64: the seeded run ends, order is FIFO again; how many choices it made | 1 |

- TWO RUNGS for these: the row with its C body, then a declaration. A word-seat declaration checks clean even on a compiler that has never heard of the row (flow-01b's addendum L1, MEASURED there). NONE IS AN ARM: each only sets scheduler state. The native runner declares nothing; its entry is built in IR (`suite_entry.av:18-21`).
- THE REPORT IS NOT A ROW IN THE EVALUATOR (blocker 5). The machine reports its own leak and deadlock, over its `Job`s, at the run's end and before `retired()` frees them; C abandons fibers only. Natively the runner's C does both.
- THE SEED AND THE CLOCK ARE STATE OF THE RUN UNDER TEST. A native suite's process IS the run. The evaluator's machine saves the scheduler's seed state and the clock when a run begins and puts both back when it ends, so the compiler's own clock never jumps and never freezes; a leak is a task made SINCE the run began.
- TASK IDS ARE NEVER REUSED IN A PROCESS. The counter stands (f:265); a report prints ids relative to the case's first spawn.
## 5. The virtual clock — one reader, frozen unless the world is held
- ONE CLOCK: `avra_now_ns` is `frozen` when frozen, else `real + skew`; the scheduler's `now_ns` calls it. In a native suite it never goes back: `"/tmp/…/${now_ns()}"` names (`idioms.av:1537`) stay unique. MEASURED: 23.3 ns a read against 23.0, 13 → 23 instructions; PR 2 gates `yield_under_within` against main.
- FROZEN, TIME MOVES ONLY BY A JUMP: nobody ready, no descriptor waiter filed, a timer filed → the clock is set to the earliest timer. MEASURED: sleeps of 60, 30 and 90 s moved the clock 90000 ms in 1 µs of wall time.
- THE CLOCK FLOWS AT WALL RATE WHILE THE WORLD IS HELD. A hold is a count: the scheduler takes it across a poller wait with a descriptor waiter filed; package C that waits outside the scheduler takes it too (`avra_clock_hold`, C only) — `@std/process` from spawn to reap (`process.av:1084` never ends on a frozen clock; `std_process.c:490`) and a file watch from open to close, with a keeper over every `poll(`, `nanosleep(`, `kevent(`, `epoll_wait(` in package C. MEASURED: a pipe reader under a 5 s limit beside a 60 s sleeper woke by the pipe at wall +51 ms, clock +51 ms.
- A HOLD AN ABANDONED TASK TOOK IS RELEASED AT SETTLE, and the failure says so; else every later sleep in the suite is real.
- A TASK THAT WAITS ON THE CLOCK WITHOUT SLEEPING TRAPS BY NAME (PROBED: it hangs). The count of reads of a frozen clock is EACH TASK'S OWN and begins again when that task parks; the limit is a setting, `AVRA_CLOCK_ASKS` (0 = never), named in the trap's words. It is a watchdog, not a law: nothing separates waiting on time from reading time while working, so a task that reads the clock that often and never waits is told the same. A virtual clock pins the switch to its slow half, where a parking task's count is cleared — so no park gains an instruction.
- OWED AT STEP 4b: frozen, `"…/${now_ns()}"` gives the SAME name twice inside one case (the sweep finds each); slice 03's tick must be COUNTED, not timed, while the clock is virtual; a jump inside an evaluated run also fires a timer the compiler's own tasks filed before it — harmless while the host parks no task during a run, and said where the run brackets are called. A case's settle drops ALL holds, live ones included (no task holds one before 4b); at 4b it drops only the abandoned tasks' share.
- TWO LIMITS, stated: a server test keeps a descriptor waiter filed for the whole case, so its sleeps stay real; and computing takes no time, so a handler that computes past its deadline is never timed out. Hatches: `AVRA_CLOCK=real` for a suite, a per-case marker (PR 4b decides its spelling).
- 81 `sleep(` calls stand in 39 test files of 8 packages; one that sleeps for an UNHELD outside thing fails when the sleep takes no time. PR 4b finds them on CI.
## 6. G2 — over the waiters the scheduler already holds
- THE REPORT, one line a task: id, spawn site, each filed waiter (`joins task N`, `gate <addr>`, `task N's end`). MEASURED on the prototype: main and two tasks each parked on a gate print three lines.
- A LEAK: a task made since the run began and not done when it settles is named the same way, then ABANDONED — out of the queue, waiters retracted (as f:1633-1648), stack back in the pool, no `defer` run.
- THE EVALUATOR'S JOIN is filed with the evaluator (it:170-181); the machine's own report reads it there.
- PARTIAL DEADLOCK: TICKET `.23`(2) STAYS OPEN until slices 04 and 05 declare a gate's claimants. What this slice can prove: a gate whose reference count equals its filed waiters (f:1228) can never open. Sound, and it misses two tasks each holding the other's gate — which, with the runner waiting on the case, is reported anyway as TOTAL deadlock.
- SPAWN SITES print as unslid code addresses first (rt:255); PR 8 makes them `file:line`.
