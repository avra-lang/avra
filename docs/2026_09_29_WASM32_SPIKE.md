# wasm32 target — spike (avra-8sb5.59.9, P1.1)

Base: lane/ui-g at 0452787, `build/avra` of that tree. Every probe below
was run by hand from `/tmp/w`; commands and outputs are quoted.

## Verdict

**The hypothesis is right in shape and wrong in one place.** A program
that uses no fibers, cores, net or process builds to a `.wasm` and runs
under node's WASI with stdout identical to the native run. That works
today with three tiny, mechanical runtime edits and no design work.

The wrong place: **settled static aggregates** (a `const` list/map/enum,
a fn table) do not lower on wasm32. 17 of 48 sampled program tests hit
it; the other 31 passed byte-for-byte, and nothing else failed. So the
first slice is not "hello only" — it is "everything except statics",
and statics are the second slice, contained in one C file.

The slice is larger than a day inside this lane's rules: the target
must travel through `llvm_wrapper.c` (a C change to the compiler's own
binary, which only `make avra` rebuilds), the entry symbol, the CLI, a
per-target runtime archive, and a program test that runs node. Per the
brief this stops at the spike. The plan (section 5) is ordered so each
step lands green.

## 1. Where the target is decided (file by file)

`grep -rniE 'triple|datalayout|SetTarget|TargetMachine|GetDefaultTarget'`
over `backend packages/std-avrac/src packages/cli/src runtime Makefile`
finds the target in ONE place:

- `backend/llvm_wrapper.c` `object_written` (l.~906): the object is
  emitted in-process, `LLVMGetDefaultTargetTriple()` ->
  `LLVMGetTargetFromTriple` -> `LLVMCreateTargetMachine(target, triple,
  baseline_cpu(triple), "", cg, LLVMRelocPIC, …)`, then `LLVMSetTarget`
  and `LLVMSetModuleDataLayout`. Registration is `native_target_ready`
  (`LLVMInitializeNativeTarget`). The emitted **text** IR carries NO
  triple and NO datalayout: `head -5 hello.ll` shows `ModuleID`,
  `source_filename`, then globals.
- `hot_linked` (same file): links `avra_hot_bc` — bitcode of
  `runtime/avra_hot.c` compiled by the HOST clang — into the module and
  overrides its triple/datalayout with the module's. On wasm32 that
  bitcode carries 64-bit pointer layouts; it must be skipped (or a
  wasm32 bitcode carried).
- `packages/std-avrac/src/compiler/backend/llvm_api.av:89`
  `avra_llvm_emit_object_later(m, lc, path, opt, workers)` — the extern
  row; a triple argument must be added here and in the C body.
- `packages/std-avrac/src/compiler/backend/llvm.av:232` (`.Object(opt)`
  arm) is its one caller; `emit_entry` names the entry `main`.
- `packages/std-avrac/src/compiler/link.av` `link_objects`: `["-w",
  "-rdynamic"] + objs + package link words + [runtime, "-o", out]`;
  the linker is `linker()` = `tool_from_env("CC", "clang")`
  (`packages/cli/src/commands/shared.av:320`). No triple, no sysroot.
- `Makefile`: `RUNTIME_OBJS = $(patsubst runtime/%.c,build/%.o,
  $(wildcard runtime/*.c))` into `build/libavra_runtime.a`; one target,
  host only.

So `--target wasm32-wasip1` needs: the CLI flag; a triple threaded
through `avra_llvm_emit_object_later`; `LLVMInitializeWebAssembly*` in
the wrapper; a target-keyed entry name; a target-keyed link (`--target`
and `--sysroot` words, no `-rdynamic`, the wasm runtime archive); and a
wasm runtime archive rule.

## 2. The runtime C on wasm32

Command shape (script `cc.sh`): `clang --target=wasm32-wasip1
--sysroot=$WASI -I… -D_WASI_EMULATED_MMAN -D_WASI_EMULATED_SIGNAL
-ferror-limit=0 -O1`. Note: `--target=wasm32-wasi` (the brief's
spelling) finds no headers with this wasi-libc, whose directories are
`wasm32-wasip1`…: `avra_runtime.c:34:10: fatal error: 'stdio.h' file
not found`. Use `wasm32-wasip1` (LLVM triple `wasm32-unknown-wasip1`).

### avra_runtime.c (3214 lines) — (b), three edits

Errors, in the order the compiler reaches them, each fixed only in a
copy under `/tmp/w/rt`:

1. `sys/mman.h`: `error: "WASI lacks a true mmap; … compile with
   -D_WASI_EMULATED_MMAN and link with -lwasi-emulated-mman"` — clears
   with the flag and library (the mapped-file rows work over a read).
2. `fatal error: 'sys/wait.h' file not found`, `'spawn.h' file not
   found` — the host section `avra_spawn_status`, `avra_spawn_in`,
   `avra_exec_self` (and `avra_capture_begin/end`, `mkstemp`) is POSIX
   process code. With those includes stubbed the remaining errors were
   exactly `posix_spawnp`, `waitpid`, `WIFSIGNALED`, `WTERMSIG`,
   `WEXITSTATUS`, `posix_spawn_file_actions_*`, `execv`, `mkstemp` —
   22 errors, all in that section. Wrapping it in `#if 0` and adding
   three `-1` stubs (the rows `avra_rt.h` asserts) compiled clean.
   **(b)**: `#if !defined(__wasm32__)` around the section, and the
   three rows answer "unsupported" the way a refused cwd already does.
3. `__builtin_return_address`: `error: Non-Emscripten WebAssembly
   hasn't implemented __builtin_return_address` — 20 uses across
   `avra_runtime.c` and `avra_hot.c` (the accounting's call-site
   notes). **(b)**: one `AVRA_CALLER()` macro, `NULL` on wasm32. The
   census/guard instruments simply have no call sites there.
4. `getpid` deprecated warning (`-D_WASI_EMULATED_GETPID`, links
   `-lwasi-emulated-getpid`) — fine as is, (a).

Everything else — boxes, strings, maps, lists, floats, bytes, the once
cache, printing, `avra_trap` — compiled with no change, (a). Result:
`avra_runtime.o` 4.2 MB unlinked.

### avra_hot.c — (b), the one macro of item 3. Compiles after it.

### avra_cores.c — (c), out of slice

`fork`, `waitpid`, `WIFEXITED`… undeclared: it is a process per core
(CORES campaign). wasm has no fork; `isolated` makers and `cores` are
refused on this target by design (a diagnostic, not a stub).

### avra_fiber.c — (c), out of slice, needs a design

What it uses: HAND-WRITTEN ASSEMBLY for the switch (`avra_fiber_switch`
as top-level `__asm__` for `__aarch64__` and `__x86_64__`, l.~60-115,
`#error "the scheduler has no context switch for this architecture"`
otherwise), a kqueue/epoll poller (`#error "the scheduler has no
poller for this platform"`), `sigaction`/`sigaltstack`/`siginfo_t` for
the stack-guard fault handler, and `mmap`ed stacks with guard pages.
No ucontext. 34 errors on wasm32, every one a class of these.
wasm cannot switch stacks without the JS-promise-integration or
stack-switching proposals (or a binaryen asyncify pass); the design
path in WEB_UI §21 is right: `spawn`/`within`/`Tasks` on wasm become
compiler-generated state machines (or asyncify), and the socket poller
is the JS event loop. Nothing in this slice touches it: a program that
does not reach a fiber row does not link the object (proved by hello
linking without it).

### Package C

- `std_io.c` compiles as is (a).
- `std_net.c`: `fatal error: 'netdb.h' file not found` — wasip1 has no
  sockets. (c): net is the browser's `fetch`/WebSocket, a host import.
- `std_process.c`: `sys/resource.h` refused, `posix_spawn_*`
  undeclared. (c): no processes.

### libc's own need

Linking wasi-libc's `libc.a` alone fails `undefined symbol: __multi3`
(intscan.c, 128-bit multiply) because there is no compiler-rt builtins
archive: `wasm-ld: error: …/lib/clang/21/lib/wasm32-unknown-wasip1/
libclang_rt.builtins.a: No such file or directory`. The spike links
`-nodefaultlibs -lc -lm` plus an 8-line C `__multi3`. Landable answers,
in preference order: provision wasi-sdk/`wasi-runtimes` and document
it; or carry `__multi3` in a wasm32-only runtime file (it is what
compiler-rt would supply, and only libc's integer scan needs it).

## 3. IR by hand: hello and 55 program tests

The scratch package `/tmp/w/pk` (`avra.toml` + `src/main.av`) makes
`build/avra emit` sub-second; emitting inside `packages/std-avrac`
analyses the whole package (minutes under load) — not for probes.

```
fn main() {
    println("hello")
}
main()
```

Steps (script `try.sh`, per program):

```
build/avra emit /tmp/w/pk/src/main.av > p.ll
( printf 'target datalayout = "e-m:e-p:32:32-p10:8:8-p20:8:8-i64:64-i128:128-n32:64-S128-ni:1:10:20"\n
target triple = "wasm32-unknown-wasip1"\n'
  sed 's/define i32 @main(/define i32 @__main_argc_argv(/' p.ll ) > p.w.ll
cc.sh -c p.w.ll -o p.o                       # clean, no diagnostics
cc.sh -fuse-ld=wasm-ld -nodefaultlibs p.o avra_runtime.o avra_hot.o \
   stubs.o rt_stub.o -lc -lm -lwasi-emulated-mman \
   -lwasi-emulated-signal -lwasi-emulated-getpid -o p.wasm
node --no-warnings run.mjs p.wasm            # node:wasi, preview1
```

- The IR compiles as is for wasm32: `ptr` is opaque, ints are `i64`,
  the header is four `i32`. Entry must be named `__main_argc_argv`
  (wasi-libc's `crt1-command` calls that; clang renames `main` only in
  the C front end): otherwise `undefined symbol: __main_argc_argv`.
- hello: `hello.wasm` 38 432 bytes; `node run.mjs hello.wasm` prints
  `hello`, exit 0. (`ExperimentalWarning: WASI is an experimental
  feature` on stderr without `--no-warnings`.)
- A trap: `xs[9]` on a 3-list — native exit 2, wasm exit 2, both
  `before` then `avra: index 9 is out of bounds (length 3)`.
- 55 program tests from `packages/std-avrac/src/features/*/tests`
  (lists, enums, maps, closures, results, nullable, structs, loops,
  formats, bytes, cells; programs that `use`/`extern` skipped, 7):
  **31 stdout-identical to `avra run`, 17 failed to compile with one
  error class, 0 differed.** The 17:

  ```
  error: unsupported expression in static initializer:
    ptrtoint (ptr getelementptr inbounds nuw (i8, ptr @.str, i32 16) to i64)
  error: unsupported expression in static initializer:
    ptrtoint (ptr @"av_same$24w" to i64)
  ```

  (`lists/vocabulary`, `consts/{aggregate,static_map,static_shapes}`,
  `maps`, `closures/*`, `enums/{inline_payloads,value_enums_flat}`,
  `nullable/*`, `fns/borrowed_params`, `loops/pairing`, `cells`, …).

### Why statics fail, and what fixes them

`backend/llvm_wrapper.c` `avra_llvm_static_array`: a static box is one
global; its cells are an `[n x i64]` and a pointer cell (a string, a
child box, a fn address) is `LLVMConstPtrToInt(cell, i64)`. On wasm32 a
data relocation is 32 bits, so a constant `ptrtoint` to `i64` has no
encoding. The layout itself already mirrors: LLVM lays
`{i64, i64, ptr, ptr, ptr}` on wasm32 at offsets 0/8/16/20/24 exactly as
clang lays `AvraArray` there (`i64` aligns 8 in the datalayout above),
and `AvraMap` likewise. What is target-dependent and hard-coded on the
host: the `_Static_assert`s (`sizeof(AvraArray) == 40`, `AvraMap == 32`)
and the header length `(uint32_t)sizeof(AvraArray)` in
`header_const(… KIND_IMMORTAL(KIND_ARRAY) …)` — those become the
TARGET's sizes (32/24), read from the target data layout, not `sizeof`.
The cell: on a 32-bit target a pointer cell is emitted as the
little-endian pair `{ptr, i32 0}` in place of the `i64` word, so the
cell array becomes a packed-by-position struct rather than `[n x i64]`.
About 40 lines in one function, plus the two size constants.

## 4. Answer: the smallest landable slice

Confirmed with amendment. Slice 1: `avra build --target wasm32-wasip1`
for any program that reaches no fiber, core, net or process row and no
settled static aggregate. It writes a `.wasm` that runs under node's
WASI with native stdout. Slice 2: static aggregates (section 3). Both
need the same plumbing, so slice 1 is the whole plumbing and slice 2 is
one C function.

Why slice 1 must include the non-static programs and not just hello:
the measured split is 31/17, and hello alone would prove only that the
link works, not that the IR, runtime and libc agree for lists, maps,
enums, floats, bytes and results — which the 31 passing cases do.

Refusals slice 1 owes (spoken by the compiler, one named voice each, at
the declaration or call): a program that names `spawn`/`within`/`Tasks`,
`cores`/`isolated`, `@std/net`, `@std/process`, `@std/sqlite` on this
target. Today they fail at link (`undefined symbol`), which is the
"symptom accuses an innocent" shape.

## 5. Plan, in landing order

Every step is a normal gate-green landing; the generation ladder
applies to the C change in step 2 and the CLI in step 3 (the wrapper is
part of the compiler binary, so it reaches the product on the second
build).

1. Runtime, no compiler change: `AVRA_CALLER()` for the 20
   `__builtin_return_address` sites; `#if !defined(__wasm32__)` around
   the host section (spawn/exec/capture); a wasm32-only
   `avra_wasm_builtins.c` with `__multi3` (or provision the builtins).
   Native build is unchanged; the witness is `clang --target=wasm32-
   wasip1 -c` over `runtime/*.c` minus fiber/cores, in a tools script
   (`make wasm-runtime` -> `build/wasm32/libavra_runtime.a`).
2. Wrapper: a `triple` argument on `avra_llvm_emit_object_later` and
   its row in `llvm_api.av`; `LLVMInitializeWebAssemblyTargetInfo/
   Target/TargetMC/AsmPrinter`; `baseline_cpu` "" for wasm; skip
   `hot_linked` when the triple is not the host's (or carry a wasm32
   hot bitcode); target-keyed entry name in `emit_entry`
   (`__main_argc_argv`).
3. CLI: `--target <triple>` on `build`/`run`-less commands; `link_objects`
   takes the target's words (`--target`, `--sysroot` from
   `WASI_SYSROOT` else the std-root-relative default, no `-rdynamic`,
   `-nodefaultlibs -lc -lm -lwasi-emulated-*`, the wasm archive, and
   the output named `x.wasm`); `[link]` rows of packages whose C the
   target cannot build are refused by name.
4. Program test: a `.av` program plus `.expected` (its native output)
   and a test that builds it with the flag and runs `node` on the
   result, comparing stdout to the native run. Needs node on the PATH;
   skipped with a spoken reason when absent, never silently green.
5. Slice 2: the static cell pair and the target's box sizes.
6. Then, separately designed: fibers as state machines, and
   `@std/net` as host imports.

## 6. Sugar and doctrine notes from the spike

- The target is a property of the module (`LLVMSetTarget`) that the
  text emitter never writes; `avra emit` output is target-less, so a
  reader cannot tell what a `.ll` was for (P7). The slice should write
  the triple and datalayout into emitted text for every target.
- `avra emit` over a file inside `packages/std-avrac` analyses the
  package; a probe wants a "single file with the prelude" mode.
