## 1. The idea

1. A STREAM is a recipe for values over time. A SOURCE is one running.
   A SINK feeds one. `select` waits on several at once, and the
   compiler demands an arm for every end.
2. A running stream lives in ONE block, as a task does, and ends with
   it. Nothing counts references.
3. A DECLARED stream (`queue`) has a CONTRACT. Its home is bound per
   run: memory, the program's own store, another process, another
   machine. The compiler checks the home against the contract, and the
   effects its handlers reach against the delivery.
4. THE CONTRACT IS THE FAULT MODEL. `avra test --faults` derives its
   faults and its oracle from the terms.
5. A LAW says how it is known, and that word decides what it may
   license: a reshaped fold, an unordered home, a skipped key.

### False choices dissolved (P6)

| choice | what holds instead |
|---|---|
| sync / async | a wait parks the task; no colour (spec 13.4) |
| push / pull | `yield` pushes into a `for` that pulls; fused they are one loop |
| close by hand / leak | a running stream is owned by a block and ends with it |
| exactly once / at least once | a demand the compiler discharges per effect, or refuses |
| local / remote | one declaration; the home is bound per run and checked |
| thread / process | a process per core shares nothing, so a crash is contained by the kernel |
| test / production | the same program; the schedule, the clock, every bound home and every marked effect are the run's |
| deterministic / parallel | `reduce` is one fixed tree on one core and on sixty-four |

### 2.1 Two tasks, a bounded channel, backpressure — DESIGNED

```avra
use @std.task.{Sink, Source}

fn crawl(urls: List<string>, out: Sink<Page>) {
    for u in urls { out.send(fetch(u)) }    // parks while 8 pages wait
}

fn index(pages: Source<Page>) -> int {
    mut n = 0
    for p in pages {                        // ends when the producer is done
        store(p)                            // and the last page is taken
        n = n + 1
    }
    n
}

let pages = produce<Page>(8) { out -> crawl(seeds, out) }
let indexed = spawn index(pages)
println("${indexed.await} pages")
```

- `produce` runs its block as a task and answers the reading end. The
  channel ends when that block does. Nobody closes it.
- If the reader leaves first, the producer is cancelled; a `send` to a
  reader that left is a cancel point (§5.4), so even a producer that
  never waits stops there.
- NEW: `produce` (a primitive beside `spawn`; its block may answer
  anything, and the answer is dropped); `for x in <Source>`; a `Source`
  as an owner.
- PROBED, with `Sink`/`Source` as generic records of fn values and the
  loop written `while true { let p? = pages.next() else { break } }`:
  the seats, the capture by `spawn`, `send` as a statement and `next`
  compile and run (`6 pages`). `channel` and `select` are reserved
  today, so the stand-in used other names.
- PROBED, and why `produce` is a primitive and not a library fn: a
  block ending in `out.send("a")` at a `fn(Sink<T>) -> void` seat is
  `type.mismatch` ("the block is `fn(int) -> bool`" for the same shape
  on `each`); with a second type parameter for the answer, `produce
  <string, bool>(8) { … }` runs but an inferred call hits a compiler
  defect ("a method on a nameless receiver survived typing").

The same producer as a recipe (DEPENDS-ON COLLECTIONS S3; this is
COLLECTIONS S4):

```avra
fn pages_of(urls: List<string>) -> Stream<Page> {
    for u in urls { yield fetch(u) }
}

for p in pages_of(seeds) { store(p) }                 // one task, one loop
for p in pages_of(seeds).buffered(8) { store(p) }     // two tasks, 8 pages between
```

### 2.2 `select` over a watch, a channel, a timer and a signal — DESIGNED

```avra
use @std.task.{quiet, signals, Source, Sig}

fn dev(saves: Source<Seen>, built: Source<Built>, quit: Source<Sig>) -> int {
    mut dirty = false
    while true {
        select {
            _ in saves -> { dirty = true }
            quiet(ms(50)) if dirty -> {      // 50 ms in which no arm fired
                dirty = false
                rebuild()
            }
            b in built -> report(b)
            _ in quit -> { return 0 }
            saves.ended -> { return 1 }
            built.ended -> { return 1 }
            quit.ended -> { return 0 }
        }
    }
}

let w = watch()?
w.add("src")?
let code = within mins(60) { dev(w.changes(), builds, signals([.Term, .Int])) } catch 2
```

- `dev` is HANDED its sources, so a test hands it scripted ones (§2.8).
- A source that can end needs its `.ended` arm (law 7). No arm exists
  for cancellation: the `within` cancels `dev` wherever it waits.
- NEW: all of `select`; `within` answering `Result<T, TimedOut>`
  (today the block answers as written — READ `std-time/src/time.av:
  62-73`); `signals` (nothing in the runtime handles SIGTERM or SIGINT
  today — PROBED grep: the only handlers are the guard page's and the
  FFI fault's); `Watch.changes()`.
- PROBED: `… catch 2` on a `Result` (by the second review: answers `2`).

### 2.4 A worker, its contract, its honest delivery — DESIGNED

```avra
@store type Main = { path: string = "app.db" }

queue emails of Email {
    store: Main
    delivery: .at_least_once
    capacity: 10000
    lease: secs(30)
    dedupe: hours(24)
    retries: 3
    backoff: secs(5)
    dead: undeliverable
}

queue undeliverable of Dead<Email, SmtpError> { store: Main  capacity: 1000 }

worker sender {
    reads: emails
    at_once: 10
    each: deliver
}

extern effect fn smtp_send(m: Email) -> Result<string, SmtpError>              // promises nothing
extern effect fn charge(keyed key: Key, cents: int) -> Result<Receipt, PayError>  // the provider dedupes

fn deliver(email: Delivery<Email>) -> Result<string, SmtpError> {
    smtp_send(email.item)
}

fn signup(u: User) -> Result<User, DbError or QueueError> {
    let tx = Main.begin()?
    errdefer tx.rollback()
    let saved = tx.insert(u)?
    tx.send(emails, welcome(saved), id: "welcome-${saved.id}")?
    tx.commit()?
    saved
}
```

### 2.7 The UI loop — DESIGNED for native targets; the web keeps its exports

```avra
// @std/ui, terminal and headless
export fn mount<V: View>(view: fn() -> V, width: int = 80) {
    let inbox = unbounded_channel<Act>()        // its writers cannot be made to wait
    let ui = app(view, plain, inbox.sink)

```

## 3. The laws

1. **A stream is a recipe; a source is running.** A `Source` is owned
   by one block, as a task is.
2. **A running stream ends with the block that owns its sink.**
   `produce` makes that block a task. A bare `channel` ends at `close()`.
3. **A source's owner leaving stops its producer.** Sends answer
   `false`, the producer is cancelled, then joined. A `false` send is a
   cancel point.
4. **A sink is a handle.** Stored, copied, captured, sent. It keeps
   nothing alive.
5. **A channel says how much it holds.** `0` hands over.
6. **Loss is spoken.** A dropping channel counts what it dropped.
7. **A `select` is exhaustive over ends.**
8. **Arms take turns.** A ready arm is passed over at most `arms − 1`
   times. `select in order { }` scans as written.
9. **A task answers once.** An arm over a task made outside the loop
   must leave the loop. A task made in an arm head and not taken is
   cancelled, never joined.
10. **A cancelled wait fails with `Cancelled`.** It travels to the
    scope that asked, which answers it. A wake that already claimed a
    wait is honoured first.
11. **Cleanup that waits says for how long.**
12. **A failure is the last item**, and it carries its path (§9).
13. **No item is left behind.** A handler that can fail names the
    item's fate. A lease counts as an attempt, so an item that kills
    its handler is dead-lettered too.
14. **An item is acked when its handler returns `Ok`.** State that must
    survive commits with the ack, or the build says which is lost.
15. **Delivery is discharged per effect, by key.** An effect's key is
    (the delivery's key, the callee, which call to that callee this
    is). `exactly_once` is a demand over every effect the handler
    reaches.
16. **The sender mints the id, and the home remembers it for `dedupe`.**
17. **A lease has an epoch.**
18. **Order is a term.** A fold over `.any` needs a commutativity law.
19. **A law says how it is known**: `proven`, `checked (n)`, `trusted`,
    `open`. The word is printed wherever it licensed something.
20. **`fold` is left; `reduce` is the fixed tree.** Neither changes
    with its placement. A law over `float` licenses no change of order.
21. **A value crosses a process by copy, by descriptor, or not at
    all.** Its type says which.
22. **A wait on another machine says how long.**
23. **State that grows with a stream names its bound.** `.list(max:)`,
    `max_keys:`, `retain:`.
24. **A durable scope resumes at a checkpoint.** Inside a turn every
    effect has a key that survives an edit to the code around it.
25. **A trap ends one process.** Its peers go on; what it held is
    under lease.

### Attacks

| attack | what happens | where |
|---|---|---|
| slow consumer | the buffer fills, the sender parks; a lossy channel counts | laws 5, 6 |

| a producer that neither sends nor waits | runs to its end; the owner's join waits. Cancel is cooperative (fibers §7 records preemption as a trigger) | §5.4 |

## 4. Types and terms

| type | is | made by | rule |
|---|---|---|---|
| `Stream<T>`, `TryStream<T, E>` | a recipe | a fn with `yield`; a chain; `source.stream()` | a value |

OWNERS. An owner is a binding, a list, or a FIELD OF A RECORD THAT IS
ITSELF AN OWNER (`Channel<T> = { sink, source }` is one). Reading the
field (`ch.source`) borrows it: it may be an argument, a `for` or arm
head, or a capture by a task of the same block. Binding it to a second
owner (`let s = ch.source`) is `flow.owner_copy`. An owner may be
answered by a fn; the receiving binding owns it. Today a `Task` in any
field or answer is `type.task_escape` (PROBED), so this is a narrowing
of the task law and is tabled in §14.

RECORDS, NOT TRAITS. `Source<T>` holds three fn values and its
producer's task if it has one:

```avra
type Source<T> = { ready: fn() -> bool, take: fn(int) -> T, arm: fn(int) -> void, work: Task<void>? }
```

`arm(tag)` registers every wake the source needs under the arm's tag
(§5.1). `take(member)` is handed the member the park named, or −1 to
look. So a seat typed `Source<T>` is an ordinary seat (PROBED, §2.1),
and no `dyn Trait<T>` is needed. COST: an indirect call per `ready` and
per `take` on a running source. A recipe is COLLECTIONS' `Walk`,
inlined, with no call per item.

`Source` (`sse.av:40`), `Sink` (`form.av:193`); the compiler has an

## 5. Mechanisms: waiting, `select`, ownership, cancel

### 5.1 Waiting — DESIGNED; cost UNMEASURED

TODAY (READ `runtime/avra_fiber.c:125-137`): a `Fiber` has one `next`
link, one `parked_fd`, one `timer` slot. One task wakes another only
through a descriptor, which is why `Bell` is a pipe pair.

- A WAITER is `{ fiber, arm, member, set }`. A fiber carries four
  inline and an overflow list. Descriptor lists, the timer heap and
  gates hold waiters, where today they hold fibers. This rewrites the
  scheduler's waiter structures in both engines.
- A wait SET has one field: who claimed it.
- TO WAKE IS TO CLAIM. The first claimant writes `(arm, member)` into
  the set and readies the fiber; a later one finds it claimed and
  moves on. On resume the fiber unlinks every waiter of the set.
  `avra_wait_park()` answers the claim as `arm << 32 | member`.
- CANCEL IS A CLAIMANT. It claims an unclaimed set with arm −1. If a
  sender, a timer or a descriptor claimed first, the cancel does NOT
  displace it: the task resumes on its arm, completes the take, and
  the cancel flag (§5.4) fails its next cancel point. So a promised
  value is always taken by the taker it was promised to.
- A GATE is a queue of waiters in memory. `avra_gate_claim(g)` claims
  the first unclaimed waiter and answers its `member`, or −1.

CHANNELS OVER GATES (a library, in Avra: one core, cooperative, so a
claim is atomic).

- A channel has a buffer, a HANDED list, a `takers` gate and a `givers`
  gate.
- SEND, a taker waiting: claim it; append the value to `handed`. The
  claimed taker pops `handed` when it runs. Claimed takers have equal
  right to the head, so order holds. A fresh taker never reads
  `handed`. (This replaces v2's `promised` count; nothing can strand.)
- SEND, no taker, room: append to the buffer. No room: park in
  `givers`, the value in a pending list at index `member`.
- TAKE, buffer non-empty: pop; if a giver waits, claim it and move its
  pending value into the buffer. Empty: park in `takers`.
- RENDEZVOUS (`capacity 0`): the buffer never holds anything; only
  `handed` and the pending list do. Taker first: the sender claims and
  hands. Sender first (an `offer` in a `select`): the taker claims the
  offer's waiter and reads its pending value; the offerer resumes with
  its offer arm claimed. If the offerer's timer claimed first, the gate
  claim skips it and its pending value is dropped at its unlink.

WHAT A WAIT CAN BE ON

| `Wake` | row | today |
|---|---|---|
| `.Readable(fd)`, `.Writable(fd)` | `avra_wait_fd` | `avra_fiber_park_fd` |
| `.At(ns)` | `avra_wait_until` | the timer heap |
| `.Gate(g)` | `avra_wait_gate` | none |
| `.Exit(pid)` | `avra_wait_exit` | none; `EVFILT_PROC`, a pidfd |
| `.Sig(set)` | `avra_wait_sig` | none; `EVFILT_SIGNAL`, a signalfd |

A thread's completion (DNS) stays a pipe byte: a gate is not
thread-safe. A completion-based host (io_uring, IOCP, a wasm host)
owns a one-result buffer and a gate. A row that BLOCKS (a file read,
`fsync`, sqlite) is not a wait; fibers F4's offload is unbuilt (READ
`FIBERS_DESIGN.md:197`), so a store home blocks its core per commit.

FIBERLESS TASKS. `after`, `quiet`, `offer` and `ended` answer a task
nothing runs. Rows: `avra_task_pending() -> ptr` makes one;
`avra_task_answer(t, v)` completes it and claims its waiters;
`avra_task_at(ns) -> ptr` is one the timer heap completes;
`avra_task_cancel(t)` cancels any task (a fiberless one is simply
dropped from its heap or gate).

COST OWED before slice 1 lands: the yield-to-yield switch (12 ns
today, READ fibers §6b) and the single-descriptor park must keep an
inline fast path; a gate park-and-claim round trip; zero allocations
per `select` turn by `make census` (an arm registers with row calls;
no list of wakes is built; `ready()` then `take()` avoid a `T?` box).

### 5.2 `select` — DESIGNED

```
select_stmt = "select" ( "in" "order" )? "{" ( arm | BREAK )* "}"
arm         = ( pattern "in" )? expression ( "if" expression )? "->" body
            | "else" "->" body
```

- An arm's expression is evaluated once on entry, in order. Its type is
  `Source`, `TrySource`, `AnyOf`, or a task (named types over a task
  are seen through, as any read sees through a name — CLAUDE.md "A NAME
  IS OPAQUE AT A SEAT AND TRANSPARENT AT A READ").
- A guard is read on entry; false removes the arm for this turn.
- `else` runs when nothing is ready. `select` is an expression.

LOWERING. No new instruction: a loop, a switch region, row calls.

```
heads → h0 … hn
loop:
    for i in rotation(cursor): if hi.ready() { v = hi.take(-1); arm i; leave }
    else-arm, if any → run it, leave
    for each live arm i: hi.arm(i)
    (a, m) = avra_wait_park()      // a = −1: cancelled (§5.4)
    if h_a is gate-claimed: v = h_a.take(m); arm a; leave
    goto loop
leave: every task made in an arm head and not taken is cancelled
```

TASKS IN ARM HEADS. A task made by an arm's expression belongs to the
`select`. Leaving the `select` cancels each one not taken (an offer is
retracted, a timer dropped). It is never joined. (v2 would have waited
out every unfired `quiet`.)

TIMERS, BY TYPE. `after(d)` answers `Deadline`; `quiet(d)` answers
`Quiet`. An arm whose head is a CALL answering `Deadline`, inside a
loop, is `flow.fresh_deadline`: it would restart every turn. `Quiet`
is the type that says so on purpose. The rule reads types, never names.

MANY SOURCES. `any(sources: List<Source<T>>) -> AnyOf<T>` borrows the
list and answers a handle: it owns nothing, and reads as ended once
every member has. Its `arm(tag)` registers each member under `(tag,
i)`; the park answers `i`; `take(i)` takes that member's item and
answers `Pick<T> { at: i, item }`. `any(tasks)` skips a task once it
answered.

### 5.3 Ownership — DESIGNED

TODAY (READ(agent) `features/task_law.av`; PROBED `type.task_escape`):
an owner is a binding, a nullable binding, a `List<Task<…>>` or
`Tasks`; each is joined by a `Deferral.Settle` at its scope's exit.

RULES ADDED

1. A `Source`, and a record with an owner field, are owner types.
2. An owner may be answered: the callee emits no settle for a local
   owner it returns (a tail or `return` of a binding or call of owner
   type — a syntactic fact, no move analysis), and the receiving
   binding settles it. An answered owner nothing binds is settled at
   the end of the statement.
3. SETTLING A SOURCE: mark it left, cancel its producer, join it.
   Settles run last-bound-first, so reader tasks spawned after a source
   are joined before it.
4. `produce<T>(n) { out -> … }` is a primitive of `features/tasks`, as
   `spawn` is: it makes the channel, spawns the block with a `defer`
   that closes the sink, and answers a `Source` whose `work` is that
   task. No library call moves an owner into a record.
5. A producer that can fail: `produce_try<T, E>(n) { out -> … }` takes
   a block answering `Result<_, E>` and answers `TrySource<T, E>`; an
   `Err` becomes the last item.

| holder of a `Sink` | what happens |
|---|---|
| the `produce` block and tasks under it | the channel ends at the block's end, after its tasks are joined |
| a fn it is passed to, however deep | a parameter is borrowed |
| a field, a registry in a `Cell`, a stored closure, another channel | a handle; `send` answers `false` after the end; the registry prunes on `false` |
| a task parked for ever elsewhere | the channel does not end; not detected |
| another process | never: a `Sink` holds fn values, so `flow.crossing` refuses it. Between processes the stream is a queue (§8) |

A bare `channel<T>(n)` ends only at `close()`. `flow.never_ends` is
syntactic: a `spawn` in the block captures `ch.source`, and no
`close()` or `defer … close()` placed after those spawns precedes the
block's end.

### 5.4 Cancel — DESIGNED; cost UNMEASURED

Ratified (READ `FIBERS_DESIGN.md:27`, `:119-123`): "Cancellation
arrives only at a pause point, as a failure on the `Result` channel…
so `?`, `defer` and `errdefer` already handle it." Fibers did not say
how that failure leaves a fn with no `Result`. This design's answer
(question 3):

- THE FLAG IS THE TASK'S. Each task has `cancelled_by`: the id of the
  scope that cancelled it, or none.
- A CANCEL POINT is: `avra_wait_park` answering −1; a `send` answering
  `false`; `yield_now()`.
- After every call that MAY REACH a cancel point, the compiler emits
  one test of the flag: set → run this frame's `defer`s and `errdefer`s
  and return. The answer returned is never read, because the caller
  tests the flag too.
- "May reach" is a fact folded over the call graph (fibers §4 names
  it). AN INDIRECT CALL MAY REACH ANYTHING: a call through a fn value
  or a `dyn` method is always followed by the test. No fn type changes
  and no ABI changes; the price is a load and a branch after such
  calls.
- A C FRAME between two Avra frames is not unwound. Its callback
  answers zero values until it returns; then its Avra caller tests the
  flag. Package C that calls back into Avra must tolerate that; the
  uniform extern frame is the one such site today.
- THE SCOPE THAT ASKED CONSUMES IT. `within` compares `cancelled_by`
  with its own id: its own deadline becomes `.Err(TimedOut)`; anyone
  else's passes through untouched, whatever `catch` follows the block.
- A loop that reaches no cancel point runs to its end.

ALSO DECIDED

- `within d { body }` answers `Result<T, TimedOut>` (fibers §4, READ).
  This changes the type of every existing `within` block; the callers
  are counted in the slice (grep: `within ` in `packages/*/src`).
  `avra_fiber_sleep` and `avra_task_join` ignore the deadline today
  (READ(agent) `avra_fiber.c:803`, `:722`); both hear it once parks go
  through `avra_wait_park`.
- A wait in a `defer` under a cancel fails at once, unless inside a
  `within` written in that `defer`. Otherwise `flow.unbounded_cleanup`.
- PARTIAL DEADLOCK IS NOT DETECTED. `avra tasks <pid>` prints each
  parked task's wakes and, for a gate, its channel.

### 5.5 Reentrancy — DESIGNED

A parking `send` inside the loop that is the channel's only reader is
`flow.self_send` when both ends are one binding in one fn. Through a
call it is seen at run time: the park knows the sender's task owns the
source and traps on the first full send. That is load-dependent, which
is why the UI's inbox does not park.

## 6. Homes

A HOME is where a stream's items sit between writer and reader.
Fibers §8's PLACEMENT is where work runs (READ `:265-275`). A crossing
happens when the writer's and the reader's placements differ.

### 6.1 The table

| another task | DESIGNED | a ring, two gates (§5.1) | a gate park when full or empty; UNMEASURED | a copy of the value or handle (fibers §8: "copies cross"); a dying unique value is moved by the store (REUSE D6 — READ :46) | at most once | cancel; `false` |

### 6.2 `Home`

A queue's typed face (`send`, its source, `Delivery<T>`) sits on a
home that moves envelopes of octets:

```avra
export type Envelope = {
    id: string, key: string, shape: int, slots: int,
    attempt: int, epoch: int, sent_ms: int,
    sent: Frame, trace: List<Frame>, body: Bytes,
}

export type Terms = {
    delivery: Delivery_, ordered: bool, by_key: bool,
    dedupe: Duration?, lease_min: Duration, max_item: int, keeps: Keeps,
}

export type Home = {
    terms:   fn() -> Result<Terms, HomeError>,
    shapes:  fn(hash: int) -> Result<Shape?, HomeError>,          // a shape's names and spellings, by hash
    declare: fn(Shape) -> Result<int, HomeError>,
    send:    fn(queue: string, e: Envelope) -> Result<string, HomeError>,      // same id within `dedupe`: one item, same answer
    take:    fn(queue: string, reader: string, max: int, lease: Duration, patience: Duration) -> Result<List<Envelope>, HomeError>,
    ack:     fn(queue: string, id: string, epoch: int) -> Result<bool, HomeError>,   // false: the lease was lost
    release: fn(queue: string, id: string, epoch: int, after: Duration) -> Result<bool, HomeError>,
    bury:    fn(queue: string, id: string, epoch: int, dead: Envelope) -> Result<bool, HomeError>,
    depth:   fn(queue: string) -> Result<Depth, HomeError>,
}
```

- A record of fn values, like `Source`. `Frame` is `@std/errors`'
  (READ `errors.av:14`: `{ label: string?, loc: Loc? }`).
- `take` parks up to `patience` for the first item. A home that cannot
  notify (sqlite across processes) polls inside it and says so in
  `depth`'s cost line.
- `ack` with a stale epoch answers `false`: the fencing check.
- `bury` moves an item to its dead letter in one step, so it is never
  in both or neither.
- `HomeError`: `.Unreachable(after: Duration)`, `.Refused(why)`,
  `.TooBig(size, max)`, `.Shape(hash)`, `.Denied`.

### 6.3 The wire, derived from the element type

`@std/relation` already has a content-only byte codec (READ
`stable.av:1-9`: "Every variable-length part carries its own length or
count ahead of it, and every `?` layer its own presence flag: the
arity is fixed per kind, so no two shapes spell the same bytes") and a
shape hash of a type's field names, spellings and marks (READ
`relation.av:272`).

- `queue … of T` generates T's encoder and decoder with the same
  machinery `@relation` uses, and refuses a T that has no stable
  encoding (a fn, a `Cell`: the existing `kind_problem` law).
- A RECORD on the wire is its slot count, then each slot as a length
  and its octets. A reader decodes the slots it knows, in order, and
  SKIPS the rest by length. So a record may grow at its end.
- AN ENUM is carried by its variant's name (READ(agent) `stable.av`),
  so adding a variant is growth. A reader that meets a name it does not
  know buries the item with cause `Unreadable`; it is never retried.
- THE SHAPE. An envelope carries its shape's hash and slot count. A
  home keeps each shape's descriptor once (`declare`). A reader that
  meets an unknown hash fetches the descriptor and classifies:

| reader's type vs the writer's | verdict |
|---|---|
| same hash | decode |
| writer has more trailing slots, the common ones spelled alike | GROWTH: decode what is known |
| writer has fewer trailing slots, and every missing one has a default | GROWTH seen from the other side: defaults fill |
| a slot renamed, reordered, retyped, or a missing slot without a default | MOVED: `flow.shape_moved` at build when the home is readable, else the item is buried `Unreadable` |

  This is CLAUDE.md's crossing law (READ: "one that merely GREW —
  fields appended, in order — crosses, because the reader takes the
  slots it knows by SLOT ORDER and never looks at the trailing ones").
- OWED, small: `shape_hash` is top-level only today; a queue's must
  fold in the shapes of the named types its fields hold.

### 6.4 Homed in the program's own store — DESIGNED, worked

`@store type Main = { path: string = "app.db" }` declares a logical
store; where its file is belongs to the run. `queue emails of Email {
store: Main … }` puts the queue in it. The store-table home over
`@std/sqlite` (API READ: `Db.open`, `begin`, `commit`, `rollback`,
`run(sql(…))`):

```sql
flow_items(queue, seq INTEGER PRIMARY KEY, id, key, shape, slots, body,
           sent_ms, sent, trace, attempt, epoch, reader, leased_until)
flow_seen(queue, id, at_ms, answer)          -- pruned after `dedupe`
flow_shapes(hash PRIMARY KEY, descriptor)
flow_kept(name, state, cursor)               -- `kept:` folds
```

| verb | statement | notes |
|---|---|---|
| `send` | look up `flow_seen`; if present answer its `answer`; else insert both rows | in the CALLER's transaction when called as `tx.send` |
| `take` | `UPDATE flow_items SET reader=?, epoch=epoch+1, attempt=attempt+1, leased_until=? WHERE seq IN (SELECT seq … WHERE queue=? AND leased_until<? ORDER BY seq LIMIT ?) RETURNING …` | order is `seq`; for `.by(key)` the subquery skips keys with a live lease |
| `ack` | `DELETE FROM flow_items WHERE id=? AND epoch=?`; rows changed 0 → `false` | in the HANDLER's transaction when the worker says `store: Main` |
| `bury` | delete from the queue and insert into the dead letter's rows, one transaction | |

- Same process: a `send` rings the queue's gate, so a reader wakes at
  once. Another process sharing the file: `take` polls every
  `min(patience, 250 ms)`; sqlite has no notify. A Postgres store would
  use LISTEN/NOTIFY; there is no Postgres driver in the tree, so that
  home is not worked.
- COST: one transaction per send and per ack; sqlite calls block the
  core (§5.1).
- EXACTLY ONCE IN THE STORE. A worker declared `store: Main` hands its
  handler a `Tx<Main>`; the handler's writes, the ack and any `tx.send`
  are one commit. A crash before it: none happened, and the item's
  lease expires. After it: all did.

## 7. Delivery and effects — DESIGNED

### 7.1 The ack

An item is ACKED when its handler returns `Ok` (or the `for`/arm body
that bound the `Delivery` finishes). A handler that fails, is
cancelled or dies leaves it unacked. A LEASE is an attempt: `attempt`
rises at `take`, so an item that kills its handler every time is
buried after `retries` leases with `Crashed`.

### 7.2 Effect contracts

```avra
extern effect fn smtp_send(m: Email) -> Result<string, SmtpError>
extern effect fn charge(keyed(hours(24)) key: Key, cents: int) -> Result<Receipt, PayError>
extern reading fn rate(pair: string) -> Result<float, NetError>
```

- `effect` marks an extern a handler may reach as an effect. `reading`
  says calling it twice changes nothing. Both are the author's claim
  about a provider: status `trusted`.
- `keyed(window)` is a SEAT mark: two calls with equal keys within the
  window have the effect of one and answer alike. It joins `SeatMark`
  (READ `core/types.av:1071`: `{ mutable, settled, state, unshared,
  consumed }`) and the seat grammar (READ `features/fns/mod.av:50`,
  after `isolated`), so it is part of the fn's type.
- A `Key` is an opaque named type. `delivery.key` is the item's.
  `key.at("tip")` is a named sub-key. `Key.of(text)` is the author's
  own identity, printed `trusted`. Nothing cuts a key or rebuilds one
  from part of another, so "derived" can only mean "passed whole, or
  extended".
- WHAT REACHES THE PROVIDER at a `keyed` seat is not the author's key
  alone. The call site's lowering extends it: `(key, callee's stable
  name, n)`, where `n` counts this handler run's calls to that callee
  with that key. Two `charge`s under one delivery are `…/charge#1` and
  `…/charge#2`. An edit that inserts a different effect before them
  does not renumber them (§12).
- AN UNMARKED extern or `World` row reached by a handler is an unknown
  effect: it repeats, `explain` names it, and under `exactly_once` it
  is `flow.not_exactly_once`. A call through a fn value or a `dyn` is
  `flow.unknown_effect`: the callee could be anything.
- An Avra fn's contract is DERIVED by folding these facts over its
  body: `reading` if every effect it reaches is; in store `S` if its
  only effects are writes through a `Tx<S>`; keyed if every effect it
  reaches is fed its `Key` seat.

### 7.3 Discharge

For each effect a handler reaches:

| the effect is | under redelivery | printed |
|---|---|---|
| `reading` | nothing to repeat | — |
| a write through the handler's `Tx<S>`, where the queue's `store` is `S` | atomic with the ack | exactly once |
| at a `keyed` seat fed the delivery's key, with the provider's window ≥ the queue's redelivery horizon | absorbed | exactly once (`trusted`) |
| absorbed by a law over the handler's kept state | harmless | exactly once (`proven` / `checked`) |
| none of these | repeats | at least once ⚠, naming the effect |

- `delivery: .exactly_once` demands the first four rows of every
  effect (spec 29.2, READ: "requires idempotent consumers or
  transactional delivery"). It is a promise per EFFECT: a handler that
  did keyed effect A, then failed at B three times, is buried with A
  done once and B never. `Dead.hops` says so.
- THE REDELIVERY HORIZON is `retries × (lease + backoff)`, or
  unbounded with no `retries`. A `keyed(window)` shorter than it is
  `flow.key_outlived`.
- THE ABSORPTION LAW, for a pure step on kept state:

  ```avra
  law seen_stays_seen {
      for s: State
      for x: Item
      for y: Item
      step(step(step(s, x), y), x) == step(step(s, x), y)
  }
  ```

  With idempotence this gives absorption after any sequence (walked by
  both reviews). `step(s, x) = x` fails it at `x, y, x`.
- A FOLD. In memory, a crash loses the state while the acks stand:
  `explain` prints "at most once: the sum is not kept". `kept: "name",
  store: S` writes state and cursor as one row of `flow_kept`: exactly
  once when the queue's store is `S`. When the queue is homed elsewhere
  the cursor is the home's, so the fold keeps a table of seen ids for
  `dedupe` instead, and prints "exactly once within 24 h". `kept:` with
  no store is `flow.too_many`'s sibling: refused, naming the missing
  `store:`.

### 7.4 Ids, the window, the dual write

- THE SENDER MINTS THE ID (AUTHORITY_AND_RECEIPTS :69 — READ).
  `send(v, id: …)`. Inside a handler, a send with no `id:` is given
  `(the handler's delivery key, the queue, n)`. Outside one it is a
  fresh UUIDv7 and `explain` says a retried caller sends twice.
- THE HOME REMEMBERS AN ID FOR `dedupe`. Law 16 holds inside that
  window and nowhere else; the term is required, checked against the
  home's `Terms`, printed, and attacked by `--faults`.
- THE DUAL WRITE. A fn that writes through a `Tx<S>` and calls
  `q.send` outside that transaction is `flow.dual_write`
  (AUTONOMOUS_SYSTEMS :356 — READ: "commit business state and the
  intent to perform an effect together"). `tx.send(q, v, id:)` is the
  fix: when `q.store` is `S` the item is a row in the same commit; when
  `q` is homed elsewhere the row goes to `S`'s `flow_items` under an
  outbox queue, and a relay worker — at least once, its far `send`
  deduped by id — forwards it.

## 8. Processes, cores, supervision — DESIGNED over fibers §13

### 8.1 The substrate

Fibers §13 as built (READ): "ONE PROCESS PER CORE, SHARING NOTHING…
then a process IS the thread-local runtime, with the kernel as the
isolation proof"; the fork is "2.5 ms with 64 MB touched, once at
start"; each core holds the write end of its own pipe, "closed by the
kernel however the core ends". `runtime/avra_cores.c` forks the group,
keeps six descriptors per core and trims the child to the calling
task (READ(agent)).

A `worker … on: .cores` (and `@std/http`'s server, unchanged) is a
group. ADDED, three rows:

| row | does |
|---|---|
| `avra_cores_link(g, core) -> int` | one end of a socketpair made BEFORE the fork, kept in the core's descriptor list (today nothing passes a descriptor to a child: no `socketpair` in `runtime/` or `packages/` — PROBED grep) |
| `avra_cores_refork(g, core) -> int` | forks that one core again from the supervisor; the child keeps the calling task alone, as every core does |
| `avra_cores_ended(g, core) -> int` | the status, without trapping (today `avra_cores_result` traps on a crash — READ `avra_cores.c:255-260`) |

Items cross a link as §6.3's octets, length-prefixed. The supervisor
deals a `.share` queue's leases to cores; a core acks over its link.
With a store home each core opens the store itself and the links carry
only wake-ups.

### 8.2 What may cross — a rule per type, three answers

| way | which types | cost | today |
|---|---|---|---|
| BY COPY | plain data: `identity_in` answers null (READ `features/contexts.av:47`) | encode + decode; the sender's value is dropped if it was dying, so nothing is held twice | the walk exists for a lambda's captures at an `isolated` seat; a second caller walks an ITEM TYPE |
| BY DESCRIPTOR | a type that IS one kernel object: `Conn`, `Listener`, an open file | `SCM_RIGHTS` on the link; the sender's copy is closed | not built; needs a `crossing: .descriptor` mark on the type and a row |
| NEVER | a `Cell`, a task, a pointer, a fn value, a `dyn`, a `Sink` or `Source` | — | `flow.crossing`, naming the field |

- A descriptor held as a bare `int` inside plain data crosses as a
  number and fails loud (`EBADF`), which fibers §13 already records.
  The mark is how a type says its `int` is a capability.
- AUTHORITY THAT IS TEXT (a token in a `string`) cannot be found by any
  walk. v1's law about it stays cut.
- CAN A UNIQUE VALUE MOVE WITHOUT A COPY? Across processes: no — the
  address spaces are separate; "move" is copy-then-drop. Across tasks
  on one core: yes, already (REUSE D4 — READ: "The twin writes in
  place only when the box's count is 1"; D6 moves a dying value into a
  cell). Across BEND's lanes (threads): it could, by pointer, when the
  value is TRANSITIVELY sole — every box under it has count 1 — and
  the allocator frees across lanes (BEND §4.3 — READ: "A box freed on
  a lane other than its minter goes to the freeing lane's list"). That
  needs one runtime walk, `sole_deep(v)`, at the hand-over: sole →
  move; else → deep copy. This design REQUIRES of the BEND campaign:
  that walk, cross-lane free, and that a `send`'s seat is `consumed`.
  It does not design the lanes.

### 8.3 Supervision

OF TASKS (structured, in one process):

| Erlang | here |
|---|---|
| link | a block: a failing block cancels its children (fibers §0) |
| monitor | an arm over the task: `r in worker -> …` hears its answer, `Err` included |
| restart a failing child | `keeping(times: 5, within: secs(10), backoff: ms(100)) { body }`: re-runs a body that answers `Err`; gives up with the last `Err` |
| trap exit | none: a trap is not a value in this process |

OF PROCESSES:

- A TRAP ENDS ITS PROCESS (READ `avra_runtime.c:1030`: `exit(2)`), and
  only its process. Peers learn by the end pipe's EOF, as today.
- DEFAULT, unchanged: fail-fast. The group stops and `run` traps
  "core i of n ended with status s" (READ `avra_cores.c:258`).
- `on_crash: .restart(backoff:, give_up: n, within: d)` on a `worker`:
  the supervisor reads the status (`avra_cores_ended`), waits the
  backoff, reforks that core. Exceeding `give_up` within `d` stops the
  group and fails as the default does. No `one_for_one` family: one
  core is one unit (the process research's refusal, READ(agent) §2.3).
- WHAT THE DEAD CORE HELD: its leases. They expire; the items are
  redelivered with `epoch + 1`; `attempt` already counted the lease,
  so a poison item is buried after `retries` (law 13). In-memory state
  of that core is gone, which is what `kept:` and the store are for.
- WHAT THE SUPERVISOR SEES: `Crashed { core, status: Exit, last: string }`
  where `last` is the dead core's final stderr line, read from a pipe
  the supervisor keeps (one more kept descriptor per core).
- A CHILD PROGRAM (`@std/process`): `child.exited()` is an arm; the
  process research's `Service` component (restart, backoff, give_up —
  READ(agent), not built) becomes a `select` loop over children. That
  package's design is its own; this one gives it the arm.
- NOT DESIGNED: hot code upgrade; a link between two arbitrary tasks
  that are not parent and child (a monitor arm covers the use).

## 9. Error topology — DESIGNED

WHAT TRAVELS. `Traced<E> = { error: E, frames: List<Frame> }` and
`Frame = { label: string?, loc: Loc? }` (READ `std-errors/src/errors.av:
14, :63`). Both are plain data when `E` is. A `dyn Error` cause is
not: it is flattened to its "caused by: …" lines before it crosses,
exactly as `DiagFacts` does for a diagnostic (READ `diagnostics/mod.av:
39-45`: "`cause`… crosses no process as a `dyn Error` — its chain is
flattened once").

A FRAME IS ADDED AT EACH HOP, by the thing that hops:

| hop | who adds the frame | label |
|---|---|---|
| a stage fails | `try_map` and its siblings | "in stage `encode`" + the stage's site |
| across a channel | the producer's `Err` item | "from `pages`, made at crawl.av:12" |
| a task's answer awaited | `.await?` | "in a task spawned at …" |
| sent to a queue | `send` | the envelope's `sent` frame: the sender's site |
| a lease | the worker runtime | a `Hop { where, epoch, at_ms }` in `Dead.hops` |
| across a process link | the codec | "on core 3 (pid 4127)" |
| across a remote home | the binding | "via https://queue.internal" |

- The trace is capped at 16 frames, the renderer's cause cap (READ(agent)
  `diagnostics/render.av:79`), dropping the middle and saying how many.
- A CHANNEL item carries no trace. Only a failure does, and only once
  it exists. A QUEUE item carries `sent` and the sender's trace because
  it must outlive its sender.
- `? context "…"` (planned, not built — READ(agent)) adds labelled
  frames to the same list; nothing here waits for it.

THREE DIRECTIONS (law 12), for `a.try_map(f).buffered(8).try_map(g)
.fold(…)` when `g` fails: the fold answers `Err(Traced)`; the source is
settled, so the task running `a.try_map(f)` is cancelled at its next
send and runs its `defer`s; what it held unread is dropped (a channel)
or never acked (a queue).

WHAT A SUPERVISOR SEES: an `Err(Traced<E>)` from a task; `Crashed`
from a process; a `Dead<T, E>` in a dead letter. Never a string to
parse.

POISON AND DEAD LETTERS

| the item | fate |
|---|---|
| fails its handler | retried `retries` times, `backoff` apart, then buried with the last `Traced<E>` |
| traps its handler | the lease counted; buried after `retries` with `Crashed` |
| cannot be decoded | buried at once, `Unreadable(hash)`; never retried |
| is too big for the home | refused at `send`: `TooBig`; never enqueued |
| is in a dead letter nobody reads | `explain flow` warns; depth is a metric |

A per-item failure that should not end a STREAM is a value at the
stage: `.try_map(parse).skipping(bad)` sends each `Err` to a sink as a
`Dead` and goes on.

`avra explain flow` DRAWS THE TOPOLOGY from the program: nodes are
declared queues, workers, the fns that send (found by the call graph)
and the marked effects; an edge is a send, a read, or a failure's path
to its fate. §2.4 is its text form; `--json` gives the graph. A queue
bound at run time is drawn with its declared terms and "home: bound at
start".

## 10. Laws, parallel placement, vectors

### 10.1 What a law's status licenses — DESIGNED

BEND §3.2 (READ): rung 1 exhaustive says `proven`; rung 2 generated
cases says `checked (n cases)`; rung 3 SMT, "a later slice", says
`proven`; else `open` "and the gate is red".

| | `proven` | `checked (n)` | `trusted` | `open` |
|---|---|---|---|---|
| run a `fold` as a tree (associativity) | yes | yes, marked | — | no |
| fold an `.any`-ordered queue (commutativity) | yes | yes, marked | — | no |
| take `at_least_once` with no key (absorption) | yes | yes, marked | — | no |
| maintain a fold under removal (inverse) | yes | yes, marked | — | no |
| skip an effect's repeat (`keyed`, `reading`) | — | — | yes, marked | — |
| what a false one does | cannot be | the transformed answer differs on inputs the cases missed | an effect repeats | — |
| how it is caught | — | `avra test` runs every licensed transformation both ways on every input it sees; `--faults` compares against the plain run; a deploy may demand `laws: .proven` | not by this toolchain | the gate |

- A TYPE RULE, NOT LUCK: a law with a `float` binder (or a type
  holding one) may license no row that changes evaluation order.
  `flow.float_law`. Exact types are `int`, `bool`, text, enums and
  records of those. (`int` wraps — PROBED: `add(add(MAX, 1), -1)` and
  `add(MAX, add(1, -1))` both answer 9223372036854775807 — so integer
  addition does associate.)
- BEND §9 question 4 asks whether a `checked` law may gate a release
  and proposes yes with the word in the receipt (READ). This table is
  that proposal, made concrete. Question 8.

### 10.2 `fold` and `reduce` — DESIGNED

Neither exists on a list today (READ `features/lists/mod.av`: rows for
`map`, `sum`, no `fold`, no `reduce`).

- `xs.fold(init, f)` is the left fold. In every placement.
- `xs.reduce(init, f)` is ONE FIXED TREE, part of its meaning:
  - LEAF: up to 1024 consecutive items, folded into 8 accumulators by
    index mod 8, then combined `((a0·a1)·(a2·a3))·((a4·a5)·(a6·a7))`.
  - ABOVE THE LEAF: split the index range at its midpoint, rounded to
    a leaf boundary; `f(left, right)`.
  - `init` is folded in once, at the root.
- The constants 8 and 1024 are the language's, not the machine's. A
  machine with 2-wide vectors runs the same eight accumulators in four
  registers; one core runs the same tree as sixty-four. So `reduce`
  over floats answers the same bits everywhere (BEND §4.3 — READ: "A
  REDUCTION TREE IS FIXED BY THE DATA LENGTH, never the worker count…
  floats do not reassociate"), and `fold` and `reduce` over floats are
  different answers under different names.
- A stream has no length: `s.reduce` is the tree over chunks of 1024
  leaves, each chunk reduced, the chunk answers folded LEFT. Still one
  shape.
- With an associativity law of a licensing status, the compiler may
  run a `fold` as a `reduce`.
- Among failing chunks, the earliest in input order is the answer.

### 10.3 Lowering — DESIGNED for one lane and vectors; the fork is BEND's

IR today (READ `core/ir.av`): 34 instructions, loops as `LoopStart`,
`LoopCond`, `LoopEnd`, `LoopJump`; `Call` for a minted fn. A list walk
keeps its index in an `Alloca` cell (READ(agent) `features/emit.av:
395-460`). The backend has scalar float builders only; nothing sets
vector types, loop metadata or fast-math; the pass pipeline is
`default<O0..3>` (READ(agent) `llvm_wrapper.c:1198`).

- `reduce` ON ONE LANE needs no new instruction: the compiler mints a
  recursive halving fn (BEND §4.4 says the same of `par for`: "lowers
  to a recursive halving fn the compiler mints") whose leaf is a loop
  over eight `Alloca` accumulators. Existing shapes: `Call`, loops,
  `Bin`.
- VECTORS need the backend told what it cannot infer: that a loop's
  turns are independent. The IR protocol asks first whether an existing
  shape can carry it. It can: `LoopStart` gains a payload,
  `LoopStart(turns: Turns)`, `Turns { Ordered, Independent }`.
  - It is a statement about what the loop MEANS (no turn reads what
    another wrote, apart from the listed accumulators), so every reader
    reads the same thing afterwards: the evaluator runs it in order and
    gets the same answer; the memory pass is unaffected; `llvm` attaches
    `llvm.loop.vectorize.enable` and `llvm.access.group` metadata.
  - The compiler may claim `Independent` only for a body in BEND §5.1's
    kernel fragment (READ: "scalar arithmetic and comparisons only,
    reads of flat numeric lists… no allocation, no `CallRt` beyond the
    math rows marked `Embed`, no recursion"), which needs BEND's
    `allocates` fact.
  - A CHECKED CLAIM (BEND §5.1b — READ: "either vectorises or `explain`
    names the line that stopped it"): the wrapper enables LLVM's
    optimisation remarks for the loop vectoriser and returns, per marked
    loop, "vectorised W×T" or the missed reason. `explain --kernels`
    prints it. Three wrapper rows; no hand-written vector IR.
  - The leaf's eight accumulators are eight scalars the vectoriser
    packs. If a release must not depend on the vectoriser, the fallback
    is explicit vector IR, which needs vector-type rows the wrapper
    lacks; that is the larger slice and is not taken first.
- HONEST LIMITS: `float` is f64 only today (READ(agent) `llvm.av:623`);
  the baseline CPU is `apple-m1` on arm64 and generic elsewhere (READ
  (agent) `llvm_wrapper.c:928`), so x86-64 gets 2×f64 until a target
  CPU is chosen. The fibers tour's "SIMD 8×f32" is not reachable yet.
- CORES. `[f(x) par for x in xs]` and a parallel `reduce` fork at the
  tree's splits. That is BEND §4: `Spawn`/`Join` (two new instructions
  that doc justifies), a stealing pool, atomic retains, the fork law
  (pure or embed reach, no `mut` capture, borrowed arguments — READ
  §4.2). It is "Not ratified" (READ, header), nothing of it is built,
  and it waits on H3, still open (READ `ROADMAP.md:973`). THIS DESIGN
  REQUIRES OF IT: (1) the fork law's two facts on user fns; (2) that a
  fork happens only at a tree split or a `par for` halving, so §10.2's
  shape is unchanged; (3) §8.2's `sole_deep` for a stream's chunks;
  (4) `Reach` on a stage so `par for x in s.chunks(n)` can refuse a
  stage that reaches the world.
- A STREAM IS PLACED A CHUNK AT A TIME: the source stays on its task;
  `chunks(n)` gives lists; each is a `par for`; answers are emitted in
  chunk order. One chunk in flight per lane bounds memory.

### 10.4 When NOT to parallelise — DESIGNED as a rule; the constants are measurements owed

- FORK GRAIN. A split forks only when both halves cost more than `k`
  forks. `cost(half) = items × per-item steps`, from COST_MODEL's
  `steps` (designed, not built — READ(agent)). Until that exists the
  per-item cost is "unknown" and the grain is 4096 items, and `explain`
  says "uncalibrated". The fork's own cost is published by the runtime
  (a fiber spawn-and-join is 126 ns today — READ fibers §6b; a pool
  task is BEND's to measure).
- The fork grain is a multiple of the leaf, so it never changes the
  tree.
- NO FORK WHEN: the list is under two grains (one length test at run
  time); the stage reaches the world; the items must be deep-copied
  and the copy costs more than the stage (compared from sizes when
  known; otherwise stay on one lane and say so).
- NO VECTOR CLAIM WHEN: the body leaves the fragment (the line is
  named); the trip count is under 32.
- PARALLELISM IS SUGGESTED, NEVER SILENT (fibers §0 — READ). `par`
  asks; the compiler may then decline at run time by the rules above,
  and `explain` prints which rule. An unmarked chain is never forked.

GPU: BEND §5.2–5.4. Nothing here.

### 11.2 `avra test --faults`

FAULTS, from the terms:

| term | fault |
|---|---|
| `delivery: .at_least_once` | each item delivered twice: adjacent, and with others between |
| `lease` | the lease expires mid-handler; a second handler runs beside the first with `epoch + 1` |
| the ack | a CRASH at every point between an effect and its ack |
| `dedupe` | the sender retries inside the window, and after it |
| `order: .any`, `.by(k)` | items permuted (across keys only, for `.by`) |
| `overflow` not `.park` | the buffer filled |
| `patience`, any `within` | expiry at every wait inside it |
| a home | unreachable for a window |
| a `checked` law | every licensed transformation run both ways |

A CRASH IS NOT A CANCEL. A cancel runs `defer`s; a crash runs nothing
and loses the process's memory. So the simulator's crash is: abandon
the run — every task dropped, no `defer` run (`avra_sched_abandon`, a
test-only row) — roll back every store model's open transactions, keep
the store and queue models' committed state, and start the program's
workers again over them. That is what a real process restart sees. The
kill points are emitted by the test build after every marked effect
call and before every ack.

ORACLES

1. NO ITEM LEFT BEHIND: at quiescence every sent id is acked or buried.
2. THE DIFFERENTIAL: the same inputs run once with no faults, in input
   order. Then, per run under faults, compare: every `@store` model's
   final rows; every `kept:` state; each keyed model's map (the set of
   effective keys and their argument hashes); each dead letter. A
   difference is a FAILURE unless the declared delivery permits it.
3. PER EFFECT: a keyed model that sees one effective key with two
   different argument hashes fails (one key, two effects). A repeat
   with the same hash is absorbed and is correct. Under `exactly_once`
   a plain `effect` model called twice for one delivery fails.
4. LAWS: both ways agree.
5. The author's `spec`s pass under every schedule tried.

PERMITTED IS A NOTE. Under `at_least_once`, an unkeyed effect that ran
twice is printed as a note with its seed. It does not fail the run.

Schedules are seeded; a failure prints its seed and is shrunk to the
fewest faults that still fail. BEND's table promises "faults injected
by seed" (READ :557) and fibers §0 "interleavings are explored" (READ);
this is where both are paid. LIMITS: it explores the in-process models,
so a provider is covered as far as its declared terms; exploration is
bounded (`--faults=1000`).

## 12. Durable scopes — SKETCHED

Fibers §8 (READ :283-285): "`durable "name" { }` checkpoints at its
`}` per iteration; a failed child… restarts from the last checkpoint."
This keeps that model.

- A CHECKPOINT is the scope's live variables at the loop's `}`: plain
  data, written with the turn number to the scope's `@store`.
- RESUME reads the last checkpoint and runs the turn again from its
  top. So every effect in a turn may run twice, and each needs a key
  that survives the code changing between the two runs.
- THE STEP KEY is `(scope name, turn, callee's stable name, n)`, `n`
  counting this turn's calls to that callee — §7.2's rule. A step may
  be NAMED (`key.at("deposit")`), which replaces `(callee, n)`.
  Ordinals in the turn are not used: inserting an unrelated effect
  shifts nothing.
- THE STEP TABLE records, per step key: the argument hash and the
  answer. On the re-run: same key and same hash → the recorded answer
  is returned and the effect is not called; same key, different hash →
  `Err(StepChanged)` and the scope stops for a human (the provider
  would have absorbed a DIFFERENT effect silently).
- READS ARE STEPS. A `reading` effect, a clock read and a random
  number are recorded like any step and replayed. An answer over 64 KiB
  is `flow.too_many`: read it through a home that keeps, which is
  recorded as a cursor.
- A SLEEP IS A STEP whose answer is the absolute wake time. A resumed
  turn sleeps what is left.
- A `select`'s claimed arm is a step.
- Inside a turn, an effect with no `keyed` seat and no store is
  `flow.unkeyed_in_durable`.
- VERSION SKEW. At a checkpoint only the live variables' SHAPE must be
  compatible, and growth is (§6.3). `avra build --against <store>`
  reads the scope table with the deploying principal's own credentials
  (no access: "not checked", never silence) and reports, per scope in
  mid-turn: its recorded steps against the new build's sequence of
  keyed calls for that turn — "3 scopes are mid-turn at fulfil.av:41;
  this build's `charge#1` has a different argument shape".

OWED before this is a design: a lease on the scope's name (the epoch
of §6); retention of finished scopes; signals and queries into a parked
scope; child scopes and compensation ("committed work is compensated,
never rolled back" — AUTHORITY_AND_RECEIPTS :159, READ); float bits
across architectures.

## 13. Folds over time, batches, protocols

### 13.1 `scan`, and maintained folds

- `s.scan(init, step)` is the running fold: a stream of states. It is
  what every stream library calls `scan`; no law, nothing new. Over a
  `.latest` source it is what a view binds.
- A MAINTAINED fold takes changes back. SKETCHED, DEPENDS-ON a source
  of `Change<T>`:

  ```avra
  enum Change<T> { Added(v: T), Removed(v: T) }

  // on Stream<Change<T>>:
  fn live<S>(init: S, add: fn(S, T) -> S, undo: fn(S, T) -> S) -> Stream<S>
  fn live_by<K, S>(key: fn(T) -> K, max_keys: int, init: S, add: fn(S, T) -> S, undo: fn(S, T) -> S) -> Stream<Map<K, S>>

  law undo_takes_back {
      for s: int
      for x: Order
      undo(add(s, x), x) == s
  }
  ```

  The law is about the two fns the verb is given. `max_keys` is law 23:
  past it the stream fails `TooMany`. Status rules are §10.1's; an
  inverse over floats is `flow.float_law`, so a float total re-folds.
- WHO GIVES `Change<T>`: a queue with `keeps` and a `remove(id)` verb
  (designable on §6.4's tables, not designed); and `@std/relation`,
  which is built as an in-memory, incremental, optionally durable
  database (`@relation`, `@query` — READ(agent) `std-relation/src`) but
  does not publish a query's changes. That publication is what this
  needs, and it belongs to the store campaign. The compiler's own
  query kernel is compile-time; no claim is made on it.

### 13.2 Batches and time

- `.batch(n, within: d)`: lists of up to `n`, flushed after `d`. A
  `select` over the source and a `Deadline` bound per batch. DESIGNED.
- `.at_once(n)`: up to `n` calls of a waiting stage, answers in input
  order; it starts item `k` only while `k − oldest unfinished < n`, so
  at most `n` answers are held. `order: .any` gives them as they land.
- `merge(a, b)` is `any([a, b])`. `zip` needs one side running.
- EVENT TIME is not designed. Owed: where an item's time comes from, a
  watermark per source, a lateness policy, windows, and whether a
  window's close is a `Removed`.

### 13.3 Protocols

- `svc.ask(q) -> Result<A, AskError>`: a request carrying a reply id
  and what is left of the asker's `within`; the handler runs inside it;
  expiry answers `TimedOut` at the asker and the outcome there is
  unknown, which is what the id is for. DESIGNED over a queue pair.
- SESSION TYPES need a value that cannot be used after a step. Consumed
  seats are inferred and "may not enter type identity" (READ(agent)
  REUSE §34). Not designed, for that reason.
