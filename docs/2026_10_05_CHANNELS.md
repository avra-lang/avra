# FLOW — streams, channels, `select`, and where they live

Design only. Nothing here is built. Ticket avra-8sb5.34.53; the
codebase survey is docs/2026_10_05_CHANNELS_CANVAS.md.

Claims about today's compiler are marked PROBED (run on `bd36bf7`,
`build/avra run` on a scratch package, result quoted) or ASSUMED.
Prior decisions are cited by file and section.

## 1. The one idea

1. A STREAM is values over time, then an END with a cause. It is a
   recipe — a value, like a list.
2. A WAIT is the one way a task stops for anything: an item, room, a
   timer, a descriptor, a task's answer. One protocol, one runtime
   door.
3. A CHANNEL is what a stream becomes when its producer and its
   consumer are in different HOMES. The home (this task, another task,
   another core, a disk, another machine, a device, the past) decides
   the mechanism; the text does not change.
4. The CONTRACT (what is delivered, in what order, how much is held,
   what happens to a failure) is in the type and the declaration. The
   home must be able to keep it, and the compiler refuses one that
   cannot.
5. Because every wait goes through one door, that door can be
   scripted: tests, virtual time, replay and durable work are the same
   mechanism.

### The false choices this dissolves (P6)

| choice | what holds instead |
|---|---|
| sync / async | a wait parks the task; no colour (spec 13.4, fibers §0) |
| push / pull | `yield` pushes into a `for` that pulls; fused, they are one loop |
| stream / queue | a queue is a stream whose home keeps items when nobody reads |
| local / remote | one declaration; the home is bound per deployment |
| in memory / durable | delivery is a contract term; the home is checked against it |
| lazy / eager | a stream is a recipe; a name bound to a list chain is still a list (COLLECTIONS 09-30 D2) |
| CSP / actors / dataflow | a channel between tasks; a task reading one channel is an actor; a chain is dataflow |
| library / language | one keyword (`select`), one statement (`yield`), four runtime rows; the rest is `@std/task` |
| close by hand / leak | a channel ends when its last writer is done |
| exactly once / at least once | at least once plus a law or an id; "exactly once" is derived, never set |
| test / production | the same program, with the wait door scripted |

### 2.1 Two tasks, a bounded channel, backpressure

```avra
use @std.task.{channel, Sink, Source}

fn crawl(urls: List<string>, out: Sink<Page>) {
    for u in urls {
        if !out.send(fetch(u)) { return }   // parks while 8 pages wait
    }                                       // false: nobody reads any more
}

fn index(pages: Source<Page>) -> int {
    mut n = 0
    for p in pages {                        // ends when `crawl` is done and
        store(p)                            // the last page is taken
        n = n + 1
    }
    n
}

let pages = channel<Page>(8)
let crawler = spawn crawl(seeds, pages)
let indexed = spawn index(pages)
println("${indexed.await} pages")
```

Nobody closes `pages`. Its one writer is `crawler`; when that task
finishes the channel ends (law 6). The seat types say which end each fn
may use (law 5).

The producer as a stream, which needs no channel until one is asked for:

```avra
fn pages_of(urls: List<string>) -> Stream<Page> {
    for u in urls { yield fetch(u) }        // a reader that leaves ends this fn here
}

for p in pages_of(seeds) { store(p) }             // one task, one loop
for p in pages_of(seeds).run(8) { store(p) }      // two tasks, 8 pages between
```

### 2.2 `select` over a watch, a channel, a timer and a signal

```avra
use @std.task.{select, after, Source}
use @std.io.watch.{watch}

fn dev(root: string, built: Source<Built>, quit: Source<Signal>) -> Result<int, IoError> {
    let w = watch()?
    defer w.close()                          // runs on return and on a stop
    w.add(root)?
    mut dirty = false
    while true {
        select {
            _ in w -> { dirty = true }
            w.ended -> { return 1 }
            after(ms(50)) if dirty -> {      // 50 ms with no save: build once
                dirty = false
                rebuild()
            }
            b in built -> report(b)
            built.ended -> { return 1 }
            _ in quit -> { return 0 }
            quit.ended -> { return 0 }
        }
    }
}
```

- An arm is `binder in source -> body`. `for x in s` takes every item;
  an arm takes one.
- A source that can end needs its `.ended` arm, as a `match` needs
  every variant (law 9).
- `after` is made on every turn, so this is a debounce by construction.
- There is no cancellation arm. A `within` around `dev`, or the block
  that spawned it failing, stops it at whatever it is waiting on and
  the `defer` runs (law 11).

### 2.3 One pipeline, three homes

```avra
fn scores(lines: Stream<string, IoError>) -> Stream<int, IoError or ParseError> {
    lines.map(parse(it)?).filter(it.valid).map(score(it))
}

law add_associates {
    for a: int
    for b: int
    for c: int
    add(add(a, b), c) == add(a, add(b, c))
}

// this task: one loop, no buffer, no closure box
let a = scores(read_lines("day.log")).fold(0, add)?

// every core: the same fn
let b = on .cores { scores(read_lines("day.log")).fold(0, add)? }

// fed by a queue on another machine: the same fn
let c = scores(events.map(it.line)).take(100000).fold(0, add)?
```

`avra explain flow` on the second:

```
scores(…).fold(0, add)                       on .cores (8)
  read_lines   this task        64 KiB pieces → lines
  ── chunks of 4096 lines, numbered ──────────────── 8 workers
  parse        pure ✓           fails: ParseError → ends the stream, stops read_lines
  filter       pure ✓
  score        pure ✓           vectorised: no (calls `lookup`, a Map read — main.av:22)
  ── joined in chunk order ─────────────────────────
  fold add     tree over chunk numbers — licensed by law add_associates (proven)
  crossing     lines copied into the ring (plain data ✓), 1.1 MiB peak
```

### 2.4 A worker with retries and a dead letter, declared

```avra
queue emails of Email {
    delivery: .at_least_once
    retries: 3
    backoff: secs(5)
    dead: undeliverable
}

queue undeliverable of Dead<Email, SmtpError>

worker sender {
    reads: emails
    at_once: 10
    restart: backoff(ms(100), secs(30))
    each email { smtp.send(email.item, key: email.id)? }
}

fn signup(u: User) -> Result<User, DbError or QueueError> {
    let saved = db.insert(u)?
    emails.send(welcome(saved))?            // answers the item's id; a home can refuse
    saved
}
```

- `email` is a `Delivery<Email>`: `.item`, `.id`, `.attempt`. The id
  reaches `smtp.send`, which is what lets the compiler accept an effect
  under at-least-once (law 14).
- Leave out `dead:` and the build refuses: the worker can fail with
  `SmtpError` after three tries and nothing says where the email goes
  (law 13).
- No home is written. In `avra dev` and `avra test` the queue lives in
  the process. A deployment binds it (§10).

### 2.5 An error across three stages and a process boundary

```avra
let made = on .cores {
    uploads.stream()
        .map(decode(it)?)                 // stage 1
        .map(resize(it, 512)?)            // stage 2
        .map(encode(it)?)                 // stage 3
        .fold(0, count)?
}
```

`encode` fails in another process. What the author sees at the `?`:

```
error: ImageError.Unsupported("cmyk jpeg")
  at codec.av:88    encode → jpeg.write
  in stage 3 `encode`      core 3 (pid 4127), chunk 17, item 2
  ← item uploads#0193      sent at api.av:41 `uploads.send(photo)?`
  ← request POST /photos   trace 7f3a91
  the stream ended here: 7 other cores were stopped, 4094 items unread went back to `uploads`
```

One failure, three directions (law 12): downstream sees the end with
its cause, upstream is stopped, the owner gets the value at its `?`.
The error is an enum, so it is plain data and crosses the boundary
whole; its trace gains a frame per hop (§7.4).

### 2.6 The UI loop and a `fetch` answer

```avra
// @std/ui: the whole of `mount`, every target
export fn mount<V: View>(view: fn() -> V, theme: fn() -> Theme = plain) {
    let on = app(view, theme, host.show)
    on.paint()
    while true {
        select {
            act in on.inbox -> on.turn(act)                     // a control spoke, an answer landed
            on.inbox.ended -> { return }
            after(on.frame_left()) if on.dirty.get() -> on.paint()
        }
    }
}

// an author's handler
on press {
    saving.set(true)
    app.run(() -> save(draft.get())) { r ->                     // a task the app owns
        saving.set(false)
        saved.set(r)
        true
    }
}
```

- `on.inbox` is a `Channel<Act>`. The host's events, timers and every
  task's answer `send` into it. `App.turn` stays the one door
  (docs/2026_10_05_UI_ARCHITECTURE.md law 7); the channel is how more
  than one thing reaches it.
- Paint is the timer arm: many turns in a frame, one paint.
- On wasm the same loop is the host's (§6.6): `act in on.inbox` becomes
  the `event` export, `after` a `requestAnimationFrame`.

### 2.8 Tests, with no clock and no network

```avra
spec "dev rebuilds once per burst" {
    given "three saves 10 ms apart, then quit" {
        let built = recorded<Built>()
        let quit = scripted([at(secs(1), Signal.Term)])
        touch_at([ms(0), ms(10), ms(20)], "src/main.av")
        let code = dev("src", built, quit)?
        then "one build, 50 ms after the last save" {
            expect(rebuilds() == 1)
            expect(elapsed() == secs(1))             // virtual: the test took no time
        }
    }
}

spec "sender gives up on a refused address" {
    given "an smtp that always refuses" {
        let smtp = refusing()
        emails.send(welcome(ada))?
        settle()                                     // run until every task waits on nothing scripted
        then "three tries, 5 s apart, then the dead letter" {
            expect(smtp.calls == 3)
            expect(elapsed() == secs(10))
            expect(undeliverable.length == 1)
            expect(undeliverable.next()?.cause is .Refused)
        }
    }
}
```

`avra test` scripts the wait door: time jumps to the next timer when
every task waits; ready tasks run in seeded order; a failure prints
its seed (fibers §0, decided 2026-09-22).

### 2.9 Where a spelling changes, and why

| prior | here | why |
|---|---|---|
| `msg = ch.receive() -> { }` (spec 18.5, fibers tour) | `msg in ch -> { }` | The prior head is a call that must NOT run — the one unevaluated call in the language — and its callee must lose nothing when another arm wins. A source value has nothing to undo. `in` is `for`'s binder. |
| `match msg { m? -> …, null -> … }` inside the arm | `ch.ended -> …` arm | An end the compiler can demand (law 9). A nested `null ->` is optional by construction. |
| `default ->` (spec 18.5) | `else ->` | `else` is already Avra's "otherwise" (`let … else`); no new word. |
| `receive()` (spec), `recv()` (old tree) | `next()` | Already this tree's word for the act: the watch, SSE's `Source.next`, `next_piece`. A stream is not only a channel. |
| "chosen non-deterministically" (spec 18.5) | rotation (law 10) | Fair without a random number: the two engines must agree, and a test must replay. |
| `Channel.new<T>(capacity: 100)` answering `(send, recv)` (spec 18.4) | `channel<T>(100)`, ends named by seat types | Tuples are not built (PROBED: "pairs as values arrive with tuples"). The seat's type is the direction. |
| capacity 0 = unbounded AND rendezvous (spec 18.4) | `channel<T>(0)` hands over; `unbounded_channel<T>()` is its own name | The spec gives 0 two meanings (flagged in docs/2026_09_06_STD_HTTP_DESIGN.md "Laws to design before sugar"). |
| `ch <- v`, `<- ch` (old tree xphase7) | `send`, `next` | The old tree's own bootstrap dropped the operators for methods. |
| `source \|> spawn parse` (spec 18.2) | `.run(n)`, `.at_once(n)` on a chain | Chains are methods (COLLECTIONS 09-30, accepted). `\|>` does not parse (PROBED: "expected BREAK"). |
| channel combinators that each spawn a task (old tree xphase7) | chain verbs fuse; a task only where asked | One loop until a boundary is written (COLLECTIONS D2). |

## 3. The laws

1. **A stream is a recipe.** `Stream<T>` is a value: return it, store
   it, copy it. Nothing runs until something walks it. Walking twice
   runs it twice.
2. **A source is running.** `Source<T>` is an identity: a channel's
   reading end, a watch, a socket, a stream after `.run(n)`. Each item
   goes to one taker. `select` takes sources, never recipes.
3. **One wait.** Every parking verb is `wait` on something that
   implements the wait protocol (§6.1). Nothing else parks a task.
4. **A channel says how much it holds.** `channel<T>(n)`. Full, a send
   parks: that is backpressure. `0` hands over. Unbounded is
   `unbounded_channel<T>()`, a name a reviewer can search for, and
   `explain` marks it.
5. **A seat names its end.** `Sink<T>` may send. `Source<T>` may take.
   `Channel<T>` may do both and fills either seat.
6. **A channel ends when its last writer is done.** A writer is a task
   whose body sends to it, or the block that holds it and sends. A
   task is done when it finishes, a block at its `}`. `close()` ends
   it early. Nobody has to.
7. **An end has a cause.** Clean, or the failure that ended it. A
   stream that can fail is `Stream<T, E>`; a `for` over it must hear
   the failure (`for x in s? { }`), or the build refuses.
8. **A send answers whether anyone can still take it.** `false` means
   every reader is gone. The answer must be read; `yield` reads it and
   returns.
9. **A `select` is exhaustive over ends.** An arm that takes items
   from a source that can end needs that source's `.ended` arm.
10. **Arms take turns.** A `select` starts its scan one past the arm
    it took last. A ready arm is passed over at most `arms − 1` times.
    `select first { }` scans in written order instead.
11. **Every wait hears its task's stop.** A stop comes from the scope:
    a deadline (`within`), a failed block, a lost `race`. The task
    unwinds to that scope, its `defer`s run, and the scope answers
    (fibers §0, §4). Cancellation is never an arm and never a
    parameter.
12. **A failure travels three ways.** Downstream as the end's cause.
    Upstream as a stop. To the owner as a value at its `?`. None of the
    three can be dropped silently.
13. **No item is left behind.** A consumer that can fail says where a
    failed item goes: retried, dead-lettered, or dropped by name. The
    build refuses a silence.
14. **At least once needs a law or an id.** A handler on an
    at-least-once stream is pure, or proves `step(step(s, x), x) ==
    step(s, x)` by a `law`, or passes the delivery's id to every effect
    it reaches. Otherwise it is refused. "Exactly once" is what
    `explain` prints when one of the three holds; it is never a
    setting.
15. **Order is a contract term.** `ordered`, `by(key)`, or `any`. A
    fold over `any` needs a commutativity `law`. A home that cannot
    keep the order is refused at the binding.
16. **Loss is spoken.** A channel that drops (`overflow: .latest`,
    `.drop_oldest`) counts what it dropped; `lost` reads the count and
    the metrics carry it. (The watch's `.Everything` is this law
    already — docs/2026_10_05_FILE_WATCH.md §2.)
17. **What crosses depends on the home.** Same core: anything, and a
    dying unique value moves without a copy. Another core, a disk,
    another machine: plain data only. A device: flat numbers. One
    predicate, the one F2111 already applies to an `isolated` seat.
18. **A crossing value carries no authority.** A handle, a capability,
    a session, a closure are refused at a durable or remote home. A
    queued item is intent (docs/2026_09_29_AUTHORITY_AND_RECEIPTS.md §1).
19. **The home is not in the code.** A declared queue runs in the
    process until a deployment binds it. A binding is checked against
    the contract at build.
20. **A hop is recorded.** A send stamps the item with the sender's
    trace; a take makes it the parent of the work. A failure's trace
    reads across hops.
21. **A durable scope reads the world only through a wait.** Its waits
    are journaled; replay with the journal reproduces it. The compiler
    refuses a clock, a random number or an environment read inside one.
22. **Collecting a stream names its bound.** `take(n)`, `.list(max:
    n)`. (HTTP design law 1: "Collecting a stream is explicit and
    bounded.")

### Attacks

| attack | what happens | law |
|---|---|---|
| slow consumer | the buffer fills, the sender parks; across a socket the window closes; a lossy channel counts | 4, 16 |
| consumer leaves early (`take(10)`) | reader count reaches 0; `send` answers `false`; `yield` returns; `defer`s run | 8 |
| producer forgets to close | nothing to forget; the last writer finishing ends it | 6 |
| block sends, then joins its readers without closing | the block's hold is released at its `}`, before the joins | 6 |
| a ring: A reads B's channel, B reads A's | neither count reaches 0. Provable in one block: refused, naming both. Otherwise the runtime's deadlock trap, printing the wait graph | 6, §6.5 |
| `send`'s answer ignored in `while true` | refused: `flow.unheard_send` | 8 |
| `select` that starves an arm | rotation bounds the bypass | 10 |
| a source ends inside a `select` loop | the `.ended` arm is required | 9 |
| deadline passes while parked on `next()` | the wait hears the stop; the task unwinds to the `within`, which answers `TimedOut`. `next()` never answers null for it | 11 |
| deadline passes mid-hop to another machine | the asker's `within` answers; the outcome there is unknown, so the item's id makes the retry safe | 14, §7.3 |
| dead worker | its channel outlives it; the item in flight is redelivered (at least once) or goes to the dead letter with `.Crashed` (at most once); `restart:` says what next | 13, §7.2 |
| duplicate delivery | law 14 was the admission test | 14 |
| poisoned message | after `retries` it is a `Dead<T, E>` with cause, trace and attempts | 13 |
| partition | a send to a remote home parks, then fails at its `within`; an outbox home keeps it on disk and the trace shows the gap | §5, §9 |
| a value that cannot cross | refused at the send, naming the field that holds the identity | 17, 18 |
| a task that leaks | cannot: tasks are joined at their owner's `}` (fibers §4b) and every wait hears a stop | 11 |
| unbounded buffer | only by its name; `avra cost` answers `Unbounded(site)` | 4 |
| reentrant handler: a UI handler sends to the inbox its own loop drains | `send` from the only reader of a full channel is the deadlock trap at once; handlers use `post`, which never parks | §6.3 |
| nullable items (`Stream<int?>`) | refused: the end would be a second null. Name the absence in an enum | §4 |
| a recipe walked twice over a source | each walk takes different items; warned once, as F2106 warns of a copy | 1, 2 |
| `yield` inside a nested lambda | refused: a `yield` belongs to the fn that answers the stream | §4 |

## 4. The types

| type | is | made by | may |
|---|---|---|---|
| `Stream<T>` / `Stream<T, E>` | a recipe | a fn with `yield`; a chain; `stream()` of a source | be walked (`for`, a chain, a fold), be run |
| `Source<T>` / `Source<T, E>` | a running supply (protocol) | `channel`, `.run(n)`, `watch()`, a connection, `every(d)` | `next()`, `for`, an arm, `.ended`, `stream()` |
| `Sink<T>` | a running demand (protocol) | `channel` | `send`, `post`, `offer`, `close` |
| `Channel<T>` | a buffer with both ends | `channel<T>(n)` | all of the above |
| `Task<T>` | a source of exactly one item (built) | `spawn` | `.await`, an arm |
| `Delivery<T>` | an item with `id`, `attempt`, `trace` | an at-least-once source | be read; its id passed on |
| `Dead<T, E>` | an item that failed for good: `item`, `cause`, `attempts`, `trace` | a consumer's policy | be read from the dead letter |

A declared `queue` never ends, so its `send` has nothing to say about
readers. It answers `Result<string, QueueError>`: the item's id, or the
home's refusal. In the process the error side cannot occur; the text
is the same either way.

WRITTEN: the element; the capacity; a seat's end; `E` on a fn's
answer (or `_`, when ERROR_UNIONS phase 2's inference reaches streams);
on a declared queue, the contract terms that differ from the defaults.

INFERRED: `E` through a chain (`.map(parse(it)?)` adds `ParseError`);
who writes and who reads a channel (from each task body's uses); the
crossing level (from the homes on each side); whether a stage is pure
(`Reach`, BEND §3.1); "exactly once"; where a fused chain needs a task.

CONTRACT TERMS of a declared stream, with their defaults:

| term | values | default |
|---|---|---|
| `delivery` | `.at_most_once`, `.at_least_once` | `.at_most_once` |
| `order` | `.ordered`, `.by(key)`, `.any` | `.ordered` |
| `capacity` | an int | required |
| `overflow` | `.park`, `.latest`, `.drop_oldest`, `.drop_newest` | `.park` |
| `readers` | `.share` (each item to one), `.each` (every reader sees all, by cursor) | `.share` |
| `keeps` | `.nothing`, `.last(n)`, `.all` | `.nothing` |
| `retries`, `backoff`, `dead` | consumer policy | none |

`readers: .each` with `keeps: .last(n)` is SSE's `Feed` (a ring log
and a cursor per observer). `.share` is a work queue. HTTP design law
4: "Broadcast and competing-consumer queues are different" — here they
are two values of one term.

### Refusals (kind, then the words)

| kind | words |
|---|---|
| `flow.capacity` | a channel says how much it holds — `channel<T>(n)`, or `unbounded_channel<T>()` to make memory the limit |
| `flow.unheard_send` | `send` answers whether anyone can still take the value — read it, or `yield` |
| `flow.unheard_end` | `lines` can end with `IoError` and this `for` does not hear it — `for line in lines? { }` |
| `flow.end_arm` | `jobs` can end and this `select` does not say what then — add `jobs.ended -> …` |
| `flow.recipe_arm` | an arm waits on something running; `lines(p)` is a recipe — run it first: `let l = lines(p).run(n)` |
| `flow.guard_binder` | an arm's guard is read before the wait, so it cannot name what the arm takes — test it in the body |
| `flow.never_ends` | `workers` read `jobs`, and this block still holds it for writing when it joins them — `jobs.close()` first |
| `flow.ring` | `a` ends when `left` finishes and `b` when `right` does, and each reads the other — one of them must `close()` |
| `flow.wrong_end` | a `Source<T>` seat takes; `send` belongs to a `Sink<T>` |
| `flow.nullable_item` | a stream's items are present values — name the absence in an enum |
| `flow.stray_yield` | `yield` belongs to the fn that answers the stream |
| `flow.crossing` | `Job.db` is a `Db`, an identity, and `jobs` lives on another core — a crossing value is plain data |
| `flow.authority` | `Order.session` carries authority, and `orders` is durable — a queued item is intent |
| `flow.no_fate` | `sender` can fail with `SmtpError` after 3 tries and nothing says where the email goes — `dead: <queue>`, or `on failed { }` |
| `flow.duplicates` | `emails` delivers at least once and `sender` reaches `smtp.send` without the delivery's id — pass `email.id`, prove the handler idempotent with a `law`, or write `duplicates: .accepted` |
| `flow.order` | `total` folds with `sub`, which has no commutativity law, over `orders`, whose order is `.any` |
| `flow.home` | `sqs` keeps `.any` order and `orders` promises `.by(account)` — bind a home that keeps it, or change the contract |
| `flow.unbounded_collect` | collecting a stream names its bound — `take(n)` or `.list(max: n)` |
| `flow.world_in_durable` | a durable scope reads the world only through a wait — `now_ms()` here would differ on replay |
| `flow.exactly_once` | "exactly once" is not a setting — it is what holds when the handler is pure, lawful or keyed |

## 5. Homes

| home | spelled | mechanism | cost | crosses | delivery · order | backpressure | fails how | `explain` shows |
|---|---|---|---|---|---|---|---|---|

## 6. `select`, and the wait protocol under it

### 6.1 The protocol

```avra
/// Something a task can wait for.
export trait Wait<T> {
    fn taken() -> Taken<T>     // never waits
    fn signal() -> Signal      // what to park on until `taken` may answer
}

export enum Taken<T> { Item(v: T), Pending }

export enum Signal {
    Readable(fd: int)
    Writable(fd: int)
    At(ms: int)                // the scheduler's clock
    Gate(g: Gate)              // another task in this process
    Any(of: List<Signal>)
    Never
}
```

- `Signal` is DATA, a closed list: the operating system, the clock,
  another task. Every wait there can be is one of the three, so the
  runtime never calls back into Avra to ask.
- A blocking verb is `wait(x)`: take, or park on the signal and take
  again. Every `try`/park/recurse loop in the tree today is this fn
  written by hand: 16 sites on `bd36bf7`, 6 parking on a descriptor
  and 10 on a bell (grep, tests excluded).
- A `Source<T>` is a `Wait<T>` for its items plus `ended`, a `Wait` for
  its cause.
- PROBED: a generic trait, an impl of it at one type, a bound naming it
  (`fn take<S: Source<int>>(s: S)`) and a default method all compile
  and run. `dyn Source<int>` does not parse ("expected `)`"), and `impl
  Source<T> for Channel<T>` is F2031 — §11 lists both doors.

### 6.2 The construct

```
select_stmt = "select" ( "first" )? "{" ( arm | BREAK )* "}"
arm         = ( pattern "in" )? expression ( "if" expression )? "->" body
            | "else" "->" body
```

- An arm's expression is evaluated once, on entry, top to bottom. Its
  type implements `Wait<T>`; the pattern binds the `T`.
- A guard is evaluated on entry. A false guard removes the arm for
  this turn. (The old tree had it both ways — xphase7 test 1.17 after
  the receive, `select_syntax/mod.rs` before. Before is the one that
  can turn an arm off.)
- `else` runs when nothing is ready now. A `select` with `else` never
  parks.
- `select` is an expression. Its arms agree on a type, as a `match`'s
  do.
- With no arm able to fire and no `else`, the task waits for its stop;
  with nothing else alive that is the deadlock trap.

### 6.3 What ships as a source

| source | item | ends |
|---|---|---|
| `ch` (a channel's reading end) | `T` | last writer done |
| `ch.offer(v)` | `bool` — taken, or every reader is gone | once |
| `task` | its answer | once |
| `after(d)` | nothing | once |
| `every(d)` | a `Tick { late: Duration }`; `overflow: .latest`, so a late tick is counted, not queued | never |
| `x.ended` | the cause | once |
| `watch` | `Seen` | `close()` |
| `listener` | a `Conn` | `close()` |
| `conn.readable()`, `conn.writable()` | nothing | the peer's end |
| `signals([.Term, .Int])` | a `Signal` | never |
| `child.exited()` | an `Exit` | once |

`post(v) -> bool` never parks: `false` when full or ended. A handler
that must not wait uses it.

### 6.4 Fairness

Law 10. The cursor is one int in the enclosing frame. No random
number: the evaluator and the native build take the same arm, and a
recorded run replays. `select first` is for "check the urgent thing
before the work", and its starvation is the author's stated choice.

### 6.5 How it lowers

No new instruction. A `select` is a loop, a switch region and runtime
calls — shapes the IR already has (CLAUDE.md, the IR protocol's step
2).

```
heads evaluated → h0 … hn
loop:
    for i in rotation(cursor):  match hi.taken() { .Item(v) → run arm i, leave }
    else-arm, if any            → run it, leave
    k = avra_wait_park([h.signal() for h in heads])     // parks; hears the stop
    goto loop
```

- Level-triggered: a wake means "look again". A second taker winning
  the item is an ordinary re-park.
- The runtime rows (DATA, so registry rows; §11): a task may register
  on several signals, where today it holds one descriptor and one timer
  (`runtime/avra_fiber.c` — the reason `Race` in `std-net/src/net.av:685`
  parks on a private poller).
- A `Gate` is a wait queue in memory. `Bell` (`net.av:919`) is one
  built from a pipe pair because the runtime has no park/wake row.
- The deadlock trap prints who waits on what: every parked task, its
  signals, and for a gate the channel that owns it.

### 6.6 wasm, where the host calls in

docs/2026_10_02_WASM32.md: no fibers; "the socket poller is the JS
event loop"; a reactor exports per-event doors.

- A ROOT LOOP IS A REACTOR. A task whose body ends in `while true {
  select { … } }` or `for x in source { … }`, with no other wait inside
  an arm, keeps nothing between turns but its loop's variables. On wasm
  the compiler turns each arm into an export (or a host timer), the
  loop's variables into a record, and the loop into "return to the
  host". No stack is kept, so no fiber is needed.
- A wait INSIDE an arm (`fetch` in a handler) needs a second stack.
  Until compiler-made state machines land (WASM32 step 6) the build
  refuses it by name, as it refuses `spawn` today
  (`tools/wasm-refuses/fiber`). The UI's shape — a handler starts work,
  the answer comes back through the inbox — needs only the reactor.
- `after` is a host timer; `every` a host interval; a channel between
  two reactors is a queue the host drains.

## 7. Errors, supervision, deadlines, traces

### 7.1 Failure

- A stage's `?` ends the stream with that failure: the stream's `E`
  grows by it, as a fn's error set does (ERROR_UNIONS phase 1 §3,
  spelled `or`).
- Law 12, concretely, for `a.map(f(it)?).run(8).map(g(it)?).fold(…)`,
  when `g` fails: the fold's `?` gets the value; the channel's reader
  count is 0, so the task running `a.map(f)` sees `send` answer false
  at its next `yield` and returns through its `defer`s; whatever it
  held unread is dropped (at most once) or returned to its source (at
  least once).
- A per-item failure that should NOT end the stream is written at the
  stage: `.map(parse(it) catch { skip })`, or `.or_dead(bad_lines)`,
  which sends a `Dead<T, E>` and goes on. The policy is lexical and
  bounded, as the error epic requires of `retry` (docs
  2026_06_08_ERROR_HANDLING_EPIC.md §6.3, §6.8).
- A trap in a task is a failure at its owner, never the program's end
  (spec 2.3: "panics kill tasks, not programs").

### 7.2 Supervision

- THE CHANNEL OUTLIVES THE WORKER. A declared queue is module-wide,
  like a `const` (COMPONENT_EXPANSION §10 item 6). A worker that dies
  loses its stack, not its inbox. That is the part of Erlang's design
  worth keeping, without a mailbox owned by the thing that dies.
- `restart: backoff(from, to)`, `give_up: 5 in secs(10)` — the process
  research's vocabulary (docs/2026_09_04_STD_PROCESS_RESEARCH_supervision_pipelines.md
  §2.2). No `one_for_one`: the graph decides what a restart touches
  (§2.3 refused the config field). Restarting a stage restarts that
  stage; its neighbours park on the channels between them.
- The item in flight has a declared fate (law 13). There is no default
  `restart: always` (§2.3).
- A worker that gives up fails its owner. At the root that is the
  process's exit status, for the process manager above (fibers §13:
  "Restart is policy for a process manager above").

### 7.3 Deadlines and stops across a boundary

- A `within` belongs to a scope and is inherited by the tasks spawned
  in it (built, `runtime/avra_fiber.c`).
- A SEND carries no deadline. The sender's `within` bounds its own
  wait for room. The item outlives it: that is what a queue is for. An
  item's own lifetime is the contract's `expires`.
- An ASK carries the deadline. `svc.ask(q)` is a send plus a wait for
  the reply; what is left of the asker's `within` rides the envelope
  and the handler runs `within` it. Mid-hop expiry: the asker's scope
  answers `TimedOut`; a stop is sent after the request, best effort.
  The outcome at the far side is unknown (AUTONOMOUS_SYSTEMS §4.4:
  "'Request timed out' means 'outcome unknown'"), which is why the
  item has an id.
- A stop crosses a core by closing the channel (the cores' stop pipe
  is this already, `runtime/avra_cores.c:82`). It crosses a machine as
  a message. It never crosses a durable home: "Cancellation stops
  future work; committed work is compensated, never rolled back"
  (AUTHORITY_AND_RECEIPTS §7).

### 7.4 Traces

- A task has a trace id and a parent. `spawn` links them. `send`
  stamps the item; `next` makes that the parent of what the taker does
  next.
- In one process the stamp is one word per item and is compiled out
  unless something reads it: a failure's `trace()`, `explain`, a test,
  a remote home.
- `Traced<E>`'s frames (DIAGNOSTICS_ARCHITECTURE §2) gain hop frames.
  §2.5 is the rendering.

## 8. Pipelines, laws, vectors, cores, partitions

The chain is the same. What changes is what the compiler must know
before it may move a stage.

| moved to | needs | declared or inferred | refused when |
|---|---|---|---|
| one loop (fusion) | nothing: evaluation is per element (COLLECTIONS D3) | — | never |
| another task (`.run(n)`, `.at_once(n)`) | nothing: tasks share a core | asked for by the verb | never |
| SIMD | the stage is in the kernel fragment: scalar arithmetic over flat numbers, no allocation (BEND §5.1) | inferred; `explain` names the line that stopped it | never refused; reported |
| cores (`on .cores`) | the fork law: `Pure` or `Embed` reach, no `mut` capture (BEND §4.2); items are plain data | inferred | a stage reaches the world, or an item holds an identity |
| a parallel fold | an associativity `law` on the operator (BEND §4.3) | declared, then proven or checked | no law: the fold stays one lane, and `explain` says so |
| partitions (a queue with `order: .by(k)` or `.any`) | per key: nothing. Across keys: a commutativity `law` on what the consumer folds | declared | `flow.order` |
| at-least-once | law 14 | a `law`, or a flow fact (the id reaches the effect) | `flow.duplicates` |

- `.at_once(n)` runs up to `n` calls of the stage at a time and gives
  their answers in input order. `.at_once(n, order: .any)` gives them
  as they land. It is for stages that wait (a `fetch`); `on .cores` is
  for stages that compute.
- THE TREE IS FIXED BY THE DATA (BEND §4.3). A stream has no length, so
  the tree is over chunk numbers, and the chunk size is a constant of
  the program, never of the machine. The same bits on one core and
  sixty-four.
- PARALLELISM IS NEVER SILENT (fibers §0). An unpinned chain is one
  loop. `on` pins a placement; the cost model may suggest one, as a
  hint with the fix.
- LAWS CHOOSE HOMES. This is BEND's "the law unlocks the optimisation"
  one level up: a commutative, idempotent fold may read an unordered,
  at-least-once home — which is the cheap kind. A merge that is
  associative, commutative and idempotent is a replicated value
  (SHARING_MODEL §4.5's `Replicated<T>`), and its channel needs no
  order and no dedupe at all.
- COST. A bounded channel is an exact heap term: capacity × item size.
  `avra cost` (COST_MODEL §3) folds it; an unbounded one answers
  `Unbounded(site)`. A `deploy` budget is checked against it.

## 9. Durability, workflows, replay

- ONE DOOR IN, SO ONE LOG. Everything a task learns from outside
  itself arrives as the answer of a wait. Record those answers and the
  task can be run again to the same state.
- `durable "fulfil-${order.id}" { … }` (the word is fibers §8's): the
  scope's waits are journaled to a disk home. After a crash the body
  runs again; each wait answers from the journal until it runs out,
  then the scope is live. A task parked for nine days on a durable
  channel is a journal and a cursor, not a stack.
- THE COMPILER PROVES WHAT OTHER SYSTEMS LINT. Law 21 is a `Reach`
  check: inside the scope, every `World` row must be a wait. A clock
  read becomes `now()` through the door, journaled like any answer.
- THE JOURNAL NAMES ITS CODE. It records the body's structural
  fingerprint (the compiler has one for every fn). Replaying under a
  changed body is refused, naming the first wait that differs; a
  migration is a fn from the old journal to the new.
- A CHECKPOINT IS A SHORTER JOURNAL. At a loop's `}` the live variables
  are plain data or the scope is refused; writing them lets the journal
  be cut (fibers §8: "checkpoints at its `}` per iteration").
- THE SAME MECHANISM, FOUR USES:

| use | the wait door answers from |
|---|---|
| `avra test` | a script and a virtual clock |
| `avra replay <journal> --until 12:03:07` | a recording, stopped at a time |
| a durable scope after a crash | its journal, then the world |
| the UI's undo (UI_DERIVATIONS §C) | the event log, one shorter |

- Effects after commit: a durable scope's sends go to an outbox in the
  same write as its journal entry ("commit business state and the
  intent to perform an effect together", AUTONOMOUS_SYSTEMS §4.4).
- An agent is a durable task whose tools are asks and whose memory is
  a log: resumable, replayable, and auditable by construction (P2).

## 13. Open questions for the owner

1. **Arms: `x in source ->` or the spec's `x = source.receive() ->`?**
   Recommend `in` (§2.9). It costs a departure from the spec and the
   fibers tour; it buys an arm that cannot lose data and an end the
   compiler can demand.
2. **Two types, `Stream` (recipe) and `Source` (running), or one?**
   Recommend two. One type is the Rx bug; two costs `.run(n)` and
   `.stream()` at the border.
3. **A channel ends when its last writer is done (law 6), with
   `close()` as the early form — or `close()` only?** Recommend law 6.
   It needs the who-writes fact and a release at `}`; it removes the
   commonest concurrency bug in Go.
4. **Stop by unwinding, pulled ahead of the rest of fibers F7.**
   Channels work without it (a send answers a value), but `within`
   around a `next()` has no honest answer until it lands. Recommend
   slice 4, before streams.
5. **Rotation instead of the spec's non-deterministic choice.**
   Recommend rotation.
6. **Does a declared queue carry its home (`at sqs(…)`), or only the
   deployment?** Recommend the deployment binds and `at` on the
   declaration pins (P8). SHARING_MODEL §4.5 writes `state x: Remote<T>
   at node`; this keeps one word for both.
