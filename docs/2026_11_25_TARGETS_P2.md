## 2. The rows

```toml
[app]
id      = "dev.avra.board"        # reverse-DNS; every store and loader's one identity
name    = "Board"                 # shown name; [package] name stays the package's
icon    = "assets/icon.png"       # a bundled asset; each target cuts its sizes (P3)
targets = ["web", "terminal"]     # what `avra build` builds, in the author's order
server  = "server"                # the package beside this one that serves it

[target.ios]                      # deltas only, each key a row
min = "17.0"

[target.web]
base = "/"
```

**One change to the decided sketch: `[app]` takes no `entry`.** The entry is `[bin] path`, which
every command already reads (`entry_written`). Two spellings of one path is a second source of
truth (P12). A manifest with `[app]` and no `[bin]` is refused: an app runs a program.

**A target is a row in ONE table, in `compiler/targets.av`: a word, a triple and a host.**
```avra
/// A target a manifest or `--target` may name: its word, the triple it builds, the host it stands beside.
const TARGETS: table<TargetRow> {
    name       | triple                      | host
    "terminal" | ""                          | BuildHost.Process
    "web"      | "wasm"                      | BuildHost.Page
    "ios"      | "arm64-apple-ios-simulator" | BuildHost.Ios
}
```
- `platform_of(triple)` keeps the link facts (SDK, object dir, suffix). The row adds the host
  (P1), so the two axes are joined in one place and kept apart everywhere else.
- `ios` builds the simulator until signing exists (decision 6, `@std/config`). The device triple
  is one more row column then, not a second target. A simulator is where you run, not something
  you ship.
- `cli/shared.av`'s `triples_of` aliases become this table's `wasm` row. **P8:** `--target`
  still takes a raw triple, which is the escape hatch, and `--target wasm` keeps working for
  every script that spells it.

**The keys are rows, not another `if` in `known_key`.** `known_key`, `link_shape` and `link_help`
are three projections of one per-key fact. `[app]` and `[target.*]` would make a fourth copy, so
they land as one table: `section | key | shape | help`. That table answers "is it known", "what
does it hold" and "how is it fixed". The `[process]` keys keep their own voice
(`unknown_process_key`) as a column, not a branch.

**The refusals (named voices):**

| Kind | When |
|---|---|
| `manifest.unknown_target` | `targets` or `[target.X]` names a word no row has. The voice lists the known words |
| `manifest.bad_app_id` | `id` is not reverse-DNS |
| `manifest.app_without_bin` | `[app]` and no `[bin]` |
| `manifest.unshipped_target` (warning) | `[target.X]` for a target not in `targets`: a delta for nothing shipped |
| `manifest.dev_server_moved` (warning, `Remedy.Fix`) | `[dev] server`: "`[dev] server` is `[app] server` — the server is part of what the app is". The fix moves the line |

**`manifest.no_target` is renamed `manifest.no_entry`**, and `Reader.target` becomes
`Reader.entry`. Once "target" names a row in `TARGETS`, a second meaning of the word is a trap.

## 3. What `avra build` does with no `--target`

| Manifest | `avra build` | `avra build --target X` | `avra run` |
|---|---|---|---|
| no `[app]` (1610 of them) | the host's binary, as today, at today's path | `X` a target word or a triple | as today |
| `[app] targets` | **every target**, each under `build/<target>/` (decision 2), then the `server` package for the host. One line each, in order | that one | the **first** listed target, saying so on its first line; `--target X` picks another, with `server` running beside it |

- `build/<target>/` is per TARGET, not per platform. Two targets on one platform (a terminal
  binary and a later macOS `.app`) would collide under `binary_suffix`.
- `avra check` judges every target in `targets` (P1 §3): the answers, never the per-platform link.
- `avra dev`'s page test becomes "a target in `targets` stands beside `Host.Page`". That
  replaces `mounts_a_page`'s import of the module named `"@std.ui.web"`, a string tag that one
  `mount` breaks (P1 §4). With no `[app]`, the import test stays for one slice, as a bridge.

## 4. `[dev] server` to `[app] server`: bridge, then sweep

Measured, the sweep is **2 manifests and 1 script**, not 1606. And no compiler that builds the
tree reads either manifest: the seed and the cached binary build `packages/cli`, which has none.
So the bridge is two commits in **one** PR:
1. **Bridge:** the reader takes `[app] server` and still takes `[dev] server`, warning with the
   fix above. `backend_of` reads `Manifest.server`, one field. The voice in dev_backend.av says
   `[app] server`.
2. **Sweep:** `tools/ui-board`, `tools/ui-observed` and `tools/dev_server_check.sh` move to
   `[app]`, run through `avra fix --only manifest.dev_server_moved`, the fix proving itself.

`[dev]` is deleted in the slice after, once `grep -l '^\[dev\]'` answers nothing. An older
compiler reading `[app] server` warns `unknown_section` and serves no server. That is loud and
only affects a stale lane binary.

## 5. `[link]` objects per platform: the first row, as the iOS lane built it

```toml
[link]
objects = ["../../build/std_io.o", "../../build/std_io_watch.o"]   # named once

[link.objects_for]        # only where a platform differs, keyed by its object dir
wasm32 = []               # no body there: a page that reaches this C is refused by name
```
Folded in as built at 9589557f: `platform_objects(m, dir)` puts `dir` between an entry's
directory and its file, `wasm_objects` is gone, `tools/manifest_objects.sh --platform <dir>`.
**It stays keyed by the PLATFORM's object dir, not the target word.** Objects follow what a binary
links against: `terminal` and a later macOS `.app` share them, and device and simulator do not.
That is P1's host/platform split showing up a second time.

Two gaps to close in the same row:
- **A key no platform has** (`web = []`, `iphonesimulater = []`) is read today and matches
  nothing, silently. It becomes `manifest.unknown_object_dir`, which names the object dirs
  `object_dir` yields over every platform, and says "`web` is a target — objects are keyed by
  platform: `wasm32`" when the key is a target word.
- **A second manifest reader:** `tools/manifest_objects.sh` reads `[link]` with awk, beside the
  compiler's reader, and P2's sections would make that a third copy. The script asks the compiler
  instead (an `avra` or `wisp` verb printing a manifest's objects for a platform). That is one
  reader, which the keepers already need.

## 6. Asks for the ruling

1. `[app]` keys `id | name | icon | targets | server`, with **no `entry`** (`[bin] path` is the entry).
2. One `TARGETS` table (word | triple | host) in `targets.av`. `ios` is the simulator until signing.
3. `avra build` builds every target into `build/<target>/`, plus the server. `avra run` runs the
   first target and says which.
4. The manifest's known keys become one table. `manifest.no_target` becomes `manifest.no_entry`.
5. `[dev] server`: one PR, bridge then sweep (2 manifests, 1 script). `[dev]` is deleted the slice after.
6. `[link.objects_for]` lands as ios-sim built it, plus `unknown_object_dir` and one manifest reader.
