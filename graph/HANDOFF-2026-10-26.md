The 0.99 span this handoff predicted is `Maison Aster`. The organization actually owed never appears above 0.0, so no fitted threshold and no label wording in the declared space reaches it — `gloss`, `first_sentence` and the bare model name give byte-identical results (right=35, absent=3, mistyped=1 for all three).

**The mechanism is contextual blindness, and it is maximal-confidence in both directions.** The same span, same label:

```
"Velluto Works is our supplier."    -> organization 0.998
"Velluto Works to Maison Aster"     -> organization: 'Maison Aster' 1.0, person: 'Velluto' 1.0
     (in the invoice header, 'Velluto' falls to 0.132 product / 0.031 person /
      0.025 organization -- under the fitted 0.25 span threshold either way)
```

So a `X to Y` construction makes the encoder read one organization as a person and lose the other, and a possessive bare first name reads as an organization. There is nothing left to tune here: the two candidate fixes are mechanisms, and both need the owner's call.

1. **Feed the store's known entity labels in as mention candidates** — a record the graph already holds is evidence the text names it. Cheapest and most precise, but the extractor hook is a pure function of the envelope (`score.py` passes no graph), so this needs the extractor to see the store or the envelope to carry candidates.
2. **A closed-choice verification over a cross-label candidate pool** — the encoder proposes spans at a *lower* probe threshold, the scorer picks which is a `<Model>`. In s13 `Velluto` is already a candidate at 0.132 (under `product`), so a cross-label pool reaches it where a per-label one cannot; s04's email address sits at 0.003 and is probably unreachable either way. Needs a new fitted parameter and gym span gold that does not exist yet.

## Reporting: the judgement is Avra, not Python

`graph/measure` (`graph-measure`) is the measurement side, in Avra, and it reads only
recorded JSON:

```
graph-measure recall FACTS RESULTS [MORE RESULTS ...]      # recall_measure.py's numbers
graph-measure claims FACTS RESULTS                         # one line per oracle scalar
graph-measure loss   FACTS QUESTIONS SPLIT RESULTS         # loss_attribution.py's table
```

Built and tested on this machine (`./avra test graph/measure`, 27 cases). Both instruments
agree with the Python ones on `score-e2e-20261026T193654.json`: **recall on every one of the
180 claims** (182 records, 64 of 79 owed present, 92 of 180 scalars equal, 63 link / 4 new /
12 abstain), and **loss on every one of the 36 development questions**. Two laws the port
pinned with tests: a property the extraction never wrote is no evidence for a null value, and
an oracle stamp holds an epoch-millisecond int (so a year is four digits, not two).

What stays Python is the model side and nothing else: `extract/cascade.py` (GLiNER2 + Qwen3),
the socket service, and the harnesses that must call them to produce scores (`fit_*`,
`bench_*`, `score.py`, `gym/`). Their *judgement* halves belong here as they arrive.
`acceptance/recall_measure.py` and `acceptance/loss_attribution.py` are now cross-checks;
retire them once a second slice agrees from the other direction (they are also imported by
`extract/fit_spans.py`'s neighbours, so delete by import, not by file).

A run of Avra needs disk: `./avra` refuses under a 2048 MB floor and a link that runs out of
disk DELETES `build/avra`. This Mac sits at 1 to 3 GB, so `.avra-cache` (407 MB, a cache
keyed by the compiler's own bytes) is the thing to clear, and `cp build/avra build/avra.pre`
first is always right. That floor, not a language limit, is what made this lane Python.

## Findings, 2026-10-27 (second pass)

**The e2e costs ~50 minutes because caching is off unless `--resume`.** `score.py` sets
`CACHE = Cache(...) if args.resume and not args.heldout else None`; a run without the flag
re-extracts every source. 42 extractions at ~58 s of encoder compute each *is* the wall time
(the planner's own 180 `choose` calls cost 146 s in total, `link` 0.5 s). Run the e2e with
`--resume` and a repeat run is minutes.

**Three defects fixed this pass** (`283af450`), all measured:

- `answered()` had no `choose_many` door, so `structured.best_many`'s batched ask raised
  `KeyError: 'request'` and killed three questions. The door answers, and the planner falls
  back to one ask at a time when a service does not batch.
- A composition the graph refuses (e.g. `plan_refused: read plan exceeds its reference-depth
  budget`) exited the planner, so the question had no answer at all. It declines now. Errors
  3 -> 0.
- The kind shortlist is off. Its recall is a ceiling on what the record pass can emit, so
  k=5 moved questions from `field values` (13 -> 5) into `record pass` (11 -> 19) with the same
  24 dying. The calls it saves are the cheap ones.

**Where the 34 remaining failures die** (acceptance, `loss_attribution.py`, both runs agree):
`field values` 13, `record pass` 11, `entity pass` 5, `relation pass` 2, `planner/read` 2,
`no cited evidence` 1. The field-value bucket is not one defect; measured claim by claim:

| sources | want vs got | nature |
|---|---|---|
| s04 s13 s17 | `Organization.name` `Velluto Works` vs `Maison Aster` | the encoder never sees it (handoff §1); a mechanism, not a knob |
| s18 | 1 `OrganizationRole` emitted, 3 stated | the relation pass emits one reading per pair; the encoder's own structure query for the kind returns **all three** titles (`creative director`, `interim creative director`, `design adviser`), so what is lost is the pass's free-label mentions, not the model's recall |
| s27 | 1 `StockMovement` (units 18, no colour), 2 stated | the encoder's structure query returns **one** structure (colour `black`) for a sentence stating two movements, so the second is never proposed |
| s30 | `Commitment` condition from the other request, `PersonalTask.summary` absent | field spans are read sentence-wide, so two statements in one sentence mix |
| s28 s29 | `Product.code` = `R-88` / absent | the identity defect (handoff lever 3) |
| s08 | `ServiceOffer.proposed_on` = `"27 October"` | a declared `iso_date` property kept raw text |
| s20 s10 | `Pet.name` = `"Fig the cat"` | span carries the appositive |

The pattern behind the first three rows is one: **the encoders propose one thing where the text
states several**, and the pass keeps the first. That is the same class as the entity pass — a
mechanism (ask again, or split the unit) rather than a threshold — and it is the biggest
single bucket that does not need an owner call.
