## 2. The one remaining performance defect (fully diagnosed)

**A declaration's identity is its arena range, not a stable name, so no declaration-grain answer can
ever be reused by the next process.**

Evidence, `AVRA_QTRACE=1` on a warm edited check of `packages/std-io`:

```
12741 refs_index        reuse      1892 placement_of    reuse (758 compute)
 8196 signed            reuse       755 names_in        compute (868 reuse)
 1042 parsed_in         reuse       755 typed_body      compute
                                  758 syntax_in       compute, ZERO reuse
```

- `placement_of` is `@scoped_by(in_arena)` — its own doc says *"where this process's arena put it,
  which names nothing past the process"*.
- `typed_body` is `@scoped_by(in_scope)` and process-bound; `syntax_in` has no `@lasting` at all.
- A unit's answer embeds those ids, so it is un-reusable by construction (hence the write removal).

**This was known and deferred.** `docs`/ledger: `HOLD_DIARY` 2026-11-29 — "kept: 517/519 files; the
edited file's 583 declarations all recompute; **no per-declaration cache is retained across
processes** (DB 07b/c); only the edited file pays it, est. **1.8–1.6 s of a 4.5 s edit**." With the
hold gone the same defect applies to all 582 files, so its cost went 1 file → 582 and it is now the
whole edit. The estimate was right; its scope was 30× too small.

**The fix is one slice:** key and hash a declaration by *path + module + declaration symbol/ordinal*,
never by arena position. Then `@scoped_by(in_arena)` stops being a concept, `@lasting` can be inferred
(leaf closure), and `analyze`+`lower` become restore hits. This is the Nodes/DB epic work — the same
work, not extra — and it is the only route to ≤300 ms.

## Correction, same day: the arena-identity diagnosis was wrong

`L-identity` (`726958d4`, merged) gave `syntax_in` its `@lasting` (its fold is structural, as its own
comment claimed) and made `names_in` fold a WINDOWED `Ids` (`x.lo`, `x.stmt_lo`) so its digest no
longer names the whole file. Both are now genuinely durable — `syntax_in`'s restore failures drop to
zero and `names_in` stops changing per process. Measured wall: **flat** (58.0 → 57.5 s), and the
suite stays `1813/1814` with the one known red. So it fixes an unsoundness, not the wall.

**And it supersedes the §2 diagnosis.** `placement_of` appears in **1** `typed_body` record; the
arena-range story was not the blocker. What actually stops a typed body's record from restoring, in
the order the trace gives them:

1. **`Named` bucket digests — 17 272 leaf occurrences across 6 898 records.** A bucket digest is a
   snapshot of what has been MINTED SO FAR (`envs`' name→files is never filed, `note_producers` has
   no caller), so it differs on any later run by construction. A partial table read recorded as a
   dependency is a race, not a fact.
2. **Unsettled `Writes`/`Lifted` leaves.** `hash_asked` exists for query answers only, so a `@family`
   row read as a leaf can never settle its own hash.
3. **In-process `parsed_in`/`marks_of` reached through `signed`/`marks_of`.**

The next slice is (1) — make a bucket's content complete before anything folds it, or fold an
order-independent fact instead — then (2), give `@family` rows the `hash_asked` a query answer has.
`typed_body` is `bodies 15.5 s` of the edit, and it is the last big number.
