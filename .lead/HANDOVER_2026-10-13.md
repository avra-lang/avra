## 9. Lessons and tricks (earned this session)

**Method**
- Measure, then assign. Three confident attributions were wrong today. Trust only: a counted before/after on the SAME
  scenario, a function profile, `explain --stats --time`, or a two-process digest diff. Event-gap reading of a trace
  blames the event after the work.
- Verify before serve. `AVRA_DB_VERIFY` caught a real stale-serve bug (Lowered not reading its own Syntax) and proved
  0 mismatches elsewhere. Build the verify table first for any saved family.
- Ask what a change can move at most before building it (serve Typed: ≤1 s → shelved).
- Noise on a Sprite edit is ±1 s on 4–6 s. Small wins are invisible; use counts.
- Two cold processes on identical input agree 100%; a digest-stability receipt must SHIFT indexes (insert a fn at the
  top of `core/lists.av`).
- A leak "fix" behind a debug flag hides the leak. Ask for the attack with the flag on.
- When a lane retracts its own claim, thank it and re-plan; lanes then report honestly.

**Design rulings I made (keep consistent)**
- No ambient "current ids" global for durable fingerprints — a wrong lookup is a silent stale hit. The derive threads
  `ids` (`fingerprint_in(ids)`). Plain `fingerprint()` still exists on DeclId/TypeId (19 users) so a missed fold is
  silent; `digest_diff` is the detector until those move.
- `ids.decl` must not memoise a name asked before its file's rows settle (guard added; no unit test).
- Stable-name rows are latest-only (an undo recomputes); values stay content-addressed.
- A suspect set computed while only the entry file is admitted is unsound; recompute when the admitted count changes.
- Shared integration branch: fast-forward only; repair by merge/cherry-pick, never force.

**Process**
- Lanes stall on Monitors and background runs; check lane-file mtimes every heartbeat (`ls -lT .lead/lanes/*.md`) and
  nudge anything >40 min silent. Stop+resume if a nudge is ignored.
- Split by file to stop two lanes waiting on each other ("you edit derive.av, they keep filesaid.av").
- When a finding is central (two derived folds), give ONE lane the central change and move the others to receipts.
- The light gate is not a verdict; `full-ci` label gives one. Check a PR's NEWEST run for its current head — the
  rollup keeps stale reds.
- "fail 0s" checks on a just-readied PR are the cancelled draft run, not failures.
- Close PRs the moment they are superseded; close batch members when the batch merges.
- Before telling the owner a PR/branch state, run the command. I mis-cited once and reported a wrong ranking twice
  (relayed from a lane); say what was measured vs inferred.
- Sprite memory: one heavy process on the Mac at a time under `sh tools/watch.sh 6000 …`; the machine has panicked before.

**Useful commands**
- Meters: `make leaves` / `tools/leaves.sh [--check]`; `AVRA_LEAVES=1`; `tools/digest_diff.py A B` (on `db-registrations`).
- Why/where: `./avra explain --stats --time <pkg>`, `./avra explain --why <pkg>`, `./avra explain 'Family(subject)'`.
