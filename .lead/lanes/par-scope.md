
# par-scope — using the cores in the compiler (2026-10-12T21:35Z)
R = READ (opened the line), G = GUESS. Paths under packages/std-avrac/src unless noted.

## 1. What runs in parallel today
- LLVM object emit, ONLY: Avra builds each module on the main thread, then hands it to 4 pthread workers (backend/llvm_wrapper.c:1324-1405 R). Width is a constant 4, not cores (compiler/backend/llvm.av:197 R). Workers touch no Avra heap (module+context only) R.
- Link and tools: one `avra_spawn_status` child (compiler/build.av:759 R). Machine slots serialise whole compiles (tools/watch.sh:260-280, AVRA_BUILD_SLOTS default 1 R).
- CI `make -j$(nproc)` for runtime objects (.github/workflows/checks.yml:346 R). The suite runner showed no case-level parallelism (grep of suite.av, std-testing: nothing R; deeper read not done G).
- Runtime for Avra code: fibers are M:1 on ONE OS thread, rc is plain int32, non-atomic (docs/2026_09_22_FIBERS_DESIGN.md:§1, BEND doc §2.1 R). `parallel {}`/atomic rc: "designed, not built" (BEND §2.2 R). So NO in-process Avra threads exist.
- Cores = fork, share nothing (runtime/avra_cores.h; FIBERS §13 R). Built for http: a core keeps no descriptor but std three + listener, and answers only an accepted-count (avra_cores.h:20-35 R). It returns NO data. `isolated` (F2111) is a typing law on the maker seat: refuses a lambda capturing a Cell/task/ptr/fn/dyn (features/checks.av:1010-1040; fns/mod.av:51 R).
- Cannot cross a core/process: Cells (the workspace, Decls, TypeRegistry, NodeStore arenas, the memo are all Cells: CLAUDE.md identity laws R), closures, TypeId/DeclId/FileId numbers (process-local, COMPILER_DB §2 L5 R).

## 2. Phases by separability
(a) parse — MOST separable. `parse_program(lang, src, words)` (compiler/program.av:186 R) builds a FRESH per-file arena (core/store.av:163 R; ids are per-file indices, alloc_expr store.av:259 R). Pure in (lang, text, words) per its own doc (workspace.av:1318 R). "ast" 18 s ~ "parse" 20 s: both name the same lex+build work (workspace.av:1332-1340 R). Shared state: (1) `lang` closures/builders, read-only but NOT audited (G); (2) `words` = `unread_words(f)` reads OTHER files' tokens through the workspace (workspace.av:1363-1370 R); (3) a file whose `use` imports a grammar is parsed TWICE, plain then under blocks (workspace.av:1376-1385 R); (4) a dirty parse is run twice, quiet then telling (program.av:188-190 R); (5) the file SET is a worklist that grows as `use` lines admit modules (whole.av:131-141, admit_used R) — so a prefetch must speculate. `admit_all` also mints Decls (shared) — not parallel; it is the ~2 s gap.
(b) unit lowering — separable in SHAPE: `lower_unit(a, externs, w, settle, cross) -> Unit` is a value (lower/lower.av:313 R). Blocked: reads the shared Decls/TypeRegistry; mono and lowering MINT TypeIds in arrival order (report_layout_defects, whole.av:105 R "mono can still mint a fresh combination"); the Unit holds Body IR with TypeIds. The only existing codec keeps wants + code-hashes, not bodies (compiler/unit_rows.av:14-50 R).
(c) typing per declaration — shared sigs, Decls, Memo kernel; one derivation alive at a time (CLAUDE.md R). Hardest. G: no.
(d) settlements — each runs the evaluator against the workspace (hooks capture it) — identity-bound. G: no.
(e) LLVM codegen — ALREADY threaded (above). Remaining serial part is the Avra-side module build + `Lowered`->LLVM IR (llvm_emit.av) on the main thread; share of `build` vs clang/LLVM: UNMEASURED (G).

## 3. Three designs
(i) Process fan-out, workers return codec bytes. Needs: an AST codec for SyntaxArena (45 Cell fields, payload enums, recursive Expr/Stmt) — COMPILER_DB A13 says the codec must still grow payload enums and recursive records; refused today (R). No `avra_proc` return channel (cores answer a count only R). The store's per-writer `seg-<writer>.log` (§6.6) is design only: no `seg-` in code (grep R). A worker = `avra_spawn` of the compiler itself (re-exec exists for the suite, cli/src/stage.av per CLAUDE.md R). Saves: parse 20 -> ~5 s IF codec decode costs < 25% of parse (G); the decode lands in the main thread's heap, ids stay file-local so determinism is free for parse (shard by FILE, merge in FileId order). Risk: memory = N compilers resident (Mac laws R); decode may rival the parse (G).
(ii) In-process tasks on cores: DOES NOT EXIST. Needs atomic rc + `Shared`/isolated heaps (BEND §4, FIBERS §1 R). A multi-month language feature; wrong first step.
(iii) Build-level: per-package compiles in parallel. Cold `check packages/cli` is ONE program closure; packages are not separable units of the 80 s (G). Wins only suites/gates (already `-j` / Sprites). No help for the 80 s, little for CI's single build.
Cheapest real lever inside the existing machinery: EMIT_WIDTH 4 -> cores (CI box is 8+). Saves only the codegen tail of `build`, not `check` (G on size).

## 4. Recommendation
Slice 0 (measure, no code, read-only): (1) `AVRA_QTRACE=1` count `Q parse` per file: parse_trace.sh exists (tools/db_measure/parse_trace.sh R); doc says parse fires twice a file on warm edits (COMPILER_DB A8:978 R) — if cold also re-parses, KILLING THE DUPLICATE beats any fan-out; (2) split "ast" into lex vs build vs `lang` cost; (3) on `build packages/cli` read clock.mark spans emit/place/link (build.av:755-778 R) to see LLVM+clang share; (4) hash-compare two cold runs' parsed fingerprints for determinism.
Slice 1: if parse dup exists, dedupe (single-core win, zero risk). Else prototype ONLY the AST codec round trip in a scratch test (decode time / parse time ratio is the go/no-go for (i)). Acceptance: decode+merge <= 30% of the file's parse time, with fingerprints equal to the in-process parse (parsed_fingerprint) for every file in packages/cli.
Slice 2 (only if go): `check` pre-pass: list the root closure's files, fork N workers sharded by file, merge into the Parsed relation in FileId order; target parse+ast 20 s -> <= 8 s on 8 cores; cold check ~80 -> ~68 s. Honest ceiling: lower (38 s) and analyze (30 s) stay serial until atomic rc or TypeId-free unit codecs exist — Amdahl caps parallel-parse at ~15% of the cold run.
Wrong-bet guard: do not start on lower/typing; both mutate Decls/TypeRegistry by arrival order.
