# One path for every saved answer (2026-10-31)

## The problem
Every lane has been hand-building its own saved-answer mechanism beside the `@query` engine. Each has its
own writer, reader, codec, read list, validity check and cache:

| saved thing | hand mechanism | lane |
|---|---|---|
| typed bodies | saved_rows.av / leaves.av AnswerRef | hd-typed |
| lowered units | lowered_rows.av / unit_rows.av | hd-decl |
| declaration shapes, items | decl_rows.av, Items row, uses_kept.av | hd-decl, hd-hold |
| name environments | Producers / NameEnvs | hd-hold |
| const settlements | kept_settle.av, Settled rows | hd-typed |
| per-file diagnostics | filesaid.av, verdict.av, doc_rows.av | hd-verdict |
| proofs, linked binaries | Stored.Proof, Linked | hd-verdict |

So every bug was found and fixed once PER MECHANISM: process-dependent fingerprints, side-effect writes, a
partial name bucket, absolute paths, a deleted file read, a cache keyed by one side, a key that ignores the
grammar, a read list that flattens a callee's reads. That is the second-mechanism defect the goal forbids,
eight times over.

## The one mechanism
A saved fact is a `@query` answer. The engine (std-relation; owner hd-families2) does everything else, once:

1. **Key**: spelled durably by ONE speller per argument type (DeclId → decl_wire, FileId → root-relative
   path, string → itself). Derived from the argument's type; a type with no speller makes the query in-process.
2. **Reads**: recorded by the kernel frame automatically. A read of another `@query` is that query's own
   answer. No hand `leaves_of`, no hand read list.
3. **Digest**: eager, of the whole answer: the hash of its codec bytes under the scope (`digest_in`, generated by `@codec`). A type never wears both `@codec` and `@derive(Fingerprint)` (refused); Fingerprint stays only for in-process types, and its `Ids` folds onto `Scope`.
4. **Codec**: derived from the answer type. A hand codec is written only for a type the derive can't cross,
   and then it is THE codec for that type.
5. **Validity**: one rule: every recorded read's digest still stands (one per-revision leaf cache).
6. **Restore**: an answer about a file not read this run is restored from its saved row by the engine's ONE restore path (`ran_lasting`, recursive via hash_asked; the unused kernel `Saved`/`set_saved` is deleted), never
   computed. That IS the hold's question, answered generically, so the hold is deleted by this, not beside it.
7. **Store**: one row per answer; per-row cost is the store's (hd-store's v8).
8. **Writers**: a query never writes anything but its answer. A side-effect write into Decls or a table is a
   second writer: make it part of the answer.

## What that collapses
| hand mechanism | becomes |
|---|---|
| typed rows (saved_rows.av) | `@query typed(d: DeclId) -> TypeFacts` |
| lowered rows (lowered_rows.av, unit_rows.av) | `@query lowered(u: UnitKey) -> Body` |
| decl rows / Items / uses_kept | `@query items(f: FileId) -> Items` (lines, uses, maker lines) |
| NameEnvs / named_refs | `@query names(m: Module) -> NameEnv`; a bucket digest is its answer's digest |
| Settled / kept_settle.av | `@query settled(c: DeclId) -> Settlement` (DB 09 Option C) |
| Said / file_refs / doc rows | `@query file_said(f: FileId) -> Said` |
| Proof, Linked | `@query proof(p)`, `@query linked(entry)` |
| the hold (1i, 1a/1b) | deleted: restore (point 6) answers what it decided |

Each conversion DELETES its hand writer, reader, codec and validity code in the same commit. The line count
goes down.

## Rules from now on
- No new hand-saved mechanism. A new saved fact is a `@query`. If the engine lacks something, the engine
  gets it (ask hd-families2), never the lane.
- An engine gap is fixed in the engine, and every lane gets the fix by merging.
- Tests derive from the engine, not hand lists (e.g. family_reflect_test's family list is derived).

## The same rule for caches
`Records` in workspace.av holds 18 hand per-build caches (`Cell<Map…>`: line_index, line_refs, named_refs,
uses_seen, record_files, …), and lanes keep adding more. A per-build memo IS an in-process `@query` (the
engine memoizes per revision and invalidates on world moves). Each becomes a `@query`; Records shrinks to
what is genuinely state, not memo. A new memo table in Records is refused at review.

Acceptance for each conversion: `grep` finds no absolute path in its saved keys or values.
Then the store moves (s-builder, measured 2026-11-02): a foreign tree's warm store ran SLOWER than an empty one (std-openapi 6.8 s vs 4.2 s) because rows carry the tree's absolute paths. Once the acceptance above holds tree-wide, ONE line in `stores_dir` (build.av) points every worktree at `$HOME/.avra/cache` (the store is already multi-writer: per-writer segments, flock compaction), and the proof is a second worktree's first check starting warm.
